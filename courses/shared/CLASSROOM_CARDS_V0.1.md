# AI-Courses 共享课堂卡 V0.2

更新时间：2026-09-01
状态：READY FOR INTERNAL WALKTHROUGH / INTERNAL AUDIT SYNCED
适用：小学高年级 / 初中

目的：把课程中反复出现的教学动作产品化，减少教师临场发挥和逐个学生解释。

原则：

> **同一种课堂问题，用同一张卡解决；高频个别救援必须逐步变成全班可用的标准资产。**

---

# C1 — 我想做什么？创意起步卡

适合：学生“没想法”。

先选一个：

### 我想做一个……
- 游戏；
- 学习产品；
- 兴趣/知识产品；
- 校园/生活工具；
- 互动体验；
- 自己提出。

### 主题可以是……
- 太空；
- 恐龙；
- 足球；
- 赛车；
- 海洋；
- 昆虫；
- 音乐；
- 书/电影；
- 学科知识；
- 校园生活；
- 自选。

最后只说一句：

> **“我想做一个关于【主题】的【产品类型】，让别人可以【做什么】。”**

不要因为“想不到最有创意的点子”而卡住。

---

# C2 — 把模糊要求说清楚卡

当学生说：
- 更酷；
- 更高级；
- 更智能；
- 更有趣；
- 不好看；
- 不好用。

改问四件事：

1. **哪里？**
2. **什么时候？**
3. **希望发生什么？**
4. **什么不要被改坏？**

推荐句式：

> 现在【具体地方】是【实际情况】。我希望当【条件】发生时，它变成/出现【具体结果】。请保留【已经正常的功能】。

---

# C3 — 产品四格需求卡

适合：初中主用，小学高阶可用。

1. **用户**：谁会用？
2. **任务**：他最主要要完成什么？
3. **核心功能**：如果只能留一个，是什么？
4. **成功表现**：用户完成以后会看到/得到什么？

一句话：

> 我的产品给【用户】用，帮助他【任务】，最重要的是【核心功能】，完成以后【成功表现】。

---

# C4 — 规则设计卡

不要先想代码。

只填：

> **当【条件】发生时 → 让【结果】发生。**

再补：

- 这个状态要不要显示给用户？
- 条件不满足时怎么办？
- 结束以后还能不能继续操作？

常见规则菜单：
- 倒计时；
- 连击；
- 错误次数；
- 生命值；
- 能量；
- 等级；
- 进度；
- 条件解锁；
- 奖励；
- 失败。

---

# C5 — AI说完成，我怎么验证？卡

每次 AI 修改以后，至少做：

### 1. 真的点一次
不要只看 AI 回复。

### 2. 触发目标情况
例如：
- 故意答错；
- 故意让时间结束；
- 连续成功；
- 重新进入；
- 达到升级条件。

### 3. 再检查旧功能

最后问：

> **“它是真的工作，还是 AI 只说它工作？”**

---

# C6 — 故障描述卡

不要只说：
> “坏了。”

用三句：

1. **我原本希望：**【目标】
2. **现在实际发生：**【现象】
3. **请修复，同时保留：**【正常功能】

完整模板：

> 我原本希望【目标】，但实际发生【现象】。请检查并修复【问题】，不要破坏【已经正常的功能】。修好后自己检查一次，我还会实际试玩验证。

---

# C7 — 稳定版 / 回退卡

当修改越来越乱：

先问：

> “最近一个完整能用的版本是哪一个？”

然后执行：

> 请回到最近稳定版本，保留【主题/核心功能】，暂时移除【不稳定高级功能】。先恢复完整可用状态，再一次只增加一个主要修改。

记住：

> **回退不是失败，是保护产品。**

---

# C8 — 同伴试玩反馈卡（小学版）

体验别人作品，只说：

1. 我最喜欢的是：________
2. 我最容易卡住的是：________
3. 如果只改一处，我建议：________

作者自己决定改不改。

---

# C9 — 用户测试反馈卡（初中版）

1. 我第一眼知道它做什么吗？
2. 我在哪一步犹豫/迷路？
3. 哪个功能最有价值？
4. 哪个功能可能多余？
5. 如果只改一处，我建议什么？

作者标记：
- 采纳；
- 不采纳；
- 部分采纳。

并写理由。

---

# C10 — AI评审卡

让 AI：

> 不要直接替我改。只给最重要的3条建议，每条说明影响哪个用户目标并排优先级。

学生：

1. 给3条建议标记：接受 / 拒绝 / 不确定；
2. **BASE只选1条修改**；
3. 至少留下一条：

> **“AI建议了，但我没有照做，因为……”**

完成后保存修改前/后截图。

---

# C11 — AI反方卡

让 AI 故意问最关键3条：

- 哪个功能可能没必要？
- 哪个地方可能太复杂？
- 哪类用户可能不喜欢？

学生 BASE 只选1条深入回应：

> 我【接受 / 不接受 / 部分接受】，因为________。

然后只做一次删除 / 合并 / 弱化 / 重排，并保存 Before / After。

AI 可以反对，但不能替学生决定。

---

# C12 — 事实核查卡

BASE 不追求数量。

### 小学/初中标准 BASE

1. 找出最关键的 **2 条事实**；
2. 用教师指定可靠来源核查；
3. 标记：支持 / 冲突 / 不确定；
4. 至少处理1条错误、不严谨或来源问题；
5. 不确定的不装作确定；
6. 检查题目、答案等关联内容是否同步；
7. 给作品增加“已核查 / 来源 / 纠错”等可见模块。

第3条及多来源比较进入 Challenge。

习惯：

> **AI生成 → 关键事实再查 → 产品纠错 → 再验证。**

---

# C13 — BASE DEADLINE 卡（教师）

## 小学
约25–30分钟：必须已有展示级 BASE。

## 初中
约30–35分钟：必须已有展示级 BASE。

未达标时：

1. 停止新增；
2. 缩小需求；
3. 切稳定母版；
4. 使用统一恢复语句；
5. 必要时教师局部协助。

不要让学生把整节课赌在一个失败高级功能上。

---

# C14 — Challenge 选择卡

完成 BASE 后，不需要等老师。

### Quick Win
5分钟左右：
- 动画；
- 状态反馈；
- 徽章；
- 主题；
- 文案；
- 低风险小增强。

### Builder
10–20分钟：
- 第二个主要复杂规则；
- 新模式；
- 新页面；
- 状态系统；
- 自定义内容。

### Open Creator

> **“我还想让它……”**

自己提出，但一次只增加一个主要复杂度。

# C16 — 30秒作品介绍卡（小学）

> 这是我的【作品名】。它可以【核心功能】。我自己决定了【规则/内容】。AI第一次【哪里不对】，后来我让它【怎么改】。你可以扫码试一下。

---

# C17 — 60秒产品发布卡（初中）

> 我的产品叫【名称】，主要给【用户】使用，帮助他【任务】。最重要的功能是【功能】。测试时我发现【问题】，后来改成【结果】。AI还建议过【建议】，但我选择【接受/不接受】，因为【理由】。现在可以扫码体验。

# C18 — 现在只改一个复杂功能卡

适合：学生功能越加越多、课堂开始失控。

先问：

> **“你现在同时有几个还没稳定的复杂功能？”**

如果答案大于1：

### 现在只留下一个

我今天最重要的复杂修改是：

> ____________________

其他想法先放：

### 我的 Challenge 停车场
- ____________________
- ____________________
- ____________________

完成当前修改以后必须：

1. 真实触发；
2. 检查旧功能；
3. 修复；
4. 再验证。

稳定以后再从停车场拿下一项。

记住：

> **AI快，不等于同时改很多；一次稳定一个，最后反而做得更多。**

# C19 — Before / After 展示卡

适合：
- 用户测试；
- AI评审；
- 事实核查；
- AI反方；
- UX优化；
- 版本升级。

不要只说“我学会了”。

必须留下：

### Before
原来是什么样？

截图/一句话：____________________

### 我发现了什么
- 用户说：____________________
- AI建议/质疑：____________________
- 来源核查发现：____________________
- 我自己发现：____________________

### 我的决定
我选择：
- [ ] 改
- [ ] 不改
- [ ] 部分改

因为：____________________

### After
现在变成什么样？

截图/一句话：____________________

最后一句：

> **“我不是只听了一个建议，我让产品真的发生了变化。”**

# 教师使用原则

这些卡片不是每节课全部发。

按问题调用：

- 没想法 → C1
- 说不清 → C2/C3
- 规则模糊 → C4
- 不验证 → C5
- 出故障 → C6/C7
- 用户测试 → C8/C9
- AI判断 → C10/C11
- 事实产品 → C12
- 掉队 → C13
- 提前完成 → C14
- 发布 → C15–C17
- 同时加太多复杂功能 → **C18**
- 认知动作看不出成果 → **C19**

目标：

> **教师少做个性化口头救援，多用标准化卡片让学生自己恢复和继续。**
