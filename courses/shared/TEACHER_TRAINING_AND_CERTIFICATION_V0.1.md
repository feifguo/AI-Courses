# AI-Courses 教师培训与认证 V0.2

更新时间：2026-09-01
状态：FIRST TRAINABLE VERSION / INTERNAL AUDIT SYNCED
适用：代理商教师 / 学校教师 / 到校授课教师

## 1. 培训目标

本培训不是把老师培训成程序员。

合格教师需要做到：

> **能在标准课时内，让不同能力学生都拿到展示级成果；少做个别技术救火，多用标准母版、支架和统一恢复；同时让强学生继续创造。**

教师核心角色：

> **创意导演 + 节奏控制者 + 支架诊断者 + 成果守门员。**

---

## 2. 认证前提

不要求：
- 编程基础；
- Python/JavaScript；
- 软件工程经验；
- AI专业背景。

建议具备：
- 正常电脑操作；
- 基本课堂管理能力；
- 愿意实际试玩学生作品；
- 能接受“老师不需要知道每个技术答案”。

---

## 3. 九条硬原则

1. **成果优先**：先让绝大多数学生有第一眼很强的完整作品。
2. **标准课时前锁 BASE**：小学25–30分钟；初中30–35分钟左右。
3. **BASE复杂度预算**：原则上1个主要复杂修改 + 1个低风险可见增强。
4. **不讲代码主线**：AI可在后台写代码，课堂不把代码变成前置门槛。
5. **AI说完成不算完成**：必须真实运行、触发、试玩、再验证。
6. **弱学生兜底，强学生不等待**：BASE/FALLBACK 与 Challenge/Open Creation 并行。
7. **认知课 action-first**：原则讲解尽量3–5分钟，连续10分钟没碰真实作品视为预警。
8. **认知课要有 Before/After**：AI评审、事实核查、用户测试、AI反方都要留下可见变化。
9. **高频个别救援必须产品化**：反复出现的问题要反馈课程方做成统一模板/恢复卡。

---

## 4. 首版培训结构

建议总时长约3小时，可拆成两次。

### Module A — 45分钟：老师自己成为学生

教师亲自完成 M1 游戏：
- 自然语言生成第一版；
- 试玩；
- 改主题；
- 加1条主要规则；
- 加1个低风险可见反馈；
- 描述问题让AI修；
- 发布二维码。

培训师不讲代码。

目标：
> **先让老师本人相信“零编程也能做”。**

同时要求教师亲自感受：

> 生成很快，但真正需要时间的是测试和修复。

### Module B — 35分钟：怎么让一班人都完成

训练：
- DISPLAY-SAFE BASE；
- BASE DEADLINE；
- BASE Complexity Budget；
- FALLBACK；
- Challenge Pool。

情境：
> “全班同时8个学生落后，你怎么办？”

合格方向：
> **统一兜底 / 模板 / 全班恢复，而不是逐个坐过去修。**

再练一个情境：
> “一个学生同时要做排行榜、Boss、升级、错题本和两套计分，怎么办？”

合格方向：
> **只保留一个主要复杂修改，其他进入Challenge。**

### Module C — 35分钟：教师支架五级

依次练习：
1. 不帮，先让学生试；
2. 追问；
3. 给选项；
4. 给句式/模板；
5. FALLBACK / 必要局部代操作。

重点是判断什么时候继续让学生探索，什么时候必须保住成果。

### Module D — 30分钟：AI不是答案机器

教师练习让 AI 充当：
- 制作员；
- 修复员；
- 评审员；
- 用户；
- 反方；
- 资料助手。

但必须遵守：

> **看一个例子 → 马上在真实作品上做 → 用 Before/After 收口。**

认知型片段原则讲解尽量不超过3–5分钟。

### Module E — 20分钟：成果展示

教师必须会组织：
- 二维码；
- 作品卡；
- 最佳截图；
- Before/After；
- 30秒介绍；
- 作品墙；
- 学校/家长展示。

核心：
> **先让外行看到作品价值，再解释教育价值。**

### Module F — 15分钟：故障与课堂边界

熟悉：
- 一直加载；
- 功能没生效；
- 新功能改坏旧功能；
- 回退；
- 账号/网络 smoke check；
- 不在课堂接复杂API/服务器；
- 不写入学生敏感隐私。

## 5. 教师实操考核

### Test 1 — 自己做出来

限时完成一个 M1/M2 BASE，并完成：
- 试玩；
- 1个主要复杂修改；
- 1个低风险可见增强；
- AI修复；
- 发布/展示。

若教师主动一次加入多个复杂功能，需说明为什么以及如何控制风险；否则扣分。

### Test 2 — 情境判断

#### 情况A
学生第8分钟还没想好主题。

正确方向：给主题菜单，立即进入 BASE。

#### 情况B
学生第27分钟还在做高风险新功能，但基础作品不稳定。

正确方向：停止高级功能，切 FALLBACK，先锁展示成果。

#### 情况C
8名学生都出现同一个加载问题。

正确方向：全班统一恢复，不逐个修。

#### 情况D
强学生第22分钟已完成 BASE。

正确方向：进入 Challenge/Open Creator，不等待全班。

#### 情况E
AI说功能完成，但学生没有试玩。

正确方向：要求实际触发和验证。

#### 情况F
学生同时在修改3个高风险逻辑。

正确方向：只保留当前最重要1个复杂修改，其余记入 Challenge。

#### 情况G
老师在“AI评审”课上已经讲了12分钟，学生还没碰自己的作品。

正确方向：立即停止继续讲解，让学生在自己的产品上执行评审/修改；后续概念在作品结果出来后再总结。

#### 情况H
学生完成了事实核查，但作品界面完全看不出任何变化。

正确方向：增加已核查/来源/纠错模块或Before/After，使教育动作变成可展示成果。

### Test 3 — 5分钟微型试讲

任选：
- 开场成果演示；
- 规则设计；
- 用户反馈；
- AI评审；
- 事实核查；
- 故障恢复；
- 发布。

考核：
- 不长讲理论；
- 不讲代码；
- 追问清楚；
- 时间意识强；
- 结果导向；
- 认知型片段能快速导向真实作品动作。

## 6. 认证结果

### PASS

可独立执行标准教案，并处理常见分层、复杂度控制和恢复。

### PASS WITH CO-TEACHING

可在主教师/助教支持下授课，需要继续练：
- 时间控制；
- 支架判断；
- Complexity Count；
- FALLBACK触发。

### NOT YET READY

典型风险：
- 讲大量原理；
- 替学生操作；
- 看到代码就讲代码；
- 不看时间；
- 强学生等全班；
- 弱学生卡到下课；
- 拒绝必要兜底；
- 作品未稳定继续堆功能；
- AI生成快就让学生同时做多个复杂逻辑；
- 认知课没有可见Before/After。

---

## 7. 认证不是一次性

建议：
- 按课程线和版本认证；
- 每学年或重大版本更新短复训；
- 新母版加入后做15–30分钟升级训练；
- 真实课堂共性问题进入下一版培训。

示例：
> AI-Courses Certified Teacher — Primary Upper V1

---

## 8. 代理商交付边界

代理商教师应获得：
- 当前授权教案；
- 课堂卡；
- 教师演示版；
- 学生任务卡；
- 当前稳定 BASE/FALLBACK；
- 故障恢复；
- Challenge Pool；
- 展示模板。

默认不获得：
- 完整研发母版库；
- 未发布下一版本；
- 全量失败数据库；
- 内部Prompt迭代历史；
- 完整渠道策略。

---

## 9. 真实课堂后的教师反馈

每节课只记录：
- 展示级完成率；
- BASE实际时间；
- FALLBACK人数；
- 最常见卡点TOP3；
- 同时承担>1复杂修改的学生比例；
- 最有效统一恢复；
- 最受欢迎Challenge；
- 学生难度差异；
- 家长/学校最喜欢的成果；
- 下一版必须改的一件事。

课程方跨班级汇总，不把单个教师经验直接当成普遍规律。

---

## 10. 一句话教师标准

> **好老师不是能替学生修所有东西，而是能让不同学生在同一个课堂里都持续向前：弱学生不掉队，普通学生有成长，强学生有空间，最后人人有拿得出手的成果。**

以及：

> **AI快省下来的时间，优先留给试玩、判断、修复和创造，而不是继续往 BASE 里塞更多复杂功能。**
