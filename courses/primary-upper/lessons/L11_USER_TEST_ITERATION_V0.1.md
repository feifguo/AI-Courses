# 小学高年级 L11 — 别人真的会用我的产品吗？V0.1

更新时间：2026-09-01
状态：CONDITIONAL READY / 通用机制可走课
年级：4–6年级
标准课时：40分钟
主机制：同伴试玩 / 反馈判断 / 再迭代
适用：M1/M2 已验证；未来扩展至 M3–M5

## 1. 本节课对外成果

每名学生至少完成：

> **自己的产品经过一次“别人试玩 → 收到反馈 → 自己决定 → 修改”的明显升级。**

本节的成果不是一张反馈表，而是测试前后作品真的不一样。

## 2. 能力暗线

学生训练：
- 让别人独立使用，不一直在旁边解释；
- 听懂具体反馈；
- 不把所有意见都当命令；
- 选择一条最值得改的；
- 修改后让对方再试一次。

## 3. 40分钟时间盒

### 0–4分钟 — “我自己会用”不代表别人会用
教师演示一个作者觉得很清楚、第一次用户却找不到入口的样例。

### 4–8分钟 — 锁定测试版
学生先保存当前稳定版本，不再加新功能。

### 8–16分钟 — 第一次同伴试玩
两人交换，作者不解释。

反馈者只回答：
1. 我第一眼知道怎么用吗？
2. 哪一步最奇怪/最容易卡？
3. 我最喜欢哪一点？
4. 如果只改一处，我建议什么？

### 16–21分钟 — 作者做决定
每条反馈标记：
- 我会改；
- 我不会改；
- 我想改一半。

至少选择一条。

### 21–29分钟 — BASE DEADLINE：根据反馈修改
模板：
> 同学第一次使用时在【地方】遇到【问题】。我决定把它改成【具体变化】，因为【理由】。请只修改这一处，不要破坏其他已经正常的功能。

到29分钟形成稳定修改版。

### 29–34分钟 — 回测
原同学再试一次，只问：
> “刚才那个问题现在有没有变好？”

### 34–37分钟 — Challenge / 收口
快学生再找一个用户；慢学生停止加功能，锁定稳定版。

### 37–40分钟 — 一句话分享
> “同学建议我【反馈】，我选择【改/不改】，因为【理由】。”

## 4. DISPLAY-SAFE BASE
- 稳定测试前版本；
- 一次真实同伴试玩；
- 一条具体反馈；
- 一次学生自主取舍；
- 一次修改和回测；
- 最终作品仍展示级。

## 5. FALLBACK
如果用户建议过大：
> 只处理最影响核心使用的一处，不重做整个产品。

如果修改后作品变坏：
> 回到测试前稳定版，只重新做一项最小修改。

## 6. 教师追问
“他说什么我都改” → “这是他的个人喜欢，还是所有用户都会遇到的问题？”

“我不想听” → “是不认同，还是怕麻烦？”

## 7. Challenge
- 第二位用户；
- 比较冲突反馈；
- 自己设计一个反馈问题；
- 让 AI 模拟用户后再和真人反馈比较。

## 8. 课后教师最小记录
- 完成真实互测比例；
- 学生最常采纳的反馈类型；
- 机械服从反馈比例；
- 2个明显因用户测试变好的案例；
- 需要改进的反馈卡问题。
