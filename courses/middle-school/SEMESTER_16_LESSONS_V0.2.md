# 初中 AI 数字创造课 — 16课时学期版 V0.2

更新时间：2026-09-01
状态：STANDARD-PERIOD PRODUCT STRUCTURE / 待逐课母版与内部走课

建议年级：7–9 年级
标准单课时：45 分钟
主平台：微信小程序教育平台（当前 Known-Good）

> V0.2 替代 V0.1 作为当前课程结构基线。V0.1 保留历史参考，其“45–60分钟”默认时长已被本版修正。

## 1. 课程承诺

学生不是“学会几个AI工具”，而是能真正完成：

> **想法 → 产品目标 → AI第一版 → 真实运行 → 用户测试 → 发现问题 → 修改 → 发布。**

家长/学校看到的是：

- 可玩的游戏；
- 可用的小工具；
- 学习/兴趣产品；
- 校园应用；
- 最终原创数字产品。

初中比小学更难的地方主要是：

- 自己定义目标；
- 自己判断用户；
- 自己拆功能；
- 自己做取舍；
- 自己验证；
- 自己迭代。

而不是多学一堆代码语法。

## 2. 标准课时硬约束

每节课必须同时满足：

1. **30–35 分钟左右锁定 DISPLAY-SAFE BASE；**
2. 35–45 分钟用于试玩、用户反馈、修改、取舍、收口；
3. 快学生提前完成后直接进入 Challenge Pool / Open Creation，不等待；
4. 60/90 分钟或双课时只增加产品深度，不补主流程；
5. 初中仍保留稳定母版和 FALLBACK，不能把高失败率当成“更高级”；
6. BASE DEADLINE 前仍未达展示线者立即停止继续加功能；
7. 强学生的难度主要增加在用户、功能拆解、规则、验证和版本决策，不靠代码语法；
8. AI 说完成不算完成，必须实际运行和验收。

统一时间结构：

> **0–35 分钟：锁产品**  
> **35–45 分钟：做判断与迭代**  
> **45 分钟以后：增加产品深度与原创性**

详见：
- `../../docs/STANDARD_PERIOD_AND_EXTENSION_POLICY.md`
- `../../docs/CHALLENGE_POOL_SYSTEM_V1.md`
- `../../docs/OUTCOME_FIRST_AND_SCAFFOLDING_POLICY.md`

## 3. 分层原则

每个核心项目仍有：

### BASE — 展示级保底
稳定母版 + 功能菜单 + 标准交付线。

### GUIDED CREATOR — 主路径
学生自己组织部分需求和功能。

### OPEN CREATOR — 强学生路径
学生自己定义产品、用户、功能和迭代方向。

即使到初中，也不能取消兜底。

# Unit 1 — AI让我马上开始做产品

## 第1课：我在一节课里做出了第一个数字产品

### BASE DEADLINE
约 30–35 分钟。

### 对外成果
可扫码试玩的小游戏或互动应用。

### BASE
提供三类稳定起点：
- 游戏；
- 互动故事；
- 小工具。

学生选择主题、视觉、一个规则。

### 标准课时深化
- 实际试玩；
- 找一个不满意处；
- 做一次具体修改；
- 确认最终版本。

### CHALLENGE / 延长课时
- 从空白描述自己的产品；
- 加一个 Builder 功能；
- 完全自定义“我还想让它……”。

### 能力暗线
- AI先帮助我跨过技术门槛；
- 第一版不是终点。

---

## 第2课：把“想法”变成“产品要求”

### BASE DEADLINE
约 30–35 分钟完成一次真实功能升级。

### 对外成果
第一课作品完成一次真实功能升级。

### BASE
需求卡：
- 谁会用；
- 他要做什么；
- 最重要的1个功能；
- 成功时会发生什么。

### 标准课时深化
学生对比：
- 我原来怎么说；
- AI做成了什么；
- 哪一句要求最关键。

### CHALLENGE / 延长课时
自己写产品目标和限制；增加第二优先级功能。

### 能力暗线
从“我想做一个很酷的东西”变成可执行需求。

---

## 第3课：规则系统——让产品真正有逻辑

### BASE DEADLINE
约 30–35 分钟加入至少两类可试玩规则。

### 对外成果
加入积分、状态、条件、奖励、失败等规则。

### BASE
规则组件菜单。

### 标准课时深化
- 自己触发规则；
- 找一条逻辑冲突或不清楚之处；
- 修正。

### CHALLENGE / 延长课时
自己设计相互影响的规则系统。

### 能力暗线
- 条件；
- 状态；
- 因果关系；
- 验证。

不要求学习编程语法名词。

---

## 第4课：版本不是越新越好

### BASE DEADLINE
约 30–35 分钟形成可比较的 V1 / V2。

### 对外成果
同一个产品形成 V1 / V2 对比。

### BASE
- 保存稳定版本；
- 改一个功能；
- 试玩；
- 如果变差则回退/修复。

### 标准课时深化
学生说明：
- 哪个版本更好；
- 为什么。

### CHALLENGE / 延长课时
比较两个不同方案后做选择；形成 V3。

### 能力暗线
版本意识、可恢复、不要盲目接受AI修改。

---

# Unit 2 — 从作品到真正的小产品

## 第5课：多页面产品——做一个“真的能用”的工具

### BASE DEADLINE
约 30–35 分钟形成完整主流程。

### 对外成果
多页面小应用。

BASE产品类型：
- 学习驾驶舱；
- 兴趣数据库；
- 运动/习惯记录；
- 阅读/影视清单；
- 校园活动中心。

### BASE
- 首页；
- 列表；
- 详情；
- 记录/收藏；
- 本地数据。

### 标准课时深化
- 从首页完成一次完整操作；
- 找一个用户可能迷路的地方；
- 修改。

### CHALLENGE / 延长课时
学生自行设计页面结构；新增模式或数据呈现。

### 能力暗线
信息架构和用户流程。

---

## 第6课：数据会让产品“记住”用户

### BASE DEADLINE
约 30–35 分钟让产品稳定保存一种核心数据。

### 对外成果
产品可以保存记录、积分、进度或收藏。

### BASE
使用平台本地数据，不接复杂服务器。

### 标准课时深化
学生回答：
- 这项数据为什么值得保存；
- 用户在哪里能看到它。

### CHALLENGE / 延长课时
设计统计、筛选、图表或本地排名。

### 能力暗线
- 哪些数据值得保存；
- 数据如何帮助用户；
- 不收集不必要隐私。

---

## 第7课：把产品做得更顺手

### BASE DEADLINE
约 30–35 分钟完成至少一次明显体验升级。

### 对外成果
一次完整用户体验升级。

### BASE
统一体验检查：
- 首页是否看得懂；
- 按钮是否清楚；
- 用户会不会迷路；
- 操作后有没有反馈；
- 错误后怎么返回。

### 标准课时深化
学生说明：
- 我改了什么；
- 为什么这个修改会让用户更顺手。

### CHALLENGE / 延长课时
自己重新设计一个关键流程。

### 能力暗线
不是“功能能跑”就等于产品好用。

---

## 第8课：用户测试——别人用起来和我想的不一样

### BASE DEADLINE
约 35 分钟完成一次他人测试并修改。

### 对外成果
测试前/测试后两个版本。

### BASE
两两测试 + 反馈卡 + 至少一次修改。

### 标准课时深化
学生明确：
- 哪条反馈采纳；
- 哪条不采纳；
- 为什么。

### CHALLENGE / 延长课时
3位用户测试，自己筛选反馈；第二轮迭代。

### 能力暗线
- 观察；
- 判断；
- 取舍；
- 用户不是永远正确，但不能不听。

---

# Unit 3 — AI不只是生成器

## 第9课：让AI当评审，而不是只让它做东西

### BASE DEADLINE
约 30–35 分钟完成 AI 评审 + 人类选择 + 一次修改。

### 对外成果
自己的产品经过一次“AI评审 + 人类判断”升级。

### BASE
让AI按清单评审：
- 是否清楚；
- 是否有明显bug；
- 是否有多余功能；
- 是否有用户看不懂的地方。

学生只能选择其中1–2条修改，不允许全部照单全收。

### 标准课时深化
解释：
- 哪条建议没听；
- 为什么。

### CHALLENGE / 延长课时
自己设计评审标准；对比 AI 与同学意见。

### 能力暗线
AI意见也要判断。

---

## 第10课：AI也会胡说——事实产品的可信度

### BASE DEADLINE
约 30–35 分钟核查3条关键事实并修正。

### 对外成果
知识/信息型产品增加来源、纠错和可信说明。

### BASE
核查3条事实并修正。

### 标准课时深化
对其中一条写出“为什么我认为它可信”。

### CHALLENGE / 延长课时
比较多个来源，处理冲突信息；增加来源页。

### 能力暗线
幻觉、来源、验证。

---

## 第11课：让AI当“反方”

### BASE DEADLINE
约 30–35 分钟完成一次有理由的删减/重构。

### 对外成果
产品经过一次有理由的删减/重构。

### BASE
让AI提出：
- 为什么这个功能可能没用；
- 哪个地方太复杂；
- 用户可能为什么不喜欢。

学生选择一条回应：接受 / 不接受 / 修改。

### 标准课时深化
学生必须说明自己的最终决策。

### CHALLENGE / 延长课时
让AI模拟不同用户群体给出冲突意见；比较后取舍。

### 能力暗线
批判性思考和产品取舍。

---

## 第12课：一个真实问题，一款小产品

### BASE DEADLINE
约 30–35 分钟必须出现真实问题项目 V1。

### 对外成果
真实问题项目 V1。

BASE主题池：
- 校园导航；
- 社团管理；
- 学习工具；
- 阅读/知识分享；
- 环保挑战；
- 运动健康记录；
- 校园文化介绍。

### BASE
课程方提供每类稳定产品骨架。

### 标准课时深化
- 说清用户；
- 完成一次核心流程；
- 缩掉一个过大的功能。

### CHALLENGE / 延长课时
学生自己发现问题并定义产品；高能力学生减少模板依赖。

### 能力暗线
问题不是越大越好，要缩成一学期能解决的范围。

---

# Unit 4 — 我的产品发布

## 第13课：定义我的最终产品

### BASE DEADLINE
约 30–35 分钟必须出现最终项目 V1。

### 对外成果
最终项目当堂出现 V1，不允许只交策划文档。

### BASE
从产品模板库选：
- 游戏；
- 学习/知识；
- 兴趣；
- 校园工具；
- 记录/管理。

学生定义：
- 用户；
- 目标；
- 3个核心功能；
- 一个展示亮点。

### 标准课时深化
- 试玩 V1；
- 确认一个最重要的升级；
- 删除一个不必要功能。

### CHALLENGE / 延长课时
完全自定义；Open Creator 可从空白定义产品。

---

## 第14课：功能取舍与产品升级

### BASE DEADLINE
约 30–35 分钟形成完整 V2。

### 对外成果
V2：比V1更完整，但不允许无止境加功能。

### BASE
必须完成：
- 1个核心流程；
- 1个状态/数据机制；
- 1个视觉 Wow；
- 1个学生原创功能。

### 标准课时深化
- 试玩；
- 判断哪个功能最重要；
- 进行一次删减/简化。

### CHALLENGE / 延长课时
更复杂流程/模式/用户角色。

### 能力暗线
产品设计的本质之一是取舍。

---

## 第15课：发布前验收

### BASE DEADLINE
约 35 分钟内形成 Final Candidate + 二维码。

### 对外成果
Final Candidate + 二维码 + 产品截图。

### BASE 验收
- 所有关键按钮；
- 核心流程；
- 数据；
- 文字；
- 事实；
- 手机扫码；
- 用户测试；
- 最后修复。

### 标准课时深化
- 最终产品截图；
- 30秒发布话术；
- 最后一处视觉/文字收口。

### CHALLENGE / 延长课时
让不同用户群体测试；再完成第二轮修订。

### FALLBACK
未达到展示线时：
- 停止新增功能；
- 回到最近稳定版本；
- 启用课程方母版保留学生主题/内容；
- 教师必要时局部协助。

### 能力暗线
发布是一种责任，不是“AI说好了就算”。

---

## 第16课：AI Product Demo Day

### 对外成果
真正的小型产品发布会。

学生/小组展示：
1. 我解决什么问题 / 创造什么体验；
2. 谁会用；
3. 第一版是什么；
4. 用户反馈是什么；
5. AI哪里帮了我；
6. 哪些AI建议我没有听；
7. 最终请大家扫码体验。

### 标准45分钟版
采用展位/轮转 + 少量代表发布：
- 0–8分钟：布置作品/二维码；
- 8–30分钟：轮转试玩/反馈；
- 30–41分钟：2–4个代表项目发布；
- 41–45分钟：收口、成果记录。

### 延长60–90分钟版
可增加：
- 更多学生发布；
- 家长/教师试玩；
- 产品奖项标签；
- 现场反馈；
- 30秒产品短视频；
- 更完整成果展。

### 对学校成果
- 产品二维码墙；
- 产品海报；
- 学生短视频；
- 优秀产品精选；
- 用户反馈摘录；
- 学期课程成果报告。

# 4. 初中与小学真正的差异

不是：

> 小学简单代码 / 初中复杂代码。

而是：

### 小学
更多给：
- 主题；
- 规则；
- 产品母版；
- 功能菜单。

重点训练：
- 选择；
- 表达；
- 试玩；
- 修改；
- 初步验证。

### 初中
逐步要求：
- 用户；
- 目标；
- 功能优先级；
- 版本；
- 用户测试；
- 事实验证；
- 对AI建议的取舍；
- 产品发布。

---

# 5. 教师可规模化兜底

每课必须配：

- BASE；
- FALLBACK；
- 功能菜单；
- 统一恢复提示；
- 常见错误；
- Quick Win Challenge；
- Builder Challenge；
- Open Creator 方向。

如果多人出现相同问题，老师优先统一投屏处理。

个别代操作允许，但不得成为高频默认模式。

---

# 6. 当前不作为必修底座

- 系统学习HTML/CSS/JS；
- 系统学习Python；
- Unity/C#；
- 自建服务器；
- 登录/OAuth；
- 复杂数据库；
- 运行时大模型API。

这些未来只在平台已封装、低门槛且课堂稳定时升级进挑战路径。

---

# 7. 下一研发动作

1. 把16课中的重复机制整理成 5–7 套稳定母版；
2. 每套母版做 BASE / FALLBACK / Quick Win / Builder / Open Creator；
3. 优先验证尚未 Known-Good 的工作台/记录工具、互动故事、兴趣馆等母版；
4. 对每课真实测 BASE 是否能在30–35分钟预算内稳定完成；
5. 形成教师追问话术和统一救援；
6. 做内部走课；
7. 达到内部发布 Gate 后直接进入学校；
8. 用真实课堂持续迭代。
