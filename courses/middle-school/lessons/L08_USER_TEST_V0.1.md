# 初中 L8 — 用户测试：别人用起来和我想的不一样 V0.1

更新时间：2026-09-01
状态：READY FOR INTERNAL WALKTHROUGH
年级：7–9年级
标准课时：45分钟
主机制：同伴测试 / 反馈筛选 / 版本迭代
适用母版：M1/M2，未来扩展 M3–M5

## 1. 本节课对外成果

每名学生形成：

> **测试前版本 + 用户反馈 + 测试后版本。**

最低要求不是“别人夸我”，而是：
- 至少1名真实同伴独立使用；
- 至少收到1条具体反馈；
- 作者明确选择“采纳 / 不采纳 / 部分采纳”；
- 至少完成一次有理由的修改。

## 2. 核心观念

教师开场：
> “你自己会用自己的产品，不代表别人第一次就会用。”

再强调：
> **用户反馈不是命令，但没有用户反馈也很危险。**

## 3. 反馈卡
体验者只能回答四项：
1. 我第一眼知道它做什么吗？
2. 我在哪一步犹豫/卡住？
3. 我最喜欢哪一点？
4. 如果只能改一处，我建议什么？

禁止只写“很好”“不好”。

## 4. 45分钟时间盒

### 0–5分钟 — 什么叫真实测试
教师演示：作者解释很多 vs 作者不说话让别人自己用。

结论：
> 测试时先少解释，才能看到真实问题。

### 5–9分钟 — 锁定测试版本
所有学生先保存当前稳定版本，不继续加功能。

### 9–18分钟 — 第一轮同伴测试
两人交换。作者不指导，体验者独立使用2–4分钟并填反馈卡。

### 18–24分钟 — 作者判断反馈
作者把每条反馈标记：
- 采纳；
- 不采纳；
- 部分采纳。

至少选一条准备修改。

教师追问：
> “为什么？”

### 24–33分钟 — BASE DEADLINE：完成一次基于用户的修改
表达模板：
> 同学在第一次使用时，在【步骤】出现【问题】。我决定采纳这条反馈，因为【理由】。请把【具体修改】实现，并保留其他已经正常的功能。

到33分钟必须形成测试后稳定版本。

### 33–39分钟 — 回测
原体验者再次用修改后的关键流程，只回答：
> “刚才的问题改善了吗？”

没有改善就修，不加新功能。

### 39–42分钟 — Challenge / 第二用户
快学生找第三人测试；普通学生记录一条未采纳反馈及理由。

### 42–45分钟 — 版本说明
学生一句话：
> “用户建议我【反馈】，我选择【采纳/不采纳】，因为【理由】，最后我改了【内容】。”

## 5. DISPLAY-SAFE BASE
- 测试前有稳定版本；
- 至少1名真实用户；
- 反馈具体；
- 有明确取舍；
- 至少一次修改；
- 回测核心问题；
- 最终仍可展示。

## 6. FALLBACK
若用户提出大改，或修改导致产品不稳定：
> 请回到测试前稳定版本，只处理用户反馈中最影响核心使用的一项：【问题】。不要同时处理其他建议，修改后重新测试核心流程。

## 7. 教师追问
“用户说什么都要改吗？” → “这条反馈和你的产品目标一致吗？”

“我不想听他的” → “是不认同，还是不想改？”

“他不会用是他的问题” → “第一次使用的人为什么没看懂？”

## 8. Challenge
- 3位用户测试；
- 比较冲突反馈；
- 给不同用户群体测试；
- 设计自己的测试问题。

## 9. 学生任务卡
1. 锁定稳定版；
2. 让别人独立使用；
3. 收一条具体反馈；
4. 决定采不采纳；
5. 改一处；
6. 让对方再试。

## 10. 课后教师最小记录
- 完成真实用户测试人数；
- 采纳/不采纳比例；
- 最常见用户卡点；
- 学生是否会机械服从反馈；
- 最有判断力的取舍案例；
- 哪些反馈卡问题需要调整。
