# 初中 L13 — 定义我的最终产品 V0.1

更新时间：2026-09-01
状态：CONDITIONAL READY / 当前支持 M1/M2；完整母版菜单待 M3–M5
年级：7–9年级
标准课时：45分钟
主机制：最终项目范围 / 用户 / 3个核心功能 / 当堂 V1
平台：微信小程序教育平台

## 1. 本节课对外成果

每名学生/小组下课前必须拥有：

> **最终项目 V1：能运行、能试玩、能展示，而不是只有项目计划。**

当前正式可用底座：
- M1 游戏；
- M2 学习/知识产品。

M3–M5 通过后再扩完整菜单。

## 2. 最终项目五格卡

1. **用户**：主要给谁？
2. **目标**：用户最重要要完成什么？
3. **3个核心功能**：最多三个；
4. **一个原创决定**：规则/内容/流程；
5. **一个 Wow**：第一眼展示亮点。

高能力学生可从空白定义；普通/弱学生必须从母版库出发，优先保证V1。

## 3. 45分钟时间盒

### 0–5分钟 — 最终项目不是“越大越好”
教师展示一个完整小产品和一个巨大但做不完的设想。

### 5–11分钟 — 填五格卡
教师只检查：
- 用户是否清楚；
- 核心功能是否≤3；
- 是否依赖复杂外部系统；
- 是否有展示亮点。

### 11–20分钟 — 建立 V1
学生基于稳定母版生成第一版。

### 20–28分钟 — 加入原创决定
必须至少一项不是课程默认：
- 一条规则；
- 一种反馈；
- 一段内容；
- 一个流程；
- 一个模式。

### 28–34分钟 — BASE DEADLINE：加入 Wow 并锁定 V1
到34分钟必须：
- 核心流程可走完；
- 3个以内功能工作；
- 有原创决定；
- 有一个展示亮点；
- 可扫码/预览。

### 34–40分钟 — 试玩与第一次取舍
学生必须回答：
> “V1里哪一个功能其实最不重要？”

可以删/弱化/保留，但要说明理由。

### 40–43分钟 — Challenge
稳定学生可增加第二优先级功能；普通学生只做修复。

### 43–45分钟 — V1发布卡
记录：用户、目标、3核心功能、原创决定、Wow。

## 4. DISPLAY-SAFE BASE
- 用户明确；
- 目标明确；
- 核心功能≤3；
- V1能完整运行；
- 至少一项原创决定；
- 一个视觉/交互 Wow；
- 可展示。

## 5. FALLBACK
若34分钟仍不稳定：
> 回到 M1/M2 稳定母版，只保留用户目标、最重要的1–2个核心功能、一个原创决定和一个展示效果。其他功能全部移到“以后再做”。

## 6. 教师追问
“我想做一个超级App” → “第一次使用时最重要的一件事是什么？”

“这三个都不能删” → “如果只剩20分钟开发，你先保哪个？”

“我想完全不使用模板” → “可以，但先保证34分钟前有稳定V1；如果来不及就切回母版。”

## 7. Challenge
- 从空白定义新产品；
- 设计第二用户角色；
- 多模式；
- 更复杂状态；
- M3–M5通过后迁移到新母版。

## 8. 课后教师最小记录
- V1按时完成率；
- FALLBACK人数；
- 平均核心功能数量；
- 最常见范围失控；
- Open Creator比例；
- 哪些新产品方向值得未来母版化。
