# 初中 L12 — Real Problem Sprint：真实问题极速赛 V0.2

更新时间：2026-09-01
状态：CONDITIONAL READY / 当前支持 M1/M2；工具型路径待 M5
年级：7–9年级
标准课时：45分钟
主机制：真实问题缩小 / 快速原型 / 团队取舍
平台：微信小程序教育平台

## 1. 本节定位调整

本节不再作为“最终项目 V1”，避免与 L13 Final Product Launch 重复。

改为：

> **一次低风险、限时的真实问题极速赛。**

学生用教师提供的问题池快速经历：

> 真实问题 → 缩小 → 选用户 → 只保留一个核心任务 → 30分钟内做出最小可用 V1 → 展示。

L12 是训练赛；L13 才是正式最终项目启动。

## 2. 对外成果

每组/每名学生在一节课内完成：

> **一个“小问题但完整”的可运行原型。**

当前稳定问题池优先适配 M1/M2：

- 帮同学每天10分钟复习一组知识；
- 让新生快速认识校园文化/规则（信息型演示版）；
- 让同学愿意参与环保/运动/阅读挑战；
- 给某个兴趣主题做一个互动学习/挑战工具；
- 给班级活动做一个简单互动介绍/选择产品。

M5通过后再加入记录、管理、驾驶舱类问题。

## 3. 竞赛规则

不是比谁功能多。

胜负标准：

1. 问题够具体；
2. 用户清楚；
3. 核心任务只有一个；
4. 产品真的能用；
5. 30秒内能让别人理解；
6. 有一处学生自己的决定。

## 4. 45分钟时间盒

### 0–5分钟 — 老师给“大问题”，全班一起缩小

例如：

> “提高全校学习效率”

缩成：

> “帮助七年级学生每天10分钟复习20个英语词。”

教师强调：

> **问题缩小不是降低难度，而是让解决方案真的能完成。**

### 5–9分钟 — 抽/选问题

学生个人或2–3人小组从问题池选择。

### 9–13分钟 — 四问缩小

1. 谁最需要？
2. 他在什么场景遇到问题？
3. 产品只帮一件事，是什么？
4. 做完以后怎样算有用？

### 13–20分钟 — 快速生成原型

模板：

> 我们要给【用户】在【场景】解决【一个小问题】。产品最重要的是让用户完成【核心任务】，完成以后【成功表现】。请基于一个稳定、可运行的微信小程序骨架直接生成最小V1，不需要登录、服务器或复杂接口。最多只做3个功能。

### 20–28分钟 — 只改最影响目标的一处

学生实际用一次，然后问：

> “它真的在解决我们选的那个小问题吗？”

只改一处最关键问题。

### 28–34分钟 — BASE DEADLINE：锁 Sprint V1

必须：
- 用户明确；
- 问题明确；
- 3个以内功能；
- 核心流程可走完；
- 有一处学生决定；
- 可展示。

### 34–40分钟 — 30秒互评

组间交换，只回答：

1. 我能看懂你解决什么吗？
2. 哪个功能最有用？
3. 有没有一个功能其实不需要？

作者可做一次小修改。

### 40–44分钟 — Sprint Showcase

选2–4个作品，重点展示：

> **“问题最小但产品最完整”**

而不是“功能最多”。

### 44–45分钟 — 连接 L13

教师说：

> “今天是训练赛。下一课你们会用这一学期学到的方法，正式启动自己的最终产品。”

## 5. DISPLAY-SAFE BASE

- 真实但小的问题；
- 明确用户；
- 一个核心任务；
- 最多3个核心功能；
- 稳定可运行；
- 可30秒解释；
- 可扫码/展示。

## 6. FALLBACK

### 问题太大

> 把目标缩成“一个用户在一次使用中只完成一件事”。

### 依赖真实学校后台/API

> 改为本地数据/演示版，不接真实系统。

### 28分钟仍不稳定

> 切回 M1/M2 稳定母版，只保留用户、核心任务和1–2个功能，先锁完整原型。

## 7. Challenge

只允许已经完成 Sprint V1 的学生：

- 增加第二优先级功能；
- 换一个用户重新思考；
- 用同一问题做第二种方案并比较；
- M5通过后尝试记录/工具版本。

## 8. 与 L13 的区别

### L12

> **教师给问题池 / 限时 Sprint / 练习缩范围。**

### L13

> **学生正式选自己的最终产品 / 决定用户与方向 / 建立 Final V1。**

这一区分必须在教师手册中保留，避免两课重新合并成重复内容。

## 9. 课后教师最小记录

- Sprint V1 按时完成率；
- 最大问题是否成功缩小；
- 最常见“问题太大”类型；
- 最容易依赖真实后台/API的需求；
- “问题小但产品完整”的优秀案例；
- 哪些问题值得以后进入正式 Sprint 题库。
