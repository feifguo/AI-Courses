# 初中 L14 — 功能取舍与产品升级 V0.1

更新时间：2026-09-01
状态：READY FOR INTERNAL WALKTHROUGH
年级：7–9年级
标准课时：45分钟
主机制：核心流程 / 功能优先级 / V2升级
适用母版：M1/M2，未来扩展 M3–M5
前置：最终项目 V1

## 1. 本节课对外成果

每名学生把最终项目 V1 升级为稳定 V2，至少具备：

- 一个完整核心流程；
- 一个状态/数据机制；
- 一个视觉 Wow；
- 一个学生原创功能；
- 至少一次主动删减/弱化。

目标是：
> **更完整，但不是更臃肿。**

## 2. 核心观念

教师板书：
> **产品升级 = 加最重要的 + 删不重要的。**

不允许把本节变成“最后疯狂堆功能”。

## 3. 四格升级卡
学生必须写：
1. 核心流程是什么；
2. 还缺哪一个最重要功能；
3. 哪个功能只是“想要”而不是“必须”；
4. 哪个地方最值得增加一个展示 Wow。

## 4. 45分钟时间盒

### 0–5分钟 — 看两个版本
一个功能多但乱，一个功能少但清楚。

### 5–10分钟 — 完成四格升级卡
教师只检查范围，不让学生立刻生成。

### 10–18分钟 — 加最重要的一项
模板：
> 我的产品给【用户】完成【核心任务】。当前V1最缺的是【功能】。请只增加这一项，并保留【核心流程/稳定功能】。完成后自己完整测试。

### 18–25分钟 — 加一个状态/数据或反馈机制
如：
- 进度；
- 积分；
- 收藏；
- 状态；
- 记录；
- 完成反馈。

只选一个真正支持核心任务的机制。

### 25–33分钟 — BASE DEADLINE：形成 V2
到33分钟必须：
- 核心流程能走完；
- 主要升级工作；
- 有学生原创功能；
- 有展示效果；
- 稳定可试玩。

### 33–38分钟 — 强制做一次删减/弱化判断
学生必须选：
- 删除；
- 合并；
- 弱化；
- 保留并说明原因。

至少对一个次要功能做决策。

### 38–42分钟 — Challenge / 第二优先级功能
仅稳定学生继续。

### 42–45分钟 — V2说明
> “V2最重要增加的是【功能】，我同时删/弱化了【功能】，因为【理由】。”

## 5. DISPLAY-SAFE BASE
- 完整核心流程；
- 一个状态/数据机制；
- 一个视觉/反馈亮点；
- 一个学生原创功能；
- 一次功能取舍；
- 稳定可展示。

## 6. FALLBACK
若33分钟仍不稳定：
> 回到V1稳定版，只保留最重要的一项升级【功能】和一个低风险展示效果，移除本节其他新增内容。优先保证核心流程完整。

## 7. 教师追问
“都重要” → “如果只能留三个呢？”

“我还要加很多” → “你的核心用户最先会用哪个？”

“删了可惜” → “它影响核心目标吗？”

## 8. Challenge
- 第二用户模式；
- 高级统计；
- 更复杂状态；
- 多模式；
- 自定义设置。

但每次只加一个主要复杂度。

## 9. 课后教师最小记录
- V2稳定完成率；
- 最常见功能膨胀；
- 主动删减人数；
- 哪些原创功能最值得保留；
- 哪些高级功能最容易拖累发布。
