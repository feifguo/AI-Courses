# 初中 L3 — Rule Lab：让产品真正有逻辑 V0.2

更新时间：2026-09-01
状态：READY FOR INTERNAL WALKTHROUGH
年级：7–9年级
标准课时：45分钟
主母版：M1 Game / Rule Engine
平台：微信小程序教育平台

## 1. 本节定位调整

为了避免 L1–L4 连续四周都修改同一个第一课产品，本节默认**新开一个 Rule Lab 产品**。

推荐形式：

> **一个新的、视觉明显不同的小游戏/挑战产品，用来专门实验规则、状态和边界。**

L1/L2 是 Pair A：第一产品 → 产品要求。

L3/L4 是 Pair B：Rule Lab → 版本/回退。

能力连续，但表面作品刷新。

## 2. 对外成果

每名学生在本节完成一个新的 Rule Lab：

> **至少两类相互关联规则、两种可见状态、完整成功/失败路径，并能扫码试玩。**

建议主题池：
- 太空能量挑战；
- 赛车冲刺；
- 生存闯关；
- 足球连胜；
- 魔法能量；
- 自选。

## 3. 能力暗线

1. 把规则说成“条件→结果”；
2. 识别产品里的状态；
3. 设计规则之间的关系；
4. 实际触发规则；
5. 测试边界；
6. 修复逻辑冲突。

不要求学习 if/else、变量等编程术语。

## 4. 45分钟时间盒

### 0–4分钟 — 新作品、新问题
教师演示 Rule Lab 样例，强调：
> “今天不是继续美化上一款产品，而是专门做一个规则实验室。”

### 4–8分钟 — 选主题 + 规则组合
基础学生从菜单选两类：
- 时间；
- 成功/奖励；
- 失败；
- 能量/生命/等级；
- 条件解锁。

### 8–15分钟 — 快速生成新的稳定 BASE
建议任务：
> 帮我做一个【主题】挑战小游戏，基础玩法简单清楚，页面显示分数和一个核心状态。先生成完整可运行版本，不要让我写代码。随后我会自己设计更复杂的规则。

第一版必须试玩。

### 15–22分钟 — 第一条规则
模板：
> 当【条件】发生时，让【结果】发生，并把【状态】显示在页面上。保留目前正常功能。

### 22–30分钟 — 第二条关联规则
必须说明它和第一条的关系。

例：
- 连胜3次→能量+30；
- 答错→连胜清零；
- 能量100→升级；
- 时间结束→禁止继续得分。

### 30–35分钟 — BASE DEADLINE：状态与结束路径
到35分钟必须：
- 两条真实规则；
- 两种可见状态/反馈；
- 一条成功或失败路径；
- 可完整试玩。

### 35–40分钟 — 边界测试
故意测试：
- 结束以后还能不能操作；
- 条件没满足会不会错误触发；
- 状态是否同步；
- 两条规则是否冲突。

### 40–43分钟 — Challenge / 收口
快学生增加第三条依赖规则；慢学生只修稳定性。

### 43–45分钟 — Rule Lab 发布
学生一句话：
> “我的两条核心规则是……它们的关系是……”

## 5. DISPLAY-SAFE BASE

- 新的 Rule Lab 产品；
- 至少两条真实规则；
- 至少两种可见状态；
- 规则能真实触发；
- 有结束/失败/奖励反馈；
- 可试玩、可展示。

## 6. FALLBACK

> 回到当前稳定 Rule Lab，只保留【规则A】和【规则B】。页面显示相关状态，删除其他高级规则，并测试正常、失败/结束和触发三种情况。

## 7. RECOVERY

### 条件错误
> 【条件】未满足时就触发 / 满足后没触发。请重新检查并修复，不改变其他规则。

### 结束后还能继续
> 产品已经结束，但用户仍能继续改变状态。请在结束状态停止核心操作，并保留重新开始。

### 状态不同步
> 页面显示和实际规则不一致。请统一状态更新，并完整测试一次。

## 8. Challenge Pool

Quick Win：状态动画、警报、升级提示。

Builder：条件解锁、双倍积分、Boss状态、两阶段难度。

Open Creator：自己先画出三条规则关系，再让 AI 实现。

## 9. 与 L4 的连接

本课最终稳定版直接成为 L4 的：

> **V1 稳定版。**

L4 不再回到 L1 产品，而是使用本节 Rule Lab 练版本修改、比较与回退。

## 10. 课后教师最小记录

- 新 Rule Lab 按时完成率；
- 两条规则稳定率；
- 最常见规则冲突；
- 学生是否因换新作品而保持兴趣；
- 哪些规则组合最适合以后预制。
