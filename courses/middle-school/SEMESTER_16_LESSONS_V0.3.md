# 初中 AI 数字创造课 — 16课时学期版 V0.3

更新时间：2026-09-01
状态：CURRENT SEMESTER STRUCTURE / INTERNAL AUDIT SYNCED / 部分母版待验证
年级：7–9年级
标准课时：45分钟
主平台：微信小程序教育平台

> V0.3 替代 V0.2 作为当前结构基线。重点：两课一个成果 Pair、作品体验刷新、认知课 action-first、BASE Complexity Budget。

## 1. 产品承诺

初中版本不通过增加代码量来变难。

难度增加在：
- 用户；
- 目标；
- 产品要求；
- 规则关系；
- 版本；
- 用户测试；
- AI意见判断；
- 事实核查；
- 功能取舍；
- 发布责任。

学生感受：

> **“我真的可以用 AI 做一个别人能玩的、能用的数字产品，而且最终决定是我做的。”**

---

## 2. 标准课时与复杂度预算

- 30–35分钟左右锁 DISPLAY-SAFE BASE；
- 35–45分钟用于判断、测试、修复、修改和收口；
- 45分钟以外才进入更复杂 Challenge / Open Creation。

审核后硬规则：

> **标准 BASE 原则上只承担 1 个主要复杂修改 + 1 个低风险可见增强。**

认知型课原则讲解尽量3–5分钟；连续10分钟没有学生操作真实作品视为预警。

AI评审、事实核查、AI反方、用户测试必须有可见 Before/After。

## 3. Showcase Pair 结构

### Pair 1 — L1/L2：第一数字产品

**L1 我做出了第一个数字产品**  
M1/M2 Known-Good。先建立“我能做产品”的能力信念。

**L2 把想法变成产品要求**  
同一个产品，明确用户、任务、核心功能和成功表现；原则讲解后快速回到真实作品修改。

里程碑：
> **一个不只是“酷”，而是目标清楚的第一产品。**

### Pair 2 — L3/L4：Rule Lab

**L3 Rule Lab：规则系统**  
默认新开一个 M1 规则实验产品。基础学生优先使用 T1 已验证预设：RL-01 连击系统 / RL-02 倒计时系统，不从空白自由组合多套未知逻辑。

**L4 版本不是越新越好**  
直接使用 L3 Rule Lab：V1 Stable → V2 Candidate → 保留/修复/回退。

里程碑：
> **第二个视觉新鲜的作品，同时形成规则与版本意识。**

### Pair 3 — L5/L6：真正的工具

**L5 多页面真实工具**  
依赖 M5：学习驾驶舱、兴趣数据库、记录工具、校园活动中心等。

**L6 数据会让产品记住用户**  
依赖 M5：本地记录、进度、统计、筛选。

里程碑：
> **一个看起来像真正软件工具的复杂产品。**

状态：等待 M5 最小实测。

### Pair 4 — L7/L8：从“我觉得好用”到真人测试

**L7 把产品做得更顺手**  
学生自己做 UX 检查：首页、按钮、流程、反馈、返回。

**L8 用户测试**  
别人第一次使用；作者少解释；每人优先走2–3分钟核心流程；收反馈、采纳/拒绝、回测。

里程碑：
> **测试前 vs 测试后明显不同的产品。**

### Pair 5 — L9/L10：AI意见与事实都要判断

**L9 让 AI 当评审**  
AI只给最重要3条建议；学生 BASE 只选 **1条** 修改，并保留至少一条没有照做的建议；必须展示 Before/After。

**L10 AI也会胡说**  
BASE核查 **2条关键事实**，用教师预置来源包，至少处理1个错误/不严谨/来源问题，并增加可见可信模块；第3条与多来源冲突进入 Challenge。

里程碑：
> **经过 AI评审、人类判断和事实核查，而且变化肉眼可见的成熟版本。**

### Pair 6 — L11/L12：取舍 + Real Problem Sprint

**L11 让 AI 当反方**  
AI只给最关键3条质疑；BASE只处理1条，通过删除/合并/弱化/重排形成明显 Before/After。

**L12 Real Problem Sprint**  
教师问题池 / 限时训练赛 / 30分钟做最小 V1。重点是“问题小但产品完整”。

里程碑：
> **学生会把真实问题缩到能解决，而不是只会想大项目。**

### Pair 7 — L13/L14：最终产品正式启动

**L13 Final Product Launch**  
学生正式定义最终用户、目标、核心功能、原创决定、Wow，并当堂形成 Final V1。

**L14 功能取舍与 V2**  
V2最终指标是累计状态。本节只新增 **1个最重要复杂升级 + 低风险展示增强 + 1次删减/弱化决策**，不为了凑指标同时新造多套复杂功能。

里程碑：
> **真正属于学生自己的 Final V2。**

### Pair 8 — L15/L16：发布与 Demo Day

**L15 发布前验收**  
Release QA、回归测试、二维码、截图、30秒发布话术；停止继续扩功能。

**L16 AI Product Demo Day**  
扫码体验、产品市集、60秒发布、学校成果沉淀。

最终里程碑：
> **小型学生产品发布会。**

## 4. 四阶段能力跃迁

### Phase 1 — 开始做产品（L1–L4）
- 第一版；
- 产品要求；
- 规则；
- 版本。

### Phase 2 — 产品真的好用（L5–L8）
- 多页面工具；
- 数据；
- UX；
- 真人用户测试。

### Phase 3 — 我会判断 AI（L9–L12）
- AI评审；
- 事实核查；
- AI反方；
- 真实问题缩小。

所有认知动作都必须落回真实作品，并留下可见证据。

### Phase 4 — 我的产品发布（L13–L16）
- Final V1；
- V2取舍；
- Release QA；
- Demo Day。

## 8. 教师讲授与课堂红线

L2/L9/L10/L11 等认知课最容易被老师讲成长篇理论。

硬约束：

> **原则讲解尽量3–5分钟，连续10分钟没有学生操作真实作品视为设计预警。**

不能把产品要求、AI评审、批判性思考、事实核查讲成PPT课。

同时：

> **AI快不代表 BASE 可以同时塞多个复杂修改。**

省下来的时间优先给试玩、验证、修复和创造。

## 9. 淘汰线

- BASE接近45分钟才完成；
- BASE基础路径同时承担多个未稳定复杂修改；
- 连续4周表面作品没有明显刷新；
- 认知课连续10分钟没有真实产品动作；
- 认知课最后没有可见 Before/After；
- 用户测试只是填表没有改产品；
- AI评审/反方变成机械复制建议；
- 最终项目前两节重复定义同一个V1；
- 复杂工具必须靠代码/API才能成立；
- 保底学生无法获得展示级成品。
