# A. 现场学生 Wow Demo

状态：**V0.2 标准课时版已形成，继续作为当前学生现场体验主方案。**

当前主方案：`WECHAT_WOW_DEMO_V0.2_STANDARD_PERIOD.md`

历史参考：`WECHAT_WOW_DEMO_V0.1.md`（原 60 分钟固定版，不再作为默认标准课时版本）

## A1. 角色

这是学生真的参与、真的制作、真的试玩的一堂体验产品。

使用场景：

- 校长现场看学生体验；
- 学校公开课；
- 科技节；
- 家长开放日；
- 学生招募体验；
- 正式课第一课的加强版导入。

现场 Demo 不能只是老师展示，学生必须自己完成一个个性化、可展示的小作品。

## A2. 核心目标

标准课时结束前，理想反应：

学生：
> “我居然真的做出来了。”

家长：
> “这个真的是孩子自己做的吗？”

校长：
> “这个非常适合做学校的特色课程和成果展示。”

课程第一优先不是展示老师多会教，而是保证绝大多数学生都拿到第一眼足够强的成品。

## A3. 标准课时

- **小学：40分钟；**
- **初中：45分钟。**

主作品必须提前完成：

- 小学 BASE 目标约 25–30 分钟内锁定；
- 初中 BASE 目标约 30–35 分钟内锁定；
- 剩余标准课时用于试玩、发现问题、修改、收口和展示。

如果学校给 60/90 分钟，不把前面流程讲慢，而是进入 Challenge / Open Creation。

原则：

> **40分钟能完整交付，60分钟不水，90分钟仍然有创造空间。**

## A4. 当前工具与可行性

2026-08-31 已在真实账号完成微信小程序教育平台 T1/T2：

- M1记忆力翻牌小游戏：`FULL STRONG PASS`；
- M2五年级英语学习平台：`STRONG PASS`。

已验证：

- 分钟级第一版；
- 自然语言修改主题、规则、动画和学习逻辑；
- AI自修真实故障；
- 二维码发布；
- 家长端免登录试玩；
- 多功能学习产品可以成立。

T1/T2 是成人真实账号可行性测试，不得写成“真实五年级学生已经完成”。

## A5. 为什么现场 Demo 主任务暂用 M1 游戏

虽然 M2 学习平台更像真实软件、更适合证明课程上限，但第一次现场体验更重视：

- 立即好玩；
- 主动试玩；
- 容易出现“我还想让它……”；
- 同伴可互玩；
- 家长十秒能看懂；
- 故障面较小；
- 40/45分钟稳定达到展示线。

因此：

> **M1负责现场第一节的稳定成功；M2及后续知识/工具产品负责证明课程不是小游戏课。**

## A6. 学生所有权

基础学生最低至少有：

1. 自己的主题/内容选择；
2. 一个规则或 Wow 效果选择；
3. 一次真实试玩；
4. 一次确认/修改。

正常/高能力学生继续进入：

- 自己设计规则；
- “我还想让它……”；
- 同伴反馈；
- 第二轮迭代；
- 新页面/新模式。

## A7. 能力暗线

课程训练但不需要作为现场显性理论课讲满：

- 把想法说清楚；
- 把“不喜欢”变成具体修改要求；
- 不相信 AI 自称完成，要试玩验证；
- 遇到故障先描述现象并让 AI 自检；
- 复杂需求拆成一步一步；
- 接受反馈并判断是否采纳；
- 能说明 AI 第一版哪里不对、后来改了什么。

仍然服从第一优先级：

> **先保证成品展示成功，再在成品之上拉高能力。**

## A8. 当前研发方法

不再把 `1老师 + 5学生` 作为上线前强制 Gate。

路径：

> **逆向成熟课程与真实课堂 → V0.x → 内部完整走课与教师准备 → 达到可交付线直接进学校 → 用真实课堂持续迭代。**

# B. 校长采购销售 Demo 视频

状态：**V0.1 制作说明已形成。**

入口：`PRINCIPAL_SALES_DEMO_VIDEO_V0.1.md`

这是一个完全不同的产品。

## B1. 它不是什么

不是：

- 把现场 Demo 课录下来；
- 40分钟课堂录像；
- 学生教程；
- AI平台介绍；
- Prompt教学。

## B2. 它是什么

> **2分30秒—3分30秒左右的动态PPT式销售讲解 + 少量真实成果录屏。**

面向：

- 校长；
- 学校课程负责人；
- 其他采购决策者。

核心目标：

1. 先让校长看到孩子可以做出很强的数字产品；
2. 让校长知道这不是简单“一键生成”；
3. 用少量专业概念证明课程有含金量；
4. 用完整课程路径和学校成果建立采购价值。

## B3. 核心原则

> **录制结果，讲解过程，抽象方法，保护配方。**

真实录制只用于：

- 产品运行；
- 手机扫码；
- Bug表现；
- 修复后的结果；
- 多个不同作品。

不展示：

- 完整原始 Prompt；
- 母版生成指令；
- 完整 Debug 输入；
- Recovery；
- 一句话/一分钟自动生成全过程；
- 代码。

原因：

> **既要证明孩子能做到，又不能让校长把课程价值全部归因给底层工具。**

## B4. 销售视频主视觉

不要只放小游戏。

应更多展示：

- 学习平台；
- 学习工具；
- 数字知识产品；
- 校园工具；
- 最终原创数字产品。

小游戏只作为早期互动创作的快速证据。

## B5. 专业能力只讲少量

第一版重点：

- **需求定义**；
- **系统逻辑**；
- **测试与调试**；
- **AI能力边界 / 人的判断**。

每个采用：

> **中文专业词 + 一句直观解释 + 一句传统产品/软件开发中的对应关系。**

让校长大概听懂，同时感受到这原本是专业工作。

不要堆英文术语，不要堆十几个能力概念。

## B6. 权威背书控制

短暂使用：

- 世界经济论坛《未来就业报告2025》：分析性思维、创造性思维、技术素养、系统思维；
- 联合国教科文组织学生AI能力框架：问题界定、系统设计、测试与优化、从使用走向创造。

不要继续延展成完整未来教育理论。

# C. 商业交付对 Demo 的影响

当前交付链：

> **课程开发方 → 代理商/区域伙伴 → 学校 → 代理商受训教师到校上课 → 学生。**

因此校长销售 Demo 不需要重点证明：

> 学校自己的老师是否能够马上学会并独立授课。

这属于代理商教师培训/认证的后台交付能力。

校长更需要看到：

- 供应方能完整交付；
- 学校自身负担低；
- 大部分学生成功；
- 产品成果强；
- 有完整学期成长；
- 有学校可以展示/传播的成果。

---

# D. Demo 产品线共同底线

无论现场 Demo 还是销售视频，都不能让外部形成：

> “这就是AI平台自己很厉害，课程没什么价值。”

同时也不能为了保护课程价值，故意隐藏AI或假装所有技术都是学生手工完成。

正确表达：

> **AI降低了技术实现门槛；课程把需求、规则、判断、测试、迭代和创造重新设计成了这个年龄的孩子能够实践的项目。**

现场 Demo 用学生真实行动证明。

销售视频用真实成果 + 简短专业讲解证明。
