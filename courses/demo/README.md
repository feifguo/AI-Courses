# AI Wow Demo — 入门演示课

状态：**V0.2 标准课时版已形成，继续作为当前主方案产品化。**

当前主方案：`WECHAT_WOW_DEMO_V0.2_STANDARD_PERIOD.md`

历史参考：`WECHAT_WOW_DEMO_V0.1.md`（原 60 分钟固定版，不再作为默认标准课时版本）

## 1. 角色

AI Wow Demo 不是正式学期课的“第一章知识介绍”，而是一款独立但能连接正式课的体验产品。

使用场景：

- 校长/学校采购前体验；
- 学校公开课；
- 科技节；
- 家长开放日；
- 学生招募体验；
- 正式课第一课的加强版导入。

## 2. 核心目标

标准课时结束前，理想反应是：

学生：
> “我居然真的做出来了。”

家长：
> “这个真的是孩子自己做的吗？”

校长：
> “这个非常适合做学校的特色课程和成果展示。”

课程第一优先不是展示老师多会教，而是保证绝大多数学生都拿到第一眼足够强的成品。

## 3. 标准课时基准

当前默认适配：

- **小学：40分钟；**
- **初中：45分钟。**

但主作品必须提前完成：

- 小学 BASE 目标约 25–30 分钟内锁定；
- 初中 BASE 目标约 30–35 分钟内锁定；
- 剩余标准课时用于试玩、发现问题、修改、收口和展示。

如果学校给 60/90 分钟，不把前面流程讲慢，而是自然进入 Challenge / Open Creation。

原则：

> **40分钟能完整交付，60分钟不水，90分钟仍然有创造空间。**

详见：
- `../../docs/STANDARD_PERIOD_AND_EXTENSION_POLICY.md`
- `../../docs/CHALLENGE_POOL_SYSTEM_V1.md`

## 4. 当前工具与可行性事实

2026-08-31 已在真实账号完成微信小程序教育平台 T1/T2：

- 记忆力翻牌小游戏：第一版和各轮修改均约 1 分钟内完成；
- 自然语言可修改主题、倒计时、连击、计分和动画；
- 出现真实“持续加载”故障后，AI 可在不要求用户手写代码的情况下自检并修复；
- 可发布二维码，家长端免登录试玩；
- 五年级英语学习平台：第一版约 2 分钟；第一次复杂学习规则修改约 2 分钟；后两次功能修改约 1 分钟；全部核心学习/闯关功能实现。

因此 Demo 当前不再验证“AI能不能做出来”，而是围绕：

> **怎么让低能力学生也稳定拿到酷炫成品，同时让高能力学生不封顶地继续发挥。**

## 5. Demo V0.2 当前选择

学生主任务暂定：

> **标准课时内做出人生第一个可扫码试玩的微信小程序——个性化记忆力小游戏。**

采用：

> **稳定骨架 + 主题自由 + 规则/Wow自由 + Challenge/Open Creation。**

不是全班复制同一个成品，也不是让零基础学生从空白分别做完全不同的软件。

基础学生可使用：

- 稳定母版；
- 主题菜单；
- 规则菜单；
- 半结构化 Prompt；
- FALLBACK；
- 必要的教师局部操作协助。

但保底作品也必须达到展示级。

高能力学生一完成 BASE，立即进入 Challenge，不等待全班。

## 6. 为什么 Demo 先用小游戏，而不是英语学习平台

英语学习平台已经实测 Strong Pass，且更能体现“小学生做出真正产品”的能力反差。

但第一次体验优先追求：

- 立即好玩；
- 学生愿意主动试玩；
- 自然产生“我还想让它……”；
- 同学之间容易互相试玩；
- 家长十秒看懂；
- 故障面较小；
- 标准40/45分钟内容易稳定达到展示线。

因此小游戏暂作为 Demo 主任务，英语学习平台用于：

- 开场/结尾展示一学期能力上限；
- 正式课程中的“从好玩到有用”的能力跃迁；
- 学校/家长成果展示。

## 7. Demo 不是教师魔术秀

必须避免：

- 老师展示一个很强产品，学生只看；
- 学生只按一个按钮得到同样结果；
- 全班作品几乎一模一样；
- 弱学生因为追求独立而整节课没有成品；
- 快学生完成后只能等待；
- Demo 用的技术太复杂，正式复制困难。

### 基础学生最低所有权

至少有：

1. 一个自己的主题/内容选择；
2. 一个规则或 Wow 效果选择；
3. 一次真实试玩；
4. 一次确认/修改。

### 正常/高能力学生

继续增加：

- 自己设计的规则；
- “我还想让它……”；
- 同伴反馈；
- 第二轮迭代；
- 新页面/新模式。

## 8. Demo 的能力暗线

学生不是显性学习“Prompt 工程”。

课程实际训练：

- 把想法说清楚；
- 从“我不喜欢”变成具体修改要求；
- 不相信 AI 自称完成，要实际试玩验证；
- 遇到故障描述现象并让 AI 自检；
- 复杂需求拆成一步一步；
- 接受同伴反馈并判断是否采纳；
- 能说明 AI 第一版哪里不对、自己后来改了什么。

但能力训练不能破坏第一优先级：

> **先保证成品展示成功，再在成品之上尽可能拉高能力。**

## 9. 弹性时长

### 小学 40 分钟

完整产品闭环必须成立。

### 初中 45 分钟

完整产品闭环成立，并多一次用户/规则判断。

### 60 分钟

标准课核心不减速；额外进入：

- Builder Challenge；
- 同伴试玩；
- 第二次修改；
- Open Creation。

### 80–90 分钟 / 双课时

第一课时先锁成果；第二阶段进入：

- Creator Challenge；
- 新页面/新模式；
- 多人测试；
- 第二轮迭代；
- 小型产品发布。

## 10. 当前研发方法

不再把 `1老师 + 5学生` 作为上线前强制 Gate。

当前路径：

> **逆向成熟课程与真实课堂 → 完成 Demo/正式课 V0.x → 内部完整走课与教师准备 → 达到可交付线后直接进学校 → 在真实课堂持续迭代。**

小规模测试只在需要发现明显教案歧义或操作卡点时作为可选 smoke test。

当前真正要完成的是：

- BASE/FALLBACK 母版；
- 标准40/45分钟教师脚本；
- Challenge Pool；
- 恢复路径；
- 学生材料；
- 展示/二维码流程；
- 教师培训；
- 学校开课前环境 smoke check。

## 11. Demo 成功标准

### P0 对外成果

- 绝大多数学生在标准课时结束前明显提前达到展示线；
- BASE 已经够酷；
- 扫码可玩；
- 家长/校方 10 秒能看懂；
- 不同学生作品有肉眼可见差异。

### P1 课堂可交付

- 弱学生有统一兜底，不依赖老师逐个长期救援；
- 快学生几乎没有等待；
- 延长课时自然增加创造深度；
- 普通教师不需要懂编程。

### P2 能力暗线

至少经历：

> **生成 → 试玩 → 找问题 → 修改 → 再验证。**

有更多时间再增加：

> **同伴反馈 → 判断 → 再迭代。**
