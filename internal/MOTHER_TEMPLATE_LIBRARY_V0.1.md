# 课程母版引擎库 V0.1

更新时间：2026-09-01
状态：INTERNAL R&D / NOT CHANNEL DISTRIBUTION SOURCE

## 1. 目的

正式课程不应该等于：

> 16 节课 = 16 套完全独立技术方案。

否则会导致：

- 研发成本高；
- 老师难培训；
- 出错类型不可控；
- 代理商教师必须不断学习新工具；
- 保底成功率下降；
- 每次平台变化都要重做整套课程。

更合理的结构是：

> **5–7 套稳定“母版引擎” × 不同主题 × 不同规则 × 不同挑战 = 一学期丰富课程。**

核心价值：

- 低能力学生靠母版保证展示级成品；
- 普通老师只需要熟悉少数底层机制；
- 强学生仍然可以把母版改到完全不同；
- 出错和恢复路径可以高度复用；
- 课程方可以持续替换底层平台而保持课程表面稳定。

# M1 — GAME CORE / 游戏核心引擎

## 当前状态

> **KNOWN-GOOD / 已真实验证**

来源：微信小程序教育平台 T1。

## 当前稳定形态

记忆翻牌游戏。

稳定能力已真实跑通：

- 卡片；
- 配对；
- 计分；
- 成功/失败；
- 倒计时；
- 连击；
- 额外加分；
- 动画；
- 主题切换；
- AI 自修一次真实兼容故障；
- 二维码发布。

## 可换主题

- 太空；
- 恐龙；
- 足球；
- 海洋；
- 魔法；
- 动物；
- 文化；
- 学科知识。

## 可换规则

### Tier A
- 倒计时；
- 三次错误失败；
- 配对加分。

### Tier B
- 连击；
- 额外奖励；
- 多关卡；
- 特殊卡。

### Tier C
- Boss；
- 随机事件；
- 道具；
- 复杂状态。

## 对应课程

小学：L1/L2。
初中：L1/L3 可作为第一引擎。

## FALLBACK

保留原稳定游戏逻辑，只回退学生新增规则，保留其主题/视觉。

- 最高连胜；

## 可换主题

- 英语；
- 成语；
- 古诗；
- 科学；
- 地理；
- 历史；
- 兴趣知识。

## 课程价值

- 校长展示；

- 学期中段能力跃迁；

- 回到基础学习 + 四选一闯关；
- 保留学生主题和题库；
- 删除新增复杂状态。

# M3 — BRANCHING STORY / 互动故事引擎

## 当前状态

> **PLANNED / 需原型验证**

## 目标稳定能力

- 开场页；
- 角色；
- 分支选择；
- 2–3种结局；
- 图片/背景；
- 基础状态；
- 奖励/隐藏结局。

## 适合原因

- 小学表达门槛低；
- 主题差异巨大；
- 很容易形成“这是我的故事”；
- 能自然训练条件和因果；
- 家长第一眼容易理解。

## BASE

统一三次选择 + 两个结局结构。

## CHALLENGE

- 多角色；
- 道具；
- 生命值；
- 隐藏路线；
- 多章节。

## 风险

如果AI生成长文本过多，作品容易变成“读故事”而不是互动产品。

验收时必须保证：

> **交互优先于文字长度。**

- 图片；

- 成就/隐藏内容。

## 主题

- 恐龙；
- 昆虫；
- 汽车；
- 足球；
- 航天；
- 海洋；
- 音乐；
- 城市/旅行；
- 学生自选。

## 产品价值

学生不需要先解决陌生领域问题，而是在自己已有兴趣上学习如何组织信息、设计交互和验证事实。

## FALLBACK

固定 4 个展区 + 8 张内容卡 + 5题测验。

## CHALLENGE

搜索、收藏榜、隐藏展品、专题路线、用户自定义内容。

## 产品价值

> **“孩子居然做了一个真的工具。”**

## 风险

容易功能很多但实际没有明确用户体验。

BASE 必须限制在 3–4 个真正能工作的模块。

# M6 — CAMPUS / REAL PROBLEM APP / 校园真实问题引擎

## 当前状态

> **PLANNED / 不是单一技术母版，而是 M2/M4/M5 的场景化组合层**

## 典型产品

- 校园导览；
- 社团活动；
- 图书推荐；
- 环保挑战；
- 运动记录；
- 校园文化；
- 失物招领演示；
- 班级活动助手。

## 设计原则

不让学生从“发现问题”直接跳到完全自由开发。

课程方应先提供：

- 问题菜单；
- 对应稳定母版；
- 3个建议核心功能。

强学生再自己发现问题。

## 产品价值

最适合向学校证明：

> **这门课不仅好玩，孩子还在用 AI 解决身边真实问题。**

# M7 — FINAL PRODUCT SHELL / 最终产品发布框架

## 当前状态

> **DESIGN LAYER / 复用 M1–M6**

不是新的技术模板。

最终项目让学生选择 M1–M6 中任一母版作为起点。

## BASE

每个项目必须有：

- 用户/体验对象；
- 3个核心功能；
- 一个明显 Wow；
- 一个学生原创修改；
- 一次用户试玩；
- 一次反馈后修改；
- 二维码；
- 作品卡。

## CHALLENGE

强学生可以完全脱离原母版。

# 9. 当前原型验证优先级

已经 Known-Good：

1. M1 Game Core；
2. M2 Learning Hub。

下一优先：

3. M5 Dashboard / Tracker；
4. M3 Branching Story；
5. M4 Museum / Interest Base。

原因：

- M5 最接近“孩子做成人级生产力工具”的能力冲击；
- M3 最适合小学趣味和所有权；
- M4 最适合兴趣 + 内容 + 学校展示。

M6 不需要单独技术验证，主要是场景设计与母版映射。

# 10. 渠道壁垒意义

对代理教师来说，正式交付只需要知道：

- 本节课如何启动；
- 本节可选主题；
- 学生可选规则；
- 遇到常见问题怎么办；
- 什么时候启用 FALLBACK；
- 强学生挑战是什么。

课程方内部则掌握：

- 哪个母版版本最稳定；
- 哪些生成策略失败率高；
- 哪些规则组合最容易破坏作品；
- 不同年龄用什么默认复杂度；
- 完整 Prompt 和恢复库；
- 母版迁移到下一平台的方法。

这部分持续迭代的数据和经验才是真正难以被代理商一次性复制的研发资产。
