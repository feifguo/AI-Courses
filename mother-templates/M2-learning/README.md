# M2 — Learning Platform / Quiz Engine 母版

更新时间：2026-09-01
状态：KNOWN-GOOD / PRODUCTIZATION V0.1
证据：微信小程序教育平台 T2 STRONG PASS

## 1. 母版承诺

让小学高年级或初中零编程学生快速做出：

> **一个像真正学习 App 的多页面学习/闯关平台。**

学生不是学编程，而是在设计：

- 学什么；
- 怎么学；
- 怎么闯关；
- 答错以后怎样反馈；
- 积分/连胜怎样工作；
- 用户如何看到进度；
- 哪些内容是自己的。

## 2. DISPLAY-SAFE BASE

默认稳定结构：

- 首页；
- 4 个学习主题；
- 每个主题若干知识卡；
- 学习模式；
- 闯关模式；
- 10题四选一；
- 即时反馈；
- 积分；
- 完成进度；
- 连续学习/状态信息；
- 本地数据；
- 现代、明亮、有游戏感但不过度幼稚的视觉。

小学 BASE 目标：25–30分钟内锁定。

初中 BASE 目标：30–35分钟内锁定，并增加更多产品判断和内容验证。

## 3. 已验证能力

T2 真实账号已完成：

- 首版英语单词学习/闯关平台约 2 分钟；
- 第一次复杂学习规则修改约 2 分钟；
- 后两次修改约 1 分钟；
- 学习模式；
- 闯关模式；
- 进度；
- 积分；
- 答错提示再尝试；
- 二次答对不同得分；
- 连续答对 / 超级学习模式；
- 最高连胜；
- 使用者自定义主题与内容；
- 本地数据保存。

这些能力可以优先进入正式 Feature Pool。

## 4. BASE Prompt Skeleton

核心结构：

> 帮我做一个适合【年级】使用的“【主题】学习闯关平台”微信小程序。不要让我写代码，请直接生成可以运行和预览的完整小程序。首页要像一个真正的学习App，显示学习进度、积分和连续学习信息，并有4个学习主题。每个主题先内置适龄内容。进入主题后有学习模式和闯关模式：学习模式逐条显示内容、解释和例子；闯关模式每次随机出10道四选一题，答对加分，答错给反馈。首页能看到各主题完成进度。界面要明亮、现代、有游戏感但不要幼稚。所有数据先保存在本地，不需要登录、服务器或数据库。

学生最低必须选择：

- 学习主题；
- 至少一组自己的内容；
- 一个反馈/奖励机制；
- 一个视觉主题。

## 8. FALLBACK

触发：

- 多页面结构被改坏；
- 自定义内容功能不稳定；
- 复杂积分逻辑冲突；
- 到 BASE DEADLINE 仍无法完整学习/闯关；
- 学生一口气增加过多功能。

回退：

1. 回到稳定首页 + 主题 + 学习 + 闯关版本；
2. 保留学生主题和视觉；
3. 保留一个已验证游戏化机制；
4. 暂时取消复杂自定义/统计；
5. 完成试玩、截图和二维码。

最低展示线：

> **有多主题、有学习、有闯关、有积分/进度、有学生自己的内容，且可正常试玩。**

## 9. RECOVERY

### 答题逻辑错

> 现在【题目/答案/计分】的实际表现和设定不一致。请检查对应逻辑并修复，保留原来的学习模式、进度和其他主题。修复后自己完整走一遍10题闯关验证。

### 修改破坏进度

> 增加【新功能】后，原来的主题进度/积分记录不正常。请恢复原有记录逻辑，并让新功能与原数据共存。不要增加服务器或外部数据库。

### 自定义内容保存失败

> 用户新增的主题/内容刷新后丢失。请检查本地存储和读取逻辑，修复后验证刷新页面仍然存在。不要加入登录或云数据库。

### 一次要求太多

> 先只实现【一个功能】，其他新增要求暂时不要做。确保原来的学习和闯关都正常后再继续。

## 10. CHALLENGE

标准课时 BASE 后可立即进入：

- 加第二种题型；
- 做错题本；
- 做等级系统；
- 做学习目标；
- 做本周报告；
- 自己设计奖励规则；
- 让同学试玩后改学习流程；
- 把英语平台迁移成完全不同的兴趣学习产品；
- 自由“我还想让它……”。

延长课时目标不是加更多题，而是增加：

> **产品设计差异度 + 用户体验 + 学生所有权。**

## 11. 教师追问

学生说“我想让它更会教”：

- 答错以后你希望它先做什么？
- 什么情况下才应该直接告诉答案？
- 怎样鼓励用户继续？
- 你希望用户为什么愿意第二天再来？

学生说“再多加一些功能”：

- 哪一个功能最能帮助学习？
- 哪一个只是看起来热闹？
- 如果只能保留一个，你留哪个？

初中进一步问：

- 谁是用户？
- 他真正的问题是什么？
- 你怎么判断这个设计有效？

## 12. 内容可信度

M2 涉及知识内容时必须加入简单内容校验。

小学：

- 教师提供安全来源或正确答案；
- 学生抽查若干内容；
- 发现错误就修改产品。

初中：

- 比较来源；
- 识别AI可能的错误；
- 在产品中增加来源/纠错说明。

但不能把整节课变成纯“AI伦理/查证讲座”。最终仍应有可见产品升级。

## 13. SHOWCASE STANDARD

家长/学校 10 秒内应看到：

- 首页像完整学习 App；
- 主题可进入；
- 有学习模式；
- 有闯关模式；
- 分数/进度在变化；
- 有明确奖励反馈；
- 有学生自己的主题/内容；
- 二维码可直接体验。

建议成果：

- 产品封面截图；
- 二维码；
- 15秒“学习→答题→奖励”视频；
- 学生一句话：“我设计了怎样的学习规则”。

## 14. Known Failure / R&D Notes

当前真实 T2 未报告需要人工技术救援的故障。

但后续课堂必须持续记录：

- 本地数据丢失；
- 题库答案错误；
- 多主题进度冲突；
- 游戏化规则破坏基础答题；
- 自定义内容导致结构异常。

任何高频问题都应转成统一 Recovery/Fallback，不依赖教师个别处理。
