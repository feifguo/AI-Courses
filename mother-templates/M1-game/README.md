# M1 — Game / Rule Engine 母版

更新时间：2026-09-01
状态：KNOWN-GOOD / PRODUCTIZATION V0.1
证据：微信小程序教育平台 T1 FULL STRONG PASS

## 1. 母版承诺

让小学高年级或初中零编程学生在标准课时内快速获得：

> **一个真的能玩、规则可改、视觉明显、可以扫码分享的小游戏。**

M1 不是“游戏编程课”。底层代码由 AI 完成，学生主要做：

- 主题选择；
- 规则设计；
- 试玩；
- 发现问题；
- 自然语言修改；
- 展示。

## 2. DISPLAY-SAFE BASE

默认稳定骨架：记忆力翻牌。

必须包含：

- 12 张卡牌 / 6 对；
- 点击翻牌；
- 匹配成功保留并计分；
- 匹配失败延迟翻回；
- 开始 / 重新开始；
- 成功页；
- 明显视觉主题；
- 至少一个动画或反馈；
- 可预览、可试玩、可发布二维码。

小学时间预算：BASE 在 25–30 分钟内锁定。

初中时间预算：BASE 在 30–35 分钟内锁定，但学生承担更多规则表达和验证。

## 3. 已验证能力

T1 真实账号已经完成：

- 第一版生成 <1 分钟；
- 太空主题改造 <1 分钟；
- 60秒倒计时；
- 时间到失败；
- 三连击额外加分；
- 连击动画；
- 通关火箭升空；
- 真实“持续加载”故障由 AI 自检、自修；
- 发布二维码；
- 家长端免登录试玩。

因此这些功能可优先进入正式 Rule/Wow 选项池。

## 4. BASE Prompt Skeleton

教师/学生执行版本不必暴露完整研发母版，可按课程主题动态下发。

核心结构：

> 帮我做一个适合【年级】玩的“记忆力翻牌”小游戏，主题是【主题】。页面有12张卡片，共6对图案，请根据主题选择6对合适图案。开始时全部背面朝上，每次点击两张；相同则保持翻开并得10分，不同则1秒后翻回。全部配对成功后显示挑战成功和总分。界面要符合主题、好看、有开始和重新开始按钮。请直接生成可以运行和预览的小程序，不要让我自己写代码。

学生最低必须做自己的：

- 主题；
- 卡牌内容；
- 一个视觉选择；
- 一个规则/Wow 选择。

## 6. RULE OPTIONS

### Quick Win

- 60秒倒计时；
- 三次错误失败；
- 连续配对加分；
- 通关奖励；
- 最高分记录。

### Builder

- 三连击超级模式；
- 多关卡；
- 不同卡牌不同分值；
- 特殊卡；
- 难度递增；
- 生命值；
- Boss / 最后一关。

### Creator

学生自己定义：

- 触发条件；
- 奖励/失败；
- 状态变化；
- 多模式；
- 自己的新玩法。

教师只帮助把模糊想法转成：

> **什么时候发生 → 发生什么 → 发生后数值/状态怎样变化。**

## 7. WOW OPTIONS

优先使用低风险、第一眼明显的效果：

- 火箭升空；
- 恐龙蛋孵化；
- 烟花；
- 奖杯；
- 球门进球；
- 宝箱打开；
- 角色庆祝；
- 背景主题切换；
- 连击动画；
- 升级动画。

原则：

> Wow 负责增强外行第一眼，不应显著增加技术救援负担。

## 8. FALLBACK

触发条件：

- BASE DEADLINE 前没有可玩版本；
- 两次修改后仍无法试玩；
- 新规则破坏基础玩法；
- 学生需求过大且无法在课内收口。

回退策略：

1. 回到最后稳定的翻牌版本；
2. 保留学生主题和视觉；
3. 只保留一条已验证规则；
4. 加一个已验证 Wow；
5. 停止继续加复杂功能；
6. 完成试玩和二维码。

最低展示线：

> **主题明显 + 核心玩法稳定 + 一条个性规则/效果 + 可扫码。**

## 9. RECOVERY

### 预览持续加载

> 现在预览一直加载/打不开。请检查最近修改、项目配置和兼容性并自己修复。不要破坏之前已经能玩的核心功能。修复后请确认重新预览可正常打开。

### 新功能没生效

> 你说已经实现【功能】，但我实际试玩时没有发生。请检查触发条件和逻辑，修好后不要影响原来的配对玩法。

### 新功能破坏旧功能

> 这次修改以后【原功能】坏了。请保留新增的【新功能】，同时恢复【旧功能】。完成后请自己检查两者是否冲突。

### 需求太复杂

统一缩成：

> 先只实现【第一件事】，其他功能暂时不要动。确认这一步可玩后再继续。

## 10. CHALLENGE

完成 BASE 后学生无需等待。

延长课时挑战：

- 自己设计新规则；
- 增加隐藏机制；
- 加第二关；
- 加玩家选择；
- 加成就系统；
- 改成完全不同主题；
- 让同学试玩后按反馈再改；
- 自由“我还想让它……”。

Challenge 失败不能破坏 BASE；必要时回到稳定版本。

## 11. 教师追问

学生说“我想更好玩”：

- 什么情况下发生？
- 玩家做什么以后触发？
- 触发后发生什么？
- 分数/生命/时间怎么变？

学生说“它没做好”：

- 你本来想怎样？
- 现在实际怎样？
- 你准备怎么告诉 AI？
- AI说修好了，你实际试玩了吗？

## 12. SHOWCASE STANDARD

家长/学校 10 秒内应看到：

- 主题明显；
- 点击后有动作；
- 分数/时间/状态在变化；
- 通关有明显反馈；
- 学生版本彼此不同；
- 手机扫码可直接玩。

建议成果：

- 二维码；
- 一张游戏封面图；
- 10–15秒玩法视频；
- 学生一句话：“我加了什么规则”。

## 13. Known Failure / R&D Notes

已真实出现过：预览持续加载。

AI 成功通过项目配置、基础库版本、URL校验和不兼容 WXSS 效果调整完成修复。

课程侧结论：

> 默认先用自然语言自修，不教学生手动处理配置和代码。

以后真实课堂高频出现的新失败必须进入本节 Known Failure，而不是靠老师记忆处理。
