# 核心母版产品化规格 V0.1

更新时间：2026-09-01
状态：PROVISIONAL / WAITING FOR M3-M5 HANDS-ON VALIDATION

> 本文件定义 M3/M4/M5 一旦通过真实账号验证后，如何立即进入课程产品化。未通过实测前，以下规格是研发目标，不得写成 Known-Good。

## 1. 为什么先产品化母版，而不是逐节课从零开发

小学高年级与初中 16 课时 V0.2 表面上有 32 个课次，但底层不应存在 32 套独立技术方案。

课程应尽量复用少数稳定母版：

- M1：小游戏 / 规则系统 — 已验证；
- M2：学习平台 / 闯关系统 — 已验证；
- M3：互动故事 / 分支世界 — 待验证；
- M4：兴趣馆 / 知识产品 — 待验证；
- M5：工作台 / 记录 / 校园工具 — 待验证。

核心目标：

> **少数稳定母版 × 主题/内容/规则/挑战组合 = 大量不同课程与学生作品。**

这样可以同时提高：

- 课堂成功率；
- 教师可复制性；
- 低能力学生完成率；
- 故障恢复效率；
- 课程持续更新效率；
- 代理渠道保护能力。

# 2. 所有母版共用的产品结构

每套正式母版必须同时具备以下资产。

## 2.1 BASE — 展示级稳定底座

要求：

- 不需要手写代码；
- 首次生成/加载后即可完整试玩；
- 即使学生只完成 BASE，也适合二维码展示、家长扫码和学校拍摄；
- 至少有一个真实可交互机制；
- 视觉不能像低配教学 Demo；
- 小学目标 25–30 分钟内可完成，初中 30–35 分钟内可完成；
- BASE 完成后继续拓展，不等待全班。

## 2.2 FALLBACK — 强制兜底版本

用途：

- 学生版本被改坏；
- 学生表达困难；
- AI连续两轮修改仍失败；
- 到 BASE DEADLINE 仍未达展示线；
- 教师需要一次性救回多个学生。

FALLBACK 不允许是“差生版”。

要求：

- 保留学生主题/内容至少两处；
- 恢复核心交互；
- 保留一个 Wow 效果；
- 可以继续试玩和发布；
- 教师最好能通过统一 Prompt/稳定版本恢复，而不是逐台改代码。

## 2.3 THEME OPTIONS — 主题池

每个母版至少准备：

- 5–8 个高成功率主题；
- 1 个自由主题入口；
- 小学主题更具画面和角色感；
- 初中主题增加校园、学习、真实问题和兴趣工具。

## 2.4 FEATURE / RULE OPTIONS — 功能菜单

分三档：

### Quick Win
一句话即可明显升级，失败风险低。

### Builder
增加真实规则、状态、记录、分支或用户流程。

### Creator
学生自己定义机制、页面、模式或产品逻辑。

## 2.5 WOW OPTIONS — 展示增强

必须有“外行第一眼能看懂”的增强项，例如：

- 动画；
- 通关/升级反馈；
- 进度条；
- 徽章；
- 隐藏内容；
- 仪表盘；
- 结局动画；
- 卡片/展馆视觉；
- 数据可视化。

原则：

> Wow 元素应技术简单、视觉明显、失败风险低。

## 2.6 RECOVERY — 自然语言恢复

每套母版至少准备：

- 打不开/持续加载；
- 新功能没生效；
- 新功能破坏旧功能；
- 本地数据不保存；
- 某页面导航失败；
- 样式破坏；
- 回到最近稳定版。

## 2.7 CHALLENGE — 延长课时与强学生上探

与 `CHALLENGE_POOL_SYSTEM_V1.md` 对齐。

要求：

- 40/45 分钟标准课不依赖 Challenge 才完成；
- 60/90 分钟可以自然扩展；
- Challenge 失败不得破坏已完成 BASE；
- 强学生可以持续自由发挥。

# 3. M3 产品化目标 — 互动故事 / 分支世界

状态：待真实验证。

## 3.1 DISPLAY-SAFE BASE

稳定结构：

- 开场；
- 角色；
- 3 次选择；
- 至少 3 种结局；
- 重新开始；
- 场景/角色视觉；
- 明显按钮；
- 至少一个结局动画。

小学默认主题：

- 恐龙岛逃生；
- 太空救援；
- 海底探险；
- 魔法学院；
- 神秘古城；
- 昆虫王国。

## 3.2 FALLBACK

如果学生分支逻辑改坏：

> 回到稳定三结局版本，只保留学生主题、角色名和一个个性化结局；停止继续增加状态系统。

最低展示线：

- 3 次选择；
- 2–3 种结局；
- 至少一处个人内容；
- 可重玩；
- 可扫码。

## 3.3 Quick Win

- 改主角名字；
- 改角色身份；
- 改一个场景；
- 增加结局动画；
- 增加隐藏提示。

## 3.4 Builder

- 勇气值；
- 补给；
- 道具；
- 身份专属分支；
- 隐藏结局；
- 收集线索。

## 3.5 Creator

- 自己画完整故事树；
- 自定义多个状态；
- 多角色视角；
- 新地图/章节；
- 设计“坏结局为什么发生”。

## 3.6 教师最重要的支架

不问：

> “你要写什么故事？”

而问：

1. 主角现在在哪？
2. 他遇到什么问题？
3. 玩家现在可以做哪两件事？
4. 不同选择会造成什么后果？

核心能力暗线：

> **把故事创意变成条件、选择和结果。**

# 4. M4 产品化目标 — 兴趣馆 / 知识产品

状态：待真实验证。

## 4.1 DISPLAY-SAFE BASE

稳定结构：

- 首页；
- 4 个主题展区；
- 每区 3 个展品；
- 展品详情；
- 收藏；
- 探索进度；
- 10 题知识挑战；
- 积分/通关；
- 统一视觉主题。

小学高成功主题：

- 恐龙；
- 昆虫；
- 航天；
- 海洋；
- 赛车；
- 足球；
- 动物；
- 中国古建筑。

## 4.2 FALLBACK

如果自定义数据、收藏或进度损坏：

> 回到稳定 4 展区 + 详情 + 10题挑战版本；保留学生选定主题、馆名、视觉风格和一个自定义展区。

最低展示线：

- 看起来像数字博物馆；
- 不是文字列表；
- 能逛；
- 能点详情；
- 能完成挑战；
- 能扫码。

## 4.3 Quick Win

- 改馆名；
- 改配色/视觉；
- 增加馆长欢迎语；
- 增加隐藏展品；
- 增加收藏徽章。

## 4.4 Builder

- 探索进度；
- 搜索；
- 展品对比；
- 错题再挑战；
- Boss 题；
- 自定义新展区。

## 4.5 Creator

- 自己定义完整主题馆；
- 自己组织展区结构；
- 设计可信信息卡；
- 比较多个来源；
- 让同学试玩后重新组织内容。

## 4.6 教师最重要的支架

教师不替学生做百科编辑。

关键问题：

1. 你这个馆最想让别人看到什么？
2. 为什么分成这几个展区？
3. 哪条信息最可能是 AI 说错的？
4. 你怎么确认？

核心能力暗线：

> **信息结构 + 内容选择 + 简单查证。**

# 5. M5 产品化目标 — 工作台 / 记录 / 校园工具

状态：待真实验证。

## 5.1 DISPLAY-SAFE BASE

学习驾驶舱稳定结构：

- 仪表盘首页；
- 今日待办；
- 专注记录；
- 学习/阅读记录；
- 本周统计；
- 本地保存；
- 进度/图表；
- 状态卡片。

原则：

> **视觉复杂度高，真实技术复杂度低。**

## 5.2 FALLBACK

如果某个统计/目标逻辑失败：

> 保留首页仪表盘、待办、学习记录和简单周进度；移除复杂统计；保留学生主题、名字、目标和视觉风格。

最低展示线：

- 第一眼像现代工具；
- 可以新增/完成任务；
- 可以记录；
- 刷新后数据仍在；
- 首页有可见进度；
- 可以扫码。

## 5.3 Quick Win

- 自定义名称；
- 主题皮肤；
- 今日鼓励；
- 等级/能量；
- 完成动画；
- 成就徽章。

## 5.4 Builder

- 本周目标；
- 分类统计；
- 连续学习；
- 本周总结；
- 多种任务类型；
- 筛选。

## 5.5 Creator

把母版迁移成：

- 运动训练驾驶舱；
- 阅读管理台；
- 社团活动台；
- 校园环保任务台；
- 兴趣训练记录；
- 自己发现的校园小工具。

初中强学生进一步要求：

- 定义用户；
- 确定核心流程；
- 主动删掉一个没有价值的功能；
- 根据用户测试改版。

## 5.6 教师最重要的支架

避免学生不断说“再加一个功能”。

教师问：

1. 这个工具是谁用？
2. 他每天最常做的动作是什么？
3. 首页最重要的三个信息是什么？
4. 哪个功能可以删掉？

核心能力暗线：

> **产品目标 + 用户流程 + 功能取舍。**

# 6. 母版通过后的版本冻结要求

M3/M4/M5 真实测试通过后，每套正式建立独立目录，建议：

```text
mother-templates/
  M3-interactive-story/
  M4-interest-museum/
  M5-dashboard-tool/
```

每个目录以后至少包含：

- `BASE.md`
- `FALLBACK.md`
- `PROMPT_SKELETON.md`
- `THEME_OPTIONS.md`
- `FEATURE_OPTIONS.md`
- `WOW_OPTIONS.md`
- `RECOVERY.md`
- `CHALLENGE.md`
- `TEACHER_DEMO.md`
- `SHOWCASE_STANDARD.md`
- `KNOWN_FAILURES.md`

其中研发母版、失败库和完整稳定 Prompt 属于内部核心资产，不默认发给代理商完整版本。

---

# 7. 进入完整教案化的 Gate

一个母版只有同时满足以下条件，才允许大量课次依赖它：

1. 真实账号至少一次完整跑通；
2. 首版达到 DISPLAY-SAFE；
3. 至少两次逻辑/结构修改通过；
4. 不手写代码；
5. 出错可自然语言恢复或稳定回退；
6. 标准课时预算成立；
7. 有低能力 FALLBACK；
8. 有强学生 Challenge；
9. 有教师统一救援路径；
10. 家长/学校 10 秒内能看懂成果。

通过后才进入：

> **完整教师手册 + 学生任务卡 + 逐课教案 + 销售展示样例。**

当前最小动作不是继续写更多课，而是：

1. 按 `MOTHER_TEMPLATE_VALIDATION_PROTOCOL_V1.md` 跑 M3；

3. 跑 M5；
4. 把结果写成真实账号 Known-Good/Guardrail/Fail；
5. 只对通过的母版建立正式 `mother-templates/` 产品资产。

一句话：

> **先把少数母版做稳，再让整学期课程从这些稳定底座上长出来。**
