# Competitive Research & Benchmarks

核实日期：2026-08-31

本文件记录可用于 AI-Courses 产品设计的公开竞品、学校项目和课程案例。重点不是照抄课程，而是拆解其产品结构、交付逻辑、优势、局限和对我们的启发。

> 证据分级说明：
> - **官方采购/政府项目**：能证明采购方需求，但不能自动证明课程最终效果。
> - **政府/学校成果展示**：能证明真实展示过的学生成果，但不一定公开完整课程结构。
> - **商业机构官网**：能证明该机构当前如何设计和销售课程；招生量、效果等若仅为机构自述，不视为独立验证。
> - **高校课程**：用于教学理念和 AI 原生开发方式参考，不直接等同于中小学适龄产品。

---

## 1. 上海青浦区科技馆：2026“智驭计划”少年营

### 证据类型

**官方政府采购需求。**

来源：青浦区科技馆《2026年科技馆“智驭计划”少年营项目采购邀请书》

https://www.shqp.gov.cn/scien/ntzgg/20260508/1371061.html

### 已核实事实

- 面向六、七年级；
- 以 AIGC 工具为核心；
- “教学 + 实战 + 体验”；
- 不少于 30 课时；
- 不少于 50 名学生；
- 内容要求覆盖 AI 入门、视觉创作、文案、视频制作等；
- 每名学生结营需能独立完成至少 3 项创意作品；
- 要有个人作品集；
- 要组织成果汇报、作品展示、评优颁奖；
- 要提供图文、视频宣传素材；
- 优秀作品后续展示；
- 所有作品需进行线上宣传；
- 最终验收还包括名单、签到、教案、学生作品、活动素材、满意度调查、成果评价等完整项目资料。

### 最值得借鉴

#### A. 学校购买的不是“课时”，而是一整套成果系统

青浦采购需求最有价值的地方不是具体教 AI 图片还是视频，而是清楚说明了 B2B 教育采购真正关心：

> 课程 + 学生作品 + 作品集 + 成果展 + 宣传素材 + 评价 + 验收资料。

对我们意味着：正式学校产品不应只交教案。

#### B. 可展示成果必须提前进入产品架构

作品展示不是课程结束后临时补的活动，而应从第一天就决定学生每阶段留下什么成果。

### 不应照搬

- 公开采购需求中主要课程内容仍偏 AI 入门、视觉、文案、视频；
- 如果只沿这条路线，容易形成 AIGC 工具拼盘，互动产品和“会工作”的作品不足；
- 目前公开信息是采购需求，**不能写成已验证教学效果或成熟成功案例**。

### 对我们的价值

**借交付结构，不照搬内容结构。**

## 2. 北京市首届中小学人工智能嘉年华（2026）

### 证据类型

**北京市政府公开报道的真实学生成果展示。**

来源：北京市人民政府门户网站

https://www.beijing.gov.cn/fuwu/bmfw/sy/jrts/202608/t20260824_4834554.html

### 已核实事实

嘉年华汇聚近 40 所学校的学生科创作品，覆盖智能硬件、物联网、AI 应用、环保科创等。

报道中的例子包括：

- 密云区新农村小学“智能橱窗”：外部以瓦楞纸等材料制作，内部加入“智慧大脑”，能回答密云旅游相关问题；
- 小学的校园安全岛物联网智能防洪系统；
- 中学的 AI 智能老人陪诊系统；
- 3D 打印与智能制造相关项目。

### 最值得借鉴

#### A. “会工作”的作品比“生成了一张图”更有冲击力

一个外观甚至并不昂贵的纸盒，如果能被询问、能回答、能互动，展示价值就非常高。

这说明“酷炫”不必等于高技术复杂度或昂贵硬件。

#### B. AI 可以嵌进孩子熟悉的主题

旅游、校园、安全、老人服务、环保等，都比抽象讲“AI 能做什么”更容易让作品拥有意义和故事。

### 不应照搬

- 一些硬件/物联网作品可能需要较强教师支持、设备和项目周期；
- 我们不能为了展览效果把正式兴趣课变成高成本科创竞赛辅导。

### 对我们的价值

> **追求“简单制作 + 明显互动 + 真实功能”的能力反差，而不是追求技术堆叠。**

## 3. Mind Theory（新加坡）：AI Sprint / Vibe Coding

### 证据类型

**商业课程官网。** 可确认课程当前存在及其课程设计；招生火爆、效果等宣传性表述只能视为机构自述。

来源：

https://www.mindtheory.sg/ai-sprint-hackathon/

https://www.mindtheory.sg/ai-holiday-camp/

https://www.mindtheory.sg/what-is-vibe-coding/

### 已核实课程结构

AI Sprint 面向约 12–16 岁学生，5 天密集课程，无需编程基础。课程覆盖：

- AI Art；
- Roblox 游戏设计；
- Vibe Coding；
- AI 文本/声音/音乐；
- 视频编辑；
- Prompt Engineering。

其中 Vibe Coding 强调：学生用自然语言描述需求，AI 生成第一版代码，学生运行、观察、继续描述修改，直到形成简单游戏或 Web App。

机构还公开描述学校工作坊常见流程：

1. Prompt 框架；
2. 工具界面；
3. 教师现场演示示例 App；
4. 学生开始自己的项目；
5. 最后进行短时间 Showcase。

### 最值得借鉴

#### A. 第一时间给成果

每个 session 都强调学生带走一个实际项目，而不是前几节只学基础。

#### B. 用自然语言替代大量逐行编码

这与我们的“AI 原生创造”方向高度一致。

#### C. Showcase 是课程本体的一部分

作品被同伴看见能增强成就感和身份认同。

### 局限

- AI Art、Roblox、Vibe Coding、视频、Prompt 多方向并列，容易产生“工具拼盘”感；
- Roblox / VS Code / HTML/CSS/JS 对我们的学校兴趣课来说仍可能过度技术化；
- 海外工具和账号不一定适合中国学校环境。

### 对我们的价值

> **学习它“意图驱动 + AI 快速搭建 + 立即展示”的节奏，但进一步降低技术暴露，并让多个阶段成果长成同一个作品。**

## 4. Roboto Coding Academy（新加坡）：Junior / Young AI Creator

### 证据类型

**商业机构课程官网。**

来源：

7–8 岁 Junior AI Creator：
https://roboto.sg/holiday-camp-junior-creator

9–12 岁 Young AI Creator：
https://roboto.sg/holiday-camp-young-creator

### 已核实课程特点

7–8 岁版本把 Minecraft、Roblox、生成式 AI 故事和 AI 影片放在一个两天营中。

9–12 岁版本继续使用 Minecraft Education、Roblox Studio，并加入生成式 AI 的文章、图片、音乐、视频和动画创作。

### 最值得借鉴

#### A. 小学生的入口不是抽象概念，而是世界、角色、游戏、故事

儿童会因为“我要让这个角色动起来”“我要做一个自己的世界”产生学习需求，而不是因为“我要掌握条件判断”。

#### B. 多模态非常适合小学

绘画、声音、故事、角色和互动结合，比纯文字 Prompt 更适龄。

### 局限

- 仍明显以 Minecraft / Roblox / 编程知识为支柱；
- 7–8 岁版本仍列出 loops、events、conditionals、variables 等编程目标；
- 对我们而言容易再次滑回“有趣的编程课”，而非真正 AI 原生的低技术创造课。

### 对我们的价值

> **借儿童兴趣入口和多模态表达，不借传统编程主线。**

## 5. 新加坡 Copilot AI Game & Web Development Bootcamp（2026）

### 证据类型

**由公开项目官网披露的政府资助学生项目。**

来源：

https://copilotaibootcamp.tk.sg/

### 已核实事实

- 面向中学和 JC 学生；
- 使用 GitHub Copilot + Visual Studio Code；
- Game track 使用 Unity + C#；
- Web track 使用 HTML/CSS/JavaScript；
- 用生成式 AI 辅助游戏和 Web 开发；
- 项目展示包括 2D 平台游戏、文字冒险、3D 物理游戏、第一人称游戏等。

### 最值得借鉴

它证明一个重要趋势：

> AI 可以让学生更早进入“真正能运行的数字产品”阶段，而不是必须在长时间语法训练后才开始做作品。

### 为什么不适合我们直接照搬

Unity、C#、VS Code、HTML/CSS/JS 都会显著提高：

- 学生技术负担；
- 老师培训要求；
- 设备要求；
- Debug 风险；
- 学校现场交付难度。

### 对我们的价值

> **把它当“成果上限证明”，而不是“实施路径模板”。**

我们要继续向前一步：保留这种成果感，但通过 AI、模板、封装环境进一步降低技术门槛。

## 6. 香港中文大学（深圳）：Vibe Coding: Build Apps with AI

### 证据类型

**高校正式课程介绍。** 对象为大学生，不是中小学竞品。

来源：

https://www.cuhk.edu.cn/en/course/18757

### 已核实课程理念

2026–27 Term 1 的本科课程，明确面向几乎没有编程经验的新生，以项目驱动方式学习 AI 辅助软件创造。

课程不是从孤立语法开始，而是从真实 mini-projects 开始，例如：

- games；
- productivity tools；
- AI assistants；
- interactive web applications；
- automation tools；
- creative personal projects。

在做项目过程中逐渐形成编程基础、计算思维、Prompt workflow、debugging habits 和负责任使用 AI 的能力。

### 最值得借鉴

这个课程很清楚地证明一种教学结构：

> **先 Build，再在 Build 的过程中学。**

与我们“作品明线、能力暗线”高度一致。

### 局限

- 大学生认知能力和设备自主性远高于中小学生；
- 不能把高校 Vibe Coding 的技术环境直接下放到小学/初中。

### 对我们的价值

> 借教学顺序和认知逻辑，不借技术难度。

## 7. 西瓜创客：成熟传统少儿编程产品的反向参照

### 证据类型

**商业机构官方网站。**

来源：

课程体系：
https://www.xiguacity.cn/curriculum

图形化课程：
https://www.xiguacity.cn/scratch

Python 人工智能编程：
https://www.xiguacity.cn/python

学校合作：
https://www.xiguacity.cn/offline-coop

### 已核实产品特点

- 7–12 岁图形化创意编程；
- 9–15 岁 Python 人工智能编程；
- 11–17 岁 C++ 信奥；
- 强调 PBL 项目式学习；
- 图形化课程公开称一年有 70+ 软件作品和多类硬件项目；
- Python 课程公开称有 100+ 主题项目，包含天气助手、图像识别、语音合成、人脸识别等；
- 学校合作包含课程、教师培训、教学平台、赛事等。

### 最值得借鉴

#### A. 项目制已经被成熟市场长期验证为有效产品形态

孩子需要不断“做出来”，而不是只听知识。

#### B. 学校版不是单一老师上课，而是包含教师培训和交付体系

### 与我们的关键区别

西瓜的核心学习路径最终仍是：

> 图形化编程语法 → Python 语言/数据结构/设计模式 → C++/算法等。

也就是“通过项目学编程”。

我们的目标应该是：

> **通过 AI 直接创造作品，并在创造过程中形成 AI 协作、判断、拆解、表达等能力。**

编程不是必须达到的显性学习目标。

### 对我们的价值

> **保留成熟少儿科技课程的 PBL、作品、教师体系；拒绝传统语言学习成为主线。**

## 8. 国家中小学 AI 教育政策与使用边界

### 8.1 《“人工智能+教育”行动计划》（2026）

证据类型：**教育部等五部门正式文件。**

来源：

https://www.moe.gov.cn/srcsite/A16/s3342/202604/t20260410_1433240.html

与本项目直接相关的方向：

- 加快普及中小学生人工智能教育；
- 鼓励 AI 跨学科教学；
- 推动 AI 教育融入课后服务、研学实践；
- 激发好奇心；
- 培养创新思维；
- 提升认知思考与解决复杂问题能力。

这支持学校兴趣课、课后服务、跨学科 AI 创造类产品的方向。

### 8.2 《中小学生成式人工智能使用指南（2025年版）》

可核实公开全文/转发来源：

中国教育和科研计算机网：
https://www.cernet.edu.cn/zhong_guo_jiao_yu/shi_ye/news/202505/t20250513_2667992.shtml

深圳市教育局相关答复：
https://www.sz.gov.cn/hdjl/ywzsk/jyj/fwxx/jyxxh/content/post_12191805.html

### 关键年龄边界

公开指南明确强调分学段管理，尤其：

- 小学阶段不应让学生独自使用开放式内容生成功能，教师可在课内适当使用/组织；
- 初中阶段可以适度探索生成内容的逻辑性分析；
- 教师应承担监督与指导责任；
- 强调隐私、安全、版权、避免直接复制 AI 内容、避免过度依赖。

### 对我们的价值

这直接影响小学课程架构：

- 不应假设每个小学生独立注册并自由使用开放式聊天机器人；
- 更适合教师组织、学校可控账号、预设生成入口、模板化/封装工具；
- 小学低年级需要更谨慎，因此暂不优先做完整开放式 AI 学期课；
- 正式课程必须把安全、隐私、版权和验证作为暗线能力，而不是只追求生成速度。

# 9. 跨案例共性

把上述案例放在一起，可以观察到几个稳定方向：

## 9.1 作品驱动比知识驱动更适合兴趣课

成熟商业课、学校采购、成果展都把“学生做出什么”放在显著位置。

## 9.2 最有展示力的成果往往不是最复杂的技术

强作品的关键通常是：

- 能互动；
- 有明确功能；
- 学生有自己的主题；
- 观众可以马上试玩/提问/操作；
- 一眼能看懂学生完成了什么。

## 9.3 AI 正在压缩“从想法到产品”的距离

Vibe Coding、AI 辅助创作等案例说明，零基础学习者可以比过去更早看到可运行成果。

## 9.4 现有很多产品仍没有完全脱离传统编程逻辑

Roblox、Scratch、Python、Unity、VS Code 仍占大量比重。

这正是我们的机会：

> **做真正 AI 原生的儿童创造课程，而不是在传统编程课上再加一层 AI。**

## 9.5 学校采购需要成果运营体系

Demo Day、作品集、宣传素材、教师培训、项目验收和家长可见成果，是 B2B 产品的一部分。

# 10. 当前竞品研究结论

目前最值得组合借鉴的不是某一个竞品，而是：

- **青浦**：学校采购交付和验收逻辑；
- **北京成果展**：简单材料也能做“会工作的 AI 作品”；
- **Mind Theory**：即时成果、自然语言驱动、Showcase；
- **Roboto**：儿童的世界/角色/游戏入口和多模态；
- **Copilot Bootcamp**：AI 把真正数字产品的进入时间提前；
- **港中深 Vibe Coding**：先 Build、能力随项目产生；
- **西瓜创客**：成熟 PBL、作品和教师交付体系，同时作为我们避免滑回传统编程课的反向参照。

我们的目标不是复制其中任何一个，而是形成：

> **更低技术门槛 + 更强 AI 杠杆 + 更完整互动作品 + 更适合学校交付 + 更明确能力暗线** 的组合。
