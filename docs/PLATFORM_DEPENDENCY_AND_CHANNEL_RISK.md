# 底层平台依赖与渠道冲突策略

更新时间：2026-08-31
状态：PRODUCT / CHANNEL STRATEGY

## 1. 为什么工具选型不能只看“课堂好不好用”

AI-Courses 的商业结构是：

> 我们（课程研发方） → 代理商/教师 → 学校 → 学生

因此底层工具除了满足课堂体验，还必须评估一个额外问题：

> **这个平台供应商是否也在直接向学校销售“平台 + 课程 + 师训 + 到校服务”的完整方案？**

如果答案是是，那么即使工具很好，也可能形成渠道冲突：

- 学校可能绕过我们直接采购平台方完整方案；
- 代理商可能认为直接代理平台方更省事；
- 我们的课程和教师体系被底层平台品牌吞没；
- 平台方掌握学生/学校数据和使用关系；
- 平台涨价、改变授权或停止开放后，我们被锁死。

因此需要把工具分为三类。

---

# 2. 三类底层平台

## A 类 — 中性基础设施 / 公益或公共型创作环境

特征：
- 主要提供工具或生态基础设施；
- 不以复制我们的“课程研发 + 代理 + 师训”商业模式为主要业务；
- 更适合作为我们可替换的底层创作引擎。

当前典型候选：

### 微信小程序教育平台

优势：
- 专门为学校和学生设计；
- 基础教学能力公开称免费；
- 学生作品是真小程序；
- 有学校/教师/学生结构；
- 腾讯有课程资源和赛事，但平台更接近公共教育生态基础设施，而不是单一代理型课程公司。

风险：
- 腾讯仍然拥有规则和平台控制权；
- AI助手模型和功能不可由我们控制；
- 若我们课程最终只是“教微信小程序教育平台官方课程”，就没有自身壁垒。

正确用法：

> **把微信平台当作画布/开发环境，而不是把腾讯官方课程当作我们的课程。**

我们的价值必须仍然来自：
- Wow 项目设计；
- 年龄分层；
- 稳定创作底座；
- 教师教学脚本；
- AI能力暗线；
- 学生作品集；
- 学校成果；
- 持续工具升级。

---

## B 类 — 通用 AI 创作工具

典型：
- 秒哒；
- 扣子编程；
- WorkBuddy；
- TraeWork；
- 腾讯元器。

优势：
- AI生成能力强；
- 不以K12课程销售为主营；
- 我们可以把它们当作“创作引擎”；
- 平台之间相互可替换，降低锁定风险。

不足：
- 未成年人、学校账号、课堂管理通常不是产品第一设计目标；
- 可能需要我们额外建设 Teacher Portal 和账号组织层。

战略价值：

> **这类工具最适合形成“课程由我们定义、工具只是发动机”的结构。**

---

## C 类 — 完整 AI 教育解决方案商 / 潜在竞合方

典型包括：
- CocoRobo / CocoFlow / CocoClass；
- 科大讯飞 AI 创新教育；
- 腾讯扣叮完整青少年 AI 教育方案；
- 有为 AI 教育；
- 神码童学等。

这些平台通常同时销售：
- 平台；
- 课程；
- 师训；
- 学校实施；
- 硬件；
- 比赛/成果出口。

它们非常值得做竞品研究，因为已经解决了大量真实进校问题；但如果直接作为我们的完整底层平台，需要额外审查渠道冲突。

---

# 3. CocoRobo 为什么特别值得研究，但暂不直接选作核心底座

CocoRobo 2026 SMART 产品公开信息与本项目方向高度重合：

- 学校 AI 原生学习环境；
- CocoFlow 支持 Agent / Workflow / H5；
- 无代码，教师可用自然语言生成互动 H5；
- 初中信息科技案例明确出现“学生用自然语言生成自己的互动小工具”；
- 可将 H5/Agent 嵌入课堂；
- 学生 PIN 码参与、学情反馈、班级资源沉淀；
- 官方披露服务学校数量达到 1,000+ 量级（不同站点/口径存在 700+、1,400+ 等不同时间/地区口径，应按发布时间理解，不做简单相加）；
- 提供固定年度学校授权和课程/师训/到校服务。

来源：
- https://cocorobo.cn/smart
- https://cocorobo.com/
- https://cocorobo.cn/research/

### 对我们的价值

CocoRobo 证明了一件重要事实：

> **“学校原生 + 自然语言创作 H5/AI应用 + 普通教师可用”这条路线不是概念，已经存在真实产品。**

特别值得借鉴：
- 教师无需写代码；
- AI生成互动H5；
- H5直接嵌入课堂；
- 学生用PIN进入；
- 学生作品沉淀；
- 课堂数据回流；
- 教师培训与校本资源共建。

### 为什么暂不作为核心依赖

CocoRobo 自己就是：

> 平台 + 课程 + 师训 + 到校服务 + 学校客户

的完整供应商。

这与我们的商业层级高度重叠。

如果我们把课程深度绑定到其完整套件：

- 代理商有可能直接向 CocoRobo 采购；
- 学校会问为什么不直接买原厂方案；
- 我们的课程品牌可能变成“CocoRobo培训课”；
- 定价和授权权力不在我们手里。

因此当前定位：

> **P0 PRODUCT BENCHMARK / P1 PLATFORM PARTNERSHIP CANDIDATE / NOT DEFAULT CORE DEPENDENCY**

除非未来获得明确的渠道合作、白标/OEM、API或教育合作条款，使我们的代理体系不会被绕开。

# 4. 我们选底层工具的商业评分维度

除了课堂15项评分，再增加5个商业维度：

1. **渠道冲突**：供应商是否直接卖同类课程给学校；
2. **品牌可控**：学生/学校最终认知是我们的课程，还是平台课程；
3. **可替换性**：换平台后核心课程是否还能继续；
4. **数据控制**：学生作品、班级记录、教师认证是否能沉淀在我们体系；
5. **授权稳定性**：平台是否允许代理商/商业课程规模化使用，价格是否可预测。

### 推荐权重

在正式商业产品中：

- 课堂体验：50%；
- 学校合规与管理：20%；
- 渠道/商业可控：20%；
- 单纯模型生成能力：10%。

因为模型能力变化最快，也最容易被替换；渠道、学校关系和课程体系才是长期资产。

---

# 5. 当前推荐架构

短中期最健康的结构仍然是：

```text
AI-Courses Teacher Portal / 授权与课程层
        │
        ├── 课程版本 / 教师脚本 / Prompt / 稳定底座
        ├── 教师认证 / 班级激活
        ├── 学生任务 / 作品提交 / Portfolio
        ├── Demo Day / 学校成果报告
        │
        └── 可替换创作引擎
             ├── 微信小程序教育平台
             ├── 秒哒
             ├── 扣子编程
             └── 未来更好的工具
```

关键原则：

> **学生可以使用外部AI平台，但学生、教师、学校和代理商关系不能只存在外部平台里。**

否则课程一旦形成规模，我们真正最有价值的资产仍掌握在第三方手里。

---

# 6. 当前决策

1. 微信小程序教育平台：继续 P0 hands-on，优先作为小学学校原生创作环境验证；
2. 秒哒：继续 P0 hands-on，优先验证最纯粹的AI原生 Wow 体验；
3. 扣子编程：继续作为初中 P0；
4. CocoRobo：升级为重要 P0 产品标杆，但暂不作为默认底层依赖；
5. 讯飞/腾讯扣叮完整方案等：重点学习其学校交付、平台、师训和成果体系；
6. 长期避免课程绑定单一厂商，Teacher Portal/作品/教师认证应由我们控制。
