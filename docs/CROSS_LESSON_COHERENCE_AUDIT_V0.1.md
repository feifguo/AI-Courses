# AI-Courses 跨课一致性审核 V0.1

更新时间：2026-09-01
状态：ACTIVE CURRICULUM AUDIT
范围：小学高年级 / 初中当前已写逐课 V0.1 + 16课时 V0.2 结构

## 1. 审核目标

单节课“能上”不等于一学期“好上”。

本审核专门检查：

- 相邻课是否重复；
- 学生会不会觉得每周都在做同一件事；
- 成果 Wow 是否有节奏；
- 能力是否真正递进；
- 标准课时是否过满；
- 最终项目是否重复定义；
- 教师支架是否重复但必要；
- 家长/学校是否能持续看到新成果。

## 2. 总体结论

当前整体方向正确，尤其：

- 每课有展示成果；
- BASE/FALLBACK/Challenge结构一致；
- 小学与初中难度差异主要在判断与产品决策，而非代码；
- 最终发布/展示链完整；
- 反复坚持“试玩→判断→修改→验证”是必要习惯，不属于无效重复。

但当前存在四个需要修正的结构风险。

---

# 3. 风险一：表面产品重复会掩盖能力递进

## 问题

核心认知循环本来就需要反复练习：

> 生成 → 试玩 → 修改 → 验证

这是“有意重复”。

但如果同时连着几节课都使用同一种表面产品，学生会主观感受到：

> “怎么又是在改上周那个东西？”

兴趣课产品需要同时满足：

- 内部能力重复练；
- 外部成果不断换新。

## 新原则：两课一个明显成果节点

建议形成：

> **1课快速成品 + 1课深度升级 = 一个作品 Pair。**

每2课至少形成一个可以重新截图/扫码展示的明显里程碑。

每4课至少出现一次“作品类型跃迁”。

# 4. 小学审计

## L1–L2：游戏 Pair

状态：GOOD。

- L1：第一次做出来；
- L2：规则设计。

虽然使用同一个作品，但第二课玩法差异足够明显。

保留。

## L3–L4：互动故事 Pair

结构上 GOOD，等待 M3 实测。

- L3：分支故事；
- L4：状态/任务/收藏。

如果 M3 Strong Pass，可直接形成第二个视觉和交互类型明显不同的作品。

## L5–L6：兴趣馆 Pair

设计目标 GOOD，但当前有一个暂时性风险。

### 风险

在 M4 尚未通过时，L6 使用 M2 独立做“知识闯关”，紧接 L7 又做 M2 学习 App，会出现：

> L6 = 知识答题产品  
> L7 = 学习+答题产品

表面体验过近。

### 决策

`L06_KNOWLEDGE_CHALLENGE_V0.1.md` 当前只作为：

> **BACKUP / CONDITIONAL PATH**

正式16课时默认不应在没有 M4 的情况下连续使用 M2 做 L6 + L7。

理想正式路径：

- L5：M4 兴趣馆；
- L6：在同一个兴趣馆中加入闯关、进度和奖励；
- L7：切换到完全不同的“学习 App 产品”。

这样外部成果分别是：

> 数字博物馆 → 会玩的博物馆 → 真正学习平台

差异足够大。

## L7–L8：学习 App Pair

状态：GOOD。

- L7：完整产品；
- L8：反馈/奖励逻辑。

能力从“做软件”升级到“设计别人怎么学”。

## L9–L10：校园工具 Pair

结构上 GOOD，等待 M5。

应明确：

- L9：做出有用工具；
- L10：增加状态/记录/产品感。

M5 若不能 Strong Pass，应重构，不用 M2 硬替代两节。

## L11：用户测试

状态：GOOD。

与 L15 发布验收不重复：

- L11 = 外部用户怎么用、要不要采纳反馈；
- L15 = 发布前功能完整性与稳定性。

教师培训必须明确二者区别。

## L12：可信内容

能力价值高，但 Wow 风险偏高。

### 风险

如果只是“查3条事实”，家长/学生会觉得产品变化不明显。

### 强制展示化

正式版必须加入至少一个明显可见升级：

- “已核查”徽章；
- 可信信息卡；
- 来源页；
- 纠错前后对比；
- 内容视觉重构。

本节不能只完成后台认知动作。

## L13–L16：最终项目四课

状态：GOOD。

四课职责需固定：

- L13 = 先拿 V1；
- L14 = 做成自己的 V2；
- L15 = 停止扩张、测试和锁版；
- L16 = 发布/嘉年华。

禁止 L13 长策划、L15 继续疯狂开发。

# 5. 初中审计

## L1–L4：当前最大节奏风险

能力递进合理：

- L1：做出来；
- L2：需求；
- L3：规则；
- L4：版本。

但如果四节都在持续修改同一个第一课作品，兴趣体验可能下降。

### 修正建议：2+2 Pair

#### Pair A — L1/L2

同一个产品：
- L1：第一版；
- L2：从模糊想法变产品要求。

#### Pair B — L3/L4

建议换一个新的“规则实验产品”或新主题版本：
- L3：快速拿到新 BASE，再专门设计相互关联规则；
- L4：用 L3 产品练 V1/V2 与回退。

这样：

> 能力连续，但作品表面刷新。

不要求从头耗费大量时间，新产品仍来自稳定 M1 母版。

## L5–L6：M5 Pair

等待 M5。

理想：
- L5：多页面工具；
- L6：让工具记住用户/数据。

这一 Pair 会带来一次非常强的“我做了真正工具”能力跃迁。

## L7 与 L8

两节容易被误以为重复，但实际目标不同，应该保留并强化区分：

### L7 — 自己看产品

> UX / 自我启发式检查：第一次打开、按钮、流程、反馈、返回。

### L8 — 别人看产品

> 真人用户测试：作者少解释、收反馈、采纳/拒绝、回测。

教师手册要把这句话写在标题下。

## L9 与 L11

同样看似都是“AI给意见”，但应明确角色差异：

### L9 — AI评审

关注：
- 质量；
- 清晰；
- Bug；
- 多余功能；
- 优先级。

### L11 — AI反方

关注：
- 产品假设；
- 为什么可能没人需要；
- 为什么可能太复杂；
- 不同用户冲突；
- 是否需要删减/重构。

L10事实核查夹在两者之间，正好避免连续两课都是“AI给意见”。

## L12 与 L13：存在真实重复

当前两节都是：

> 定义用户/问题 → 做 V1

连续出现会显得重复。

### 建议重构

#### L12 — Real Problem Sprint / 真实问题极速赛

定位为低风险练习赛，不是最终项目。

特点：
- 使用教师预设/校园问题池；
- 小组完成；
- 快速缩问题；
- 30分钟做一个最小 V1；
- 最后比较哪一组“问题小但产品最完整”。

核心能力：
> 真实问题不是越大越好。

#### L13 — Final Product Launch

才正式进入个人/小组最终项目：
- 学生自行选方向；
- 用一学期经验决定用户/目标/3功能；
- 当堂形成最终项目 V1。

这样 L12 是一次“模拟赛/训练”，L13 是正式启动，角色不同。

## L14–L16

状态：GOOD。

- L14：V2 + 取舍；
- L15：Release QA；
- L16：Demo Day。

# 6. 时间审计

当前大部分完整教案 BASE DEADLINE：

- 小学约 28–29 分钟；
- 初中约 32–35 分钟。

总体符合政策。

但需要内部走课特别关注：

### 小学风险

L7 学习平台首版虽然工具本身分钟级生成，但学生选择主题、试玩、内容修改可能占时。

若真实内部走课中 BASE >30分钟：
- 减少首版要求；
- 把4个分类预置；
- 内容先由模板生成；
- 学生重点只改一个主题。

### 初中风险

L2/L9/L11 认知讨论容易讲长。

教师必须执行：

> **讲解不超过5分钟，能力训练必须发生在作品修改里。**

否则会重新变成“AI素养讲座”。

# 9. 当前判断

当前课程不是需要推倒重来。

真正需要的是：

> **保持同一认知循环反复练习，但不断刷新作品表面、项目角色和能力任务。**

也就是：

> **方法可以重复，体验不能重复；能力要累积，成果要不断换新。**

这会同时提高：
- 学生兴趣；
- 学校展示价值；
- 家长持续感知；
- 教师授课节奏；
- 能力迁移。
