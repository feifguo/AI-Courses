# AI-Courses 统一起点与逐级开放规则 V0.1

更新时间：2026-09-25  
状态：V0.4 CANDIDATE POLICY / INTERNAL

## 1. 为什么增加这条规则

AI 可以让学生很快生成不同类型的产品，但如果一节标准课从一开始就允许全班自由选择完全不同的产品架构，课堂会迅速出现：

- 不同学生的功能难度差异过大；
- 老师无法用同一套演示和恢复方法带全班；
- 常见问题无法统一处理；
- 一部分学生十几分钟就完成，另一部分学生一直陷在未知技术问题；
- 教师被迫逐个救火；
- 40 / 45 分钟的完成率变得不可预测。

因此，课程正式采用：

> **先同构，后分化；先完成，后创造。**

这不是减少创造力，而是把创造力放到学生已经拥有稳定作品以后。

---

## 2. 标准课的三层自由度

### 第一层：统一起点

标准课堂前半段，全班使用：

- 同一个母版；或
- 同一个经过验证的产品架构；或
- 极少数课程方明确验证过、教师可以统一管理的固定轨道。

这一阶段不允许学生自行发明新的产品架构。

### 第二层：有边界的个性化

学生达到稳定版本后，可以在课程方菜单中选择：

- 主题；
- 内容；
- 视觉；
- 文案；
- 一条已验证规则；
- 一个低风险展示效果；
- 一项本课允许的关键功能变化。

此时不同学生作品应该“明显属于自己”，但教师仍然能够用统一方法带课。

### 第三层：开放创造

只有已经达到本节稳定完成线的学生才进入。

可以：

- 自己提出一个新功能；
- 改变一个用户流程；
- 做第二种方案；
- 在 Final 阶段更大幅度个性化。

原则仍然是：

> **一次只承担一个新的高风险变化。**

开放创造不能成为基础完成条件。

---

## 3. 小学与初中的开放程度不同

### 小学高年级

标准课更严格：

- 新产品课默认全班同一产品骨架；
- 差异主要来自主题、内容、视觉、规则菜单和低风险 Wow；
- 直到 Final 阶段才明显扩大产品方向选择；
- Final 仍从成熟母版轨道开始，不从完全空白架构起步。

### 初中

可以更早增加产品判断与取舍，但仍遵守：

- 第一节统一产品骨架；
- Rule Lab 使用课程方预验证组合；
- 工具课统一 M5 架构；
- Real Problem Sprint 的问题必须绑定成熟产品轨道；
- Final 先选择成熟轨道形成稳定 V1，再开放更大幅度原创。

---

## 4. 对教师的直接要求

老师不需要同时管理十几种不同软件。

标准课开始时老师必须能回答：

1. 今天全班共同从什么起点开始？
2. 哪些东西所有学生都一样？
3. 哪些东西学生可以自己选？
4. 做到什么以后才可以自由扩展？
5. 学生偏离标准轨道以后，什么时候必须拉回？

如果这五个问题无法清楚回答，该课不能进入正式学校交付。

## 5. 当前关键课次的 V0.4 约束

### 小学 L1

保持 M1 统一记忆翻牌骨架。

学生自由发生在：

- 主题；
- 图案；
- 视觉；
- 一个已验证规则 / Wow。

### 小学 L3

M3 通过后，全班从同一个互动冒险骨架开始。

### 小学 L5

M4 通过后，全班从同一个数字博物馆骨架开始。

### 小学 L9

M5 通过后，全班从同一个“学习驾驶舱 / 校园个人工作台”骨架开始。

不再允许一开始任选“校园工具 / 学习工具 / 记录工具”等完全不同架构。

### 小学 L13

学生从 M1 / M2 / 后续通过验证的 M3 / M4 / M5 成熟轨道中选一个。

先形成稳定 V1，再扩大原创；不从完全空白架构起步。

### 初中 L1

全班统一 M1 第一数字产品。

M2 可以作为教师展示“后续还能做到什么”，但不在第一课形成两条学生架构。

### 初中 L3

继续使用课程方验证过的 Rule Lab 组合。

### 初中 L5

M5 通过后，全班统一使用 M5 工具架构。

差异主要发生在内容、目标、数据字段、视觉和经过验证的功能菜单。

### 初中 L12

教师问题池中的每个问题必须事先绑定成熟产品轨道。

学生选择的是“问题”，不是在课堂里临时选择未知技术架构。

M5 未通过前只开放 M1 / M2 可稳定承载的问题。

### 初中 L13

学生先选择成熟母版轨道形成 Final V1。

高能力学生也不以“完全从空白建立新架构”作为标准课堂起点。

达到稳定 V1 后才进入更开放原创。

---

## 6. 课程研发验收

任何新建产品课必须同时通过：

- 统一起点是否清楚；
- 基础学生是否能在标准课时完成；
- 教师是否有统一恢复方法；
- 个性化是否足够明显；
- 快学生是否有开放空间；
- 自由度是否不会破坏全班进度；
- 未验证的新架构是否被挡在基础路径之外。

一句话：

> **课堂先共享结构，作品再逐渐长成每个人自己的样子。**
