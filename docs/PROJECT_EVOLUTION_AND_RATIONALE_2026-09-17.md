# 1. 项目最早的起点：AI 使用能力 / 暑期营，而不是现在的 AI 原生创造课

## 1.1 2026-06：最初问题

最早目标是：

- 给中小学生设计 AI 课程；
- 教孩子把 AI 用到学习、任务和日常问题中；
- 每节课要有可见产出，而不是只讲概念；
- 家长能看到孩子“真的学会了什么”。

早期课程形态讨论过：

- 12–16课的长期课程；
- 线上每课约25–35分钟 + 课后任务；
- 14–21天集中完成；
- 暑假集中营。

2026-06-21 团队讨论后形成过一个产品矩阵：

- **3天体验营**：引流/快速验证；
- **5天标准暑期营**：主暑期产品；
- **14课长期版**：学校、长期班、线上课。

当时的重要判断是：

> AI 大幅降低了课程设计、内容生产和试错成本，与其长期猜测哪一种形式最好，不如快速做出多种版本测试。

“领养 AI”等早期包装属于这一阶段。它解决的是产品形态和招生/营地体验问题，还不是后来完整的 AI-native 创造课程体系。

# 2. 2026-07：10节 AI 使用能力录播课阶段

## 2.1 当时的定位

7月的版本更明确地走向：

> **轻量、可录播、孩子能马上在学习中使用的 AI 使用能力课程。**

当时特别关注：

- 怎样清楚向 AI 提问；
- 怎样定义想要的输出；
- 怎样减少 AI 幻觉/错误；
- 怎样把 AI 用到数学错题、英语、作文、阅读、计划等学习场景；
- 不背 Prompt 模板，而学习可迁移的方法。

市场课程研究带来的主要启发包括：

- 少讲抽象原理，多做真实场景；
- 尽快给结果；
- 每10分钟左右最好出现一次动作/产出；
- 不把课做成 Prompt 术语课；
- 工具可以以豆包等易用产品为主，但方法不能绑死在一个工具。

当时形成过“AI沟通五步法”等方法化表达，并逐渐区分：

- **AI学习助手**；
- **AI思维伙伴 / 共同创造者**。

用户明确决定：

> **先做10节课的大纲和教师教案，再做宣传页面。**

原因是课程首先要交给老师录课/交付，不能先做营销包装再倒推内容。

10节课的基本节奏是：

> **讲一点 → AI演示 → 学生实操 → 小任务/成果。**

## 2.2 这一阶段后来为什么不再作为学校兴趣课主线

这套课没有被否定。

保留下来的部分包括：

- 提问；
- 表达要求；
- 搜索和整理；
- 判断和验证；
- 反思；
- 学习场景应用。

但后来发现，如果把它直接作为学校兴趣课的显性主线，很容易变成：

> “AI 有什么用” → “今天学一个功能” → “明天换一个场景”。

它的教育价值存在，但**作品感、持续吸引力、学校展示价值和学生所有权不够强**。

因此这些能力后来没有丢掉，而是转为“暗线”，嵌入真实作品创造之中。

# 3. 核心范式转变：从“AI有什么用”到“孩子能创造什么”

项目后来形成的最重要战略转折：

> **不要从“AI有什么用”设计兴趣课，而要从“孩子能创造什么让人眼前一亮的东西”倒推课程。**

由此确立：

> **作品是明线，AI能力是暗线。**

以及：

> **从“问AI”到“用AI创造”。**

课程不再首先问：

- 今天教哪个AI功能？
- 今天学哪个Prompt技巧？

而是先问：

- 今天孩子能做出什么真的能玩、能用、能分享的东西？
- AI怎样让这个年龄的孩子获得过去不属于他的创造能力？
- 在做作品的过程中，自然需要哪些表达、判断、验证、迭代能力？

## 3.1 硬约束：不是“更容易的编程课”

后来多次确认：

- 不以 Scratch / Python / HTML / JS 语法为主线；
- 不要求学生大量手写代码；
- 不要求教师是程序员；
- 不把环境配置、语法错误、传统 Debug 当作学习成本；
- AI应承担大量底层技术实现。

内部目标：

> **技术难度 2/10，作品观感 8/10。**

课程认知循环逐渐稳定为：

> **想象 → 描述 → 判断 → 修改 → 测试 → 完成。**

更完整的产品循环为：

> **我想做什么 → 告诉AI → 第一版 → 玩/用 → 哪里不满意就告诉AI改 → 加自己的内容和规则 → 完成。**

# 4. 工具路线的演化：从泛工具比较到教育原生平台

## 4.1 早期工具候选

项目曾广泛考虑：

- 豆包等通用 AI；
- 秒哒；
- 扣子；
- WorkBuddy / CodeBuddy；
- 其他 Vibe Coding / Builder。

这些工具可能有很强的生成能力，但进入中小学正式课堂时出现一组不同于“个人使用”的问题：

- 未成年人账号；
- 学校/教师/学生组织；
- 课堂统一登录；
- 作品管理；
- 分享；
- 设备和网络；
- 教师救援；
- 商业课程方服务多所学校的权限边界。

于是选型标准发生变化：

> **最强的消费级生成工具，不等于最适合正式进校课堂的工具。**

## 4.2 教育原生层 + AI创作能力

项目曾提出两层结构：

1. **教育原生层**：学校/老师/学生/作品/任务/未成年人边界；
2. **AI创作引擎层**：负责更强的应用、游戏、智能体或视觉生成。

如果一个教育原生平台本身已经足以承担 AI-native 创作，则优先单平台，避免学生跨平台和教师救援复杂度。

## 4.3 微信小程序教育平台成为第一候选

公开研究显示微信小程序教育平台：

- 专门面向中小学；
- 有真实学校规模应用；
- 有教师/学生组织结构；
- 浏览器端可用；
- 有 AI 自然语言辅助；
- 能做真正可运行、可发布的小程序；
- 对中国家长和校方有“这是真软件”的认知优势。

因此暂停泛化横评，先把这一路线跑透。

> **已真实复现出适合五年级学生尝试的技术能力路径；真实儿童课堂表现仍需后续课堂数据。**

# 6. 课程设计第二次重大转折：Outcome First

随着真实平台能力变强，项目遇到另一个风险：

> 如果为了“学生完全独立”，导致弱学生一节课卡住、最后没有漂亮成果，那么教育理念正确但产品失败。

因此正式确立：

> **先保证绝大多数学生都有“第一眼很厉害”的可展示成果，再在这个成果之上拉开能力成长和原创深度。**

## 6.1 三层学生路径

### DISPLAY-SAFE BASE

- 稳定骨架；
- 主题/规则选项；
- 半成品/母版；
- 统一恢复；
- 最终成品即使走兜底也必须好看、能用、能展示。

### GUIDED CREATOR

- 学生自己描述功能；
- 修改真实规则；
- 批评AI第一版；
- 接受同伴/用户反馈；
- 做至少一次真实迭代。

### OPEN CREATOR

- 自己定义功能；
- 拆解需求；
- 加页面/模式/状态；
- 形成更强原创度。

核心：

> **保底作品必须已经很厉害；能力强的学生再把它变成真正属于自己的、更厉害的作品。**

兜底优先级：

> **课程系统兜底 > 模板兜底 > 全班统一救援 > 小组救援 > 个别教师代操作。**

# 7. 标准课时与内部走课：AI生成快，不等于课堂就该塞满

中国学校标准基线最终确认：

- 小学：40分钟；
- 初中：45分钟。

课程不是按满40/45分钟才做完，而是：

- 小学 BASE 约25–30分钟；
- 初中 BASE 约30–35分钟；
- 剩余时间用于试玩、判断、修复、反馈、收口；
- 60/90分钟只用于 Challenge / Open Creation。

原则：

> **保底核心成品完成时间 < 标准课时。**

内部走课设计审计进一步发现：

> **AI生成速度不是课堂总耗时。真正不确定的时间发生在试玩、触发、发现冲突、修复、再验证。**

因此形成：

> **BASE Complexity Budget = 1个主要复杂修改 + 1个低风险可见增强。**

这直接导致多节课削减 BASE 复杂度，把第二个复杂功能放入 Guided / Challenge。

- `docs/INTERNAL_WALKTHROUGH_AUDIT_V0.1.md`
- `docs/STANDARD_PERIOD_AND_EXTENSION_POLICY.md`
- `docs/CHALLENGE_POOL_SYSTEM_V1.md`

当前正式开发两条：

- 小学高年级；

1. L1/L2 游戏；

- L12 的可信内容必须让作品发生可见变化；

## 8.2 初中 V0.3

Pair 结构：

1. L1/L2 第一数字产品；
2. L3/L4 Rule Lab；
3. L5/L6 真正工具；
4. L7/L8 UX → 真人用户测试；

# 10. 2026-09：Demo 概念进一步拆成两个完全不同的产品

最近讨论中先提出两个场景：

1. **现场去学校上 Demo**；
2. **录制 Demo**。

随后不断澄清，最终必须明确：

## 10.1 校长现场 Demo 课

这是**真实给学生上课，同时给校长看结果**。

销售证据来自：

- 学生在现场真的做；
- 大部分学生都成功；
- 作品有明显差异；
- 作品可试玩/可扫码；
- 校长看到这是可交付的正式课程，而不是老师魔术秀。

## 10.2 校长销售演示视频

这**不是“录一堂课”**。

它的本质是：

> **一份会动的校长销售PPT + 少量真实作品录屏。**

它面向采购决策者，目的不是证明课堂镜头真实，而是快速回答：

1. 孩子最后能做出什么？
2. 为什么这不是“一句话生成”的工具课？
3. 课程真正训练什么未来能力？
4. 一学期能形成什么成长与学校成果？

这两个 Demo 必须分开维护，不能再混为一谈。

# 11. 销售视频讨论的完整演化与被否定的方向

这一段专门保留最近讨论过程，避免新工具只看到最终脚本，不知道为什么这样设计。

## 11.1 第一版想法：拍/录 Demo 课

最初容易自然理解成：

> 拍教师怎么上、学生怎么操作、怎么完成作品。

后来用户明确否定：视频不是课堂实录。

原因：校长并不需要通过长课堂录像判断购买。

---

## 11.2 第二版想法：重点展示“孩子一句话也能做出来”

这个方向也被用户明确否定。

问题是：

> 如果展示“输入几个词 → AI一分钟生成漂亮App”，校长可能把成果归因给平台，而不是课程。

原本校长可能认为：

> “你们这门课能教小朋友做出这么专业的东西，很厉害。”

过度展示底层生成机制后，会变成：

> “原来是工具厉害，课程没什么含金量。”

因此形成重要销售原则：

> **要让校长理解孩子为什么能做到，但不能把它展示成‘原来这么容易做到’。**

---

## 11.3 第三版澄清：真实录制只负责“成果证据”

最终用户明确：

> **所有真正录制的内容，本质上都只需要是成果展示。**

包括 Debug，也不需要录学生真实输入和完整操作。

Debug 应由视频解释：

> AI第一版不一定正确 → 孩子要发现“预期 ≠ 实际” → 描述问题 → 修正 → 再验证。

画面只需要：

- 错误结果；
- 修复后的结果。

因此最终原则：

> **录制结果，讲解过程，抽象方法，保护配方。**

不展示：

- 完整母 Prompt；
- 第一版生成配方；
- Recovery Prompt；
- 完整AI操作；
- “一句话一分钟做App”全过程；
- 代码。

---

## 11.4 第四版修正：销售视频的主视觉不应只是游戏

用户提醒：如果目标是校长采购，真正更有冲击力的是：

> **孩子做出像真正软件一样的实用学习工具 / 数字产品。**

因此销售视频里：

- M1 游戏可以出现，证明起点好玩、即时；
- 但不应成为整支视频的 C 位；
- M2 学习平台，以及未来 M4/M5 的知识产品、校园工具、学习驾驶舱，应成为建立含金量的主要成果形态。

销售视频应传递：

> **不是“孩子会做AI小游戏”，而是“孩子可以逐步进入真实数字产品创造”。**

---

## 11.5 第五版修正：专业术语可以用，但不能过量

最初担心术语太多，倾向全部口语化。

用户指出：这不是大众短视频，校长不需要把每一个概念完全学懂。

适度专业词反而产生重要反差：

> **这些原本是专业产品/软件开发中的工作方式，而我们能把它教给小学生和初中生。**

但随后又进一步收敛：不能堆十几个术语，否则短视频发散、假、像论坛演讲。

最终第一版只保留少量专业概念：

1. **需求定义**；
2. **系统逻辑**；
3. **测试与调试**；
4. **AI能力边界 / 人的判断**。

表达格式：

> **一个中文专业词 + 一句直观解释 + 一句传统开发中谁在做/为什么专业。**

例如：

> **需求定义**：先判断用户是谁、真正的问题是什么、最重要的功能是什么。传统产品开发中，这通常是产品经理首先要解决的问题。

目标是让校长：

> **大概听懂，但明显知道这是专业工作。**

不是故意让人听不懂。

---

## 11.6 第六版修正：未来能力要有权威来源，但不能延展成理论课

讨论过世界经济论坛、联合国教科文组织以及 OECD 等框架。

用户最终要求：

> **不要在这个角度延伸太多；我们只是一个简短宣传短视频，东西太多会散、会假、不聚焦。**

因此当前销售视频只保留很短的权威背书：

### 世界经济论坛《未来就业报告2025》

用于说明未来重要能力中包括：

- 分析性思维；
- 创造性思维；
- 技术素养；
- 系统思维。

### 联合国教科文组织学生AI能力框架

用于说明学生AI教育不能只停留在“会用工具”，还包括：

- 问题界定；
- 系统设计；
- 测试与优化；
- 从理解/应用走向创造。

当前**不在短视频里展开OECD、学生能动性、复杂能力模型等更大的理论体系**。

这些可以留作未来课程白皮书/校长长版材料，但不是本销售短视频主线。

# 12. 当前校长销售视频 V0.1 的最终定位

视频不是：

- 课堂录像；
- AI平台介绍；
- Prompt教程；
- 教育理论演讲；
- 面向家长/大众的流量短视频。

视频是：

> **2分30秒—3分30秒左右的校长采购销售演示：动态PPT式讲解 + 少量真实作品运行证据。**

核心四个判断：

1. **孩子居然能做出这么完整、这么专业的数字产品。**
2. **这不是点一下AI，而是一套经过设计的课程。**
3. **课程在训练AI时代真正重要的专业动作和未来能力。**
4. **放进学校以后，一学期有持续、可展示、可传播的成果。**

建议信息比例（不是严格剪辑秒数）：

- 约35–40%：成果冲击；
- 约30%左右：课程含金量（需求、逻辑、测试、AI判断）；
- 约20%：一学期成长路径；
- 约10%：学校成果。

正式制作说明：

`courses/demo/PRINCIPAL_SALES_DEMO_VIDEO_V0.1.md`

# 13. 商业交付模式对 Demo 信息的影响

最近进一步明确商业链路：

> **课程开发方 → 代理商/区域伙伴 → 学校 → 代理商自己的受训教师到校上课 → 学生。**

因此，校长销售 Demo **不应该把“学校自己的老师能不能教会”作为主要采购证明**。

教师可培训性仍然非常重要，但它属于：

- 代理商教师培训；
- 教师认证；
- 后台交付稳定性。

它不是校长销售短视频的主要信息。

校长更应该看到：

- 供应方能完整交付；
- 学校自身负担低；
- 大部分学生能成功；
- 成果强；
- 有完整学期路径；
- 可形成学校展示资产。

---

# 14. 微信平台“认证/班级”问题：当前只记录为 OPEN，不要猜

2026-09 进一步讨论到：微信小程序教育平台创建班级可能涉及账号/学校认证。

当前公开资料显示：

- 2025后平台有“未认证也可先开展教学、默认学生账号”等公开二手记录；
- 但“创建班级是否必须认证”“非学校教育机构能否通过平台内部学校认证”“具体资质清单”尚未找到足够权威、最新、可独立确认的官方说明；
- 不能把普通微信小程序的企业/教育类目认证，直接等同于教育平台内部的学校认证。

因此当前状态：

> **OPEN / NEED REAL-ACCOUNT OR OFFICIAL VERIFICATION**

不要在课程销售材料里做任何超出事实的承诺。

这个问题主要影响：

- 班级组织；
- 多校代理交付；
- 作品/账号管理。

它目前不推翻 T1/T2 已证明的创作能力本身。

# 15. 当前所有“不可重新推翻”的核心判断

除非出现新真实证据，否则新会话/新工具不要重新从头争论以下结论：

1. **课程不是传统编程课。**
2. **课程不是AI工具说明课。**
3. **作品是明线，AI能力是暗线。**
4. **先成果成功，再拉开能力与原创深度。**
5. **保底作品也必须第一眼够强。**
6. **教师/学生都不应承担大量代码和配置。**
7. **M1游戏 T1 = FULL STRONG PASS。**
8. **M2学习平台 T2 = STRONG PASS。**
9. **不再泛搜秒哒/扣子/WorkBuddy来重复证明AI能不能生成应用。**
10. **小学40分钟、初中45分钟；BASE提前完成。**
11. **BASE通常只承担1个主要复杂修改 + 1个低风险可见增强。**
12. **方法可以重复，体验不能重复。**
13. **现场学生 Demo 与校长销售视频是两个不同产品。**
14. **校长销售视频不是课堂录像，只录成果证据。**
15. **不向校长完整展示母Prompt/生成配方/Recovery。**
16. **销售视频不以小游戏为唯一主角，应突出学习工具/数字产品的“真软件”感。**
17. **专业术语适量，用中文；让校长似懂非懂但感知专业，不堆砌。**
18. **未来能力用权威框架做短背书，不把销售视频做成理论白皮书。**
19. **商业交付由代理商受训教师到校完成，学校自有教师能否授课不是校长销售Demo主证明。**
