# 课堂平台费用、模型自由度与实施风险扫描

更新时间：2026-08-31
状态：FIRST PASS / OFFICIAL-DOC VERIFIED

## 1. 目的

本文件回答当前 AI-Courses 选型中的课堂级问题，而不是单纯比较“哪个平台生成效果最好”。

核心问题：

1. 费用是否可控，是否适合 20–40 人班级长期使用；
2. 平台底层大模型是否绑定，能否自带模型/API；
3. 是否适合未成年人和学校组织使用；
4. 账号、团队、并发、发布、数据、隐私、内容安全是否会成为课堂故障点；
5. 哪些能力适合直接给学生，哪些更适合由课程研发方/教师使用；
6. 如何避免课程被某个外部平台锁死。

结论先行：

> **当前最大风险不是 Token 本身，而是账号与年龄合规、课堂同时操作时的稳定性、平台规则变化，以及作品公开发布后的数据责任。**

当前建议：

- 秒哒：继续作为小学高年级与初中“无代码应用/小游戏”P0 候选，优先做真实课堂测试；
- 扣子编程：作为初中“带 AI 能力应用”P0 候选；对 13 岁以下学生暂不作为默认平台；
- WorkBuddy：更适合课程研发方、教师和较高年龄学生的复杂工作台/原型，不作为小学默认学生端；
- 所有平台均视为“可替换创作引擎”，不得成为课程核心 IP 或唯一交付依赖。

# 2. 秒哒 MIAODA

## 2.1 费用结构

秒哒采用“订阅 + 秒点”体系。

官方 2026-07-16 计费规则中，典型消耗包括：

- 快速开发请求：10 秒点/条；
- 深度开发请求：40 秒点/条；
- 发布应用：20 秒点/个；
- 复制自己应用：30 秒点/次；
- 下载源码：300 秒点/次；
- 后端基础版：15 秒点/应用/天；
- 更高后端规格按天增加；
- 部分官方技能按调用次数额外消耗秒点，可设每日调用上限。

秒点加油包当前最低档为 22 元/1000 秒点，大额包单点成本也大致在约 0.02 元量级附近；平台明确说明价格可能随版本更新调整。

官方来源：
- https://cloud.baidu.com/doc/MIAODA/s/ymmbrojwl
- https://cloud.baidu.com/doc/MIAODA/s/Pmih6khzs
- https://cloud.baidu.com/doc/MIAODA/s/omnczjzml

### 粗略课堂成本模型（仅用于产品预算，不作为正式报价）

按最低加油包 22 元/1000 秒点计算：

#### 轻量课
每名学生：4 次快速开发 + 1 次发布

- 60 秒点/人；
- 约 1.32 元/人/节；
- 30 人班约 39.6 元/节。

#### 中量课
每名学生：1 次深度开发 + 3 次快速修改 + 1 次发布

- 90 秒点/人；
- 约 1.98 元/人/节；
- 30 人班约 59.4 元/节。

#### 重量课
每名学生：5 次深度开发 + 1 次发布

- 220 秒点/人；
- 约 4.84 元/人/节；
- 30 人班约 145.2 元/节。

以上不包含：

- 企业订阅/成员席位；
- 长期开后端；
- 付费插件/技能；
- 视频、图像等更高成本生成；
- 未来价格变化。

因此对于“HTML/小游戏/轻应用”类课程，**纯生成费用本身并不高，且可以通过控制每节课允许的深度请求数形成预算上限。**

## 2.2 企业/课堂组织能力

2026 V3.x 已建立“企业—团队—成员”体系，支持：

- 一人购买、多成员使用；
- 团队空间；
- 企业/团队管理员；
- 向团队分配秒点；
- 查看团队秒点消耗；
- 项目权限与多人协作；
- 企业标准版与定制版。

这比“让30个学生各自充值个人账号”更适合学校课程。

官方来源：
- https://cloud.baidu.com/doc/MIAODA/s/Zmm32qp8x
- https://cloud.baidu.com/doc/MIAODA/s/Pmih6khzs

具体企业席位价格、学校批量采购方式和教育场景商务政策仍需向百度销售确认，不应仅按公开个人价推算。

## 2.3 秒哒的底层模型是否可换

需要区分两个层面。

### A. “秒哒替你开发应用”时的生成模型

官方定位明确为“百度基于文心大模型推出的生成式应用开发平台”。截至本次扫描，未找到官方文档表明用户可以把“秒哒自身的应用生成 Agent”整体替换成任意第三方模型。

因此当前应视为：

> **秒哒作为 App Builder 的核心生成能力主要由平台控制，课程方不能把它当成一个完全 BYO-Model 的壳。**

来源：
- https://cloud.baidu.com/doc/MIAODA/index.html

### B. 学生生成出来的应用里面要调用什么 AI

这里自由度明显更高。

秒哒支持：

- 自定义 API；
- 自定义插件；
- 自定义 Skill；
- 关联百度千帆 AppBuilder 智能体；
- 通过插件接入第三方文本大模型，官方甚至给出了 MiniMax 的完整示例；
- 官方文档也有通过 API 接入扣子智能体的案例。

来源：
- https://cloud.baidu.com/doc/MIAODA/s/3mj9fhz2o
- https://cloud.baidu.com/doc/MIAODA/s/6mlmjycxh
- https://cloud.baidu.com/doc/MIAODA/s/Xmaurlooz
- https://cloud.baidu.com/doc/MIAODA/s/Mmkm1klpy

所以秒哒的现实结构是：

> 秒哒负责“把应用做出来”；应用运行时的某些 AI 功能，可以接我们指定的外部模型/API。

这对课程已经足够，因为学生无需理解 API；未来我们的 Teacher Portal/课程底座可以统一封装这些能力。

## 2.4 未成年人问题

秒哒用户协议要求：

- 未满18岁应在监护人监护、指导并获得监护人同意后使用；
- 隐私政策明确称产品和服务“主要面向成年人”；
- 未满14岁使用前，应由父母/监护人阅读相关隐私规则并获得监护人同意；
- 平台可能收集手机号、设备信息，部分功能还涉及实名认证；
- 官方隐私政策写明，在彻底匿名化等条件下，AI交互内容和使用记录可能用于分析研究和模型训练；如不同意，可联系平台处理。

来源：
- https://cloud.baidu.com/doc/MIAODA/s/Vmb0jj48v
- https://cloud.baidu.com/doc/MIAODA/s/xmb0kke6f

### 对课程的含义

小学高年级不能简单采用：

> “让每个孩子现场自己用手机号注册秒哒。”

更可行的路径是：

1. 优先谈企业/学校组织账号；
2. 在招生/报名环节一次性处理监护人告知与同意；
3. 课堂不输入学生真实姓名、身份证、联系方式、成绩、家庭隐私等非必要信息；
4. 作品用昵称/编号；
5. 教师统一管理发布与公开展示；
6. 公开展示前做内容/肖像/版权审核。

## 2.5 课堂技术风险

### 风险 1：浏览器 Cookie / 学校电脑策略

秒哒官方文档明确指出应用广场可能因第三方 Cookie/跨站跟踪设置导致无法访问；微信内置浏览器也可能受限。

来源：
- https://cloud.baidu.com/doc/MIAODA/s/Pmck9hefk

因此学校部署前必须做“机房预检”，不能第一次上课才发现浏览器策略阻断。

### 风险 2：生成结果不稳定

秒哒 SLA 明确说明，大模型生成结果受输入、模型特性和随机性影响，不属于 SLA 强保证范围。

来源：
- https://cloud.baidu.com/doc/MIAODA/s/Mmowbge2a

因此课程不能采用“全班完全自由从空白生成任意复杂应用”。

应采用：

> 课程底座 + 自然语言个性化 + 明确恢复路径。

### 风险 3：后端长期保活费用

静态小游戏、无需登录的轻应用尽量不启用后端。

需要长期保存数据、登录、排行榜、数据库时再使用后端，避免每个学生作品每天持续扣费。

### 风险 4：公开广场可复制

研发母版不得发布到可复制的公开广场；学生作品可以在审核后用于展示，但课程底座应保持私有。

# 3. 扣子 / 扣子编程

## 3.1 费用结构

扣子 2026 年已全面转为订阅套餐 + 积分计费。

当前官方套餐公开价包括：

- 个人免费版：0 元；
- 个人进阶版：39.9 元/月，3 万积分；
- 个人高阶版：99 元/月，9.9 万积分；
- 个人旗舰版：199 元/月，19.9 万积分；
- 团队高阶版：198 元/月起；
- 团队旗舰版：398 元/月起；
- 团队尊享版：1998 元/月起；
- 企业标准版：980 元/月起；
- 企业旗舰版：8980 元/月起。

不同套餐成员数和积分不同，企业成员共享组织积分池。

来源：
- https://docs.coze.cn/coze_pro_premium_package
- https://docs.coze.cn/cozespace_coze_billing_overview
- https://docs.coze.cn/coze_pro_premium_package_faq

AI 编程从 2026-01-19 起正式计费。

来源：
- https://docs.coze.cn/guides_20260119_coze_premium_upgraded

### 为什么现在还不能给出“每生每节精确成本”

扣子的 AI 编程按“任务”计费，每轮任务消耗受：

- 模型；
- 代码执行；
- 虚拟机；
- 内置集成；
- 项目复杂度；

共同影响，不是一个固定的 Token 单价。

因此真实课堂成本必须通过统一 Benchmark 记录“30个学生完成同一个任务的积分消耗分布”，不能仅根据套餐价推算。

来源：
- https://docs.coze.cn/coze_pro_coze_task_fee

## 3.2 模型自由度明显高于秒哒

扣子编程官方明确支持：

1. 扣子官方内置模型；
2. 火山方舟模型；
3. 自定义模型服务。

其中自定义模型可以配置 API Key、API URL 等，像官方模型一样在工作空间使用。

但权限有层级限制：

- 低代码项目接自定义模型：企业旗舰版；
- 企业管理员配置后授权给工作空间；
- 使用自定义模型开发 AI 编程项目时，不产生扣子编程模型任务费用，但产生你自己的模型 Token 费用；
- 如果同时调用扣子内置集成服务，仍可能产生平台费用。

来源：
- https://docs.coze.cn/guides_model
- https://docs.coze.cn/guides_deploy_custom_model
- https://docs.coze.cn/guides_vibe_coding_faq

这对我们未来很有价值，因为理论上可以实现：

> 课程平台统一选择/更换模型 → 扣子负责应用开发环境。

但要注意企业旗舰版成本，不应在课程刚启动时就为了“模型可换”购买重企业方案。

## 3.3 最大课堂问题：13岁以下条款

扣子 2026-08-17 生效的最新用户协议同时规定：

- 未满18岁，应在监护人监护、指导并获得监护人同意后使用；
- 服务主要适用人群为18岁及以上；
- 对用户创建的 Agent/软件，用户有最终用户的数据和年龄适配责任；
- **用户创建的 Agent 不应面向13岁以下儿童。**

协议中“你的Agent”实际包含用户通过服务创建的 Agent 和其他软件。

来源：
- https://docs.coze.cn/guides_terms-of-service

### 当前产品决策意义

这条规则会直接影响小学高年级：五六年级往往包含 10–12 岁学生。

因此当前暂定：

> **扣子不作为小学高年级默认学生创作/发布平台，至少在获得平台官方教育场景解释或形成合规替代方案之前如此。**

但它仍然非常适合：

- 初中课程（多数学生13岁+，仍需监护人同意与学校合规）；
- 教师研发课程底座；
- 课程开发团队制作 AI 应用原型。

特别注意：即使“开发者本人”是老师或成年人，如果最终发布作品面向13岁以下儿童使用，该条款仍可能构成问题，所以不能靠老师代注册简单绕开。

## 3.4 账号与费用责任

扣子个人账号原则上限本人使用，不应让一个个人账号全班共享。

企业版支持成员、工作空间、访问控制和统一计费；企业成员的扣子费用由企业购买者承担，并共享积分池。

来源：
- https://docs.coze.cn/guides_terms-of-service
- https://docs.coze.cn/coze_pro_premium_package_faq
- https://docs.coze.cn/coze_pro_bills_and_usage

因此正式课堂如果使用扣子，应走组织/成员模式，而不是“老师的个人号给30个学生轮流登录”。

## 3.5 模型/能力会下架，课程不能绑定具体模型名

扣子 2026 年产品日志已经出现多次模型上线/下架，例如 7 月曾下线多个 Kimi、GLM、DeepSeek 版本。

来源：
- https://docs.coze.cn/guides_release_note

因此教案不能写死：

> “第5课必须选择 XX-2026 模型。”

而应写：

> “选择当前课程验证通过的【快速开发模型】/【高质量开发模型】。”

真正的模型映射由我们的课程平台/教师更新页维护。

# 4. WorkBuddy / CodeBuddy

## 4.1 成本

2026-07-01 起个人套餐公开价：

- 体验版：免费；
- 标准版：99 元/月；
- 高级版：199 元/月；
- 旗舰版：999 元/月；

连续包月和年付有折扣。

来源：
- https://www.workbuddy.cn/docs/workbuddy/Pricing

如果给每个学生购买个人订阅，课堂成本显然高于秒哒式秒点，因此不适合作为小学大班默认工具。

## 4.2 模型自由度很高

WorkBuddy 支持：

- 内置多个主流模型；
- 腾讯云 Token Plan；
- 第三方 Coding Plan；
- 自定义 API；
- OpenAI 兼容接口；
- Ollama 本地模型；
- API Key 保存在本地配置。

来源：
- https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Model

因此它对课程研发团队非常有价值，可用于：

- 快速做课程原型；
- 批量生成教师模板；
- 尝试不同模型；
- 搭建复杂工作台/轻应用。

## 4.3 为什么不优先给小学生

WorkBuddy 不只是网页生成器，而是能读写本地文件、执行任务的 Agent 工作环境。

虽然隐私政策允许在监护人同意等前提下处理未成年人数据，但对小学课堂而言，权限边界、设备安全和错误操作成本都高于浏览器式无代码平台。

来源：
- https://www.workbuddy.cn/privacy/

当前建议：

> **研发方/教师工具 > 初中高阶可选 > 小学默认学生工具。**

# 5. 课堂使用的共性问题

## 5.1 账号摩擦

这是最容易在真实课堂里毁掉体验的因素之一。

禁止设计：

> 第一次上课用20分钟让30个学生注册账号、收验证码、实名认证、找回密码。

正式课应做到：

- 课前建立组织/班级账号；
- 第一次登录路径统一；
- 备用账号/设备有明确规则；
- 不共享个人账户；
- 学生退出后不遗留他人作品和隐私。

## 5.2 同时生成时的并发与排队

官方网站通常公布 API RPM 或企业资源限制，但“30个学生同一分钟都点生成”是否顺畅，不能只从文档推断。

真实 Pilot 必须做：

- 10人并发；
- 20人并发；
- 30人并发；
- 同一 Wi-Fi；
- 同一机房出口 IP；

并记录：成功率、排队时间、风控验证码、异常提示。

## 5.3 学校网络与浏览器

至少预检：

- 域名能否访问；
- CDN/JS依赖是否被拦；
- WebGL 是否可用；
- 第三方 Cookie；
- 下载/上传策略；
- 浏览器版本；
- 学校电脑是否禁止安装客户端。

## 5.4 学生作品的数据责任

一旦作品加入：

- 登录；
- 评论；
- 上传照片；
- AI 对话历史；
- 排行榜；
- 学生姓名；

就会从“一个小游戏”变成有真实用户数据处理责任的应用。

第一阶段课程应默认：

> **无实名、无社交、无真实成绩、无家庭信息、无真实联系方式、尽量无后端。**

## 5.5 作品公开发布与版权

学生可以做“平台跳跃游戏”，但公开展示不应直接复制：

- Mario；
- Minecraft；
- Roblox角色；
- 动漫IP；
- 影视角色；
- 商业音乐；

课程应该提供“机制借鉴、主题原创”的创作规范。

## 5.6 成本失控

所有平台都应有课堂预算阀门：

- 每节课允许多少次高质量生成；
- 图片/视频调用上限；
- 后端默认关闭；
- 对话轮次上限；
- 学生不能自行添加付费插件/API；
- 教师/管理员查看全班消耗。

## 5.7 工具下架与课程版本漂移

课程必须把“产品能力”写成抽象层，而不是具体按钮路径。

例如：

- `APP_BUILDER_FAST`：快速生成轻应用；
- `APP_BUILDER_AI`：支持 AI 功能的应用生成；
- `IMAGE_GEN`：课程验证过的图像生成；
- `PUBLISH_WEB`：生成可访问作品链接。

每学期由课程研发方更新“当前推荐工具映射”。

这样平台 UI 改版或模型下架，不必重写整门课。

# 6. 当前课堂选型建议

# 7. 下一步真实 Benchmark 必测项

对于每个平台，用同一课程任务测试：

1. 首次登录时间；
2. 是否需要手机号/实名；
3. 30学生账号如何批量管理；
4. 从输入第一条需求到第一版可玩作品的时间；
5. 第一版成功率；
6. 修改3次后的成功率；
7. 老师是否需要看代码救场；
8. 30人同一时间生成是否排队/风控；
9. 每名学生实际积分/秒点/费用；
10. 发布是否需要额外审核；

13. 能否复制教师母版但不暴露研发母版；
