# 核心母版验证协议 V1

更新时间：2026-09-01
状态：READY FOR HANDS-ON VALIDATION

## 1. 目的

微信小程序教育平台已经真实验证：

- M1 游戏母版：FULL STRONG PASS；
- M2 学习平台母版：STRONG PASS。

当前不再重复验证它们。

下一阶段只验证三个会覆盖大量正式课次、但尚未成为本项目 Known-Good 的核心母版：

- **M3 互动故事 / 分支世界；**
- **M4 兴趣馆 / 知识产品；**
- **M5 工作台 / 记录 / 校园工具。**

验证目标不是追求“最复杂”，而是确认：

> **是否能成为展示级、低教师负担、40/45分钟内可交付、还能向上无限拓展的稳定课程底座。**

## 2. 统一验证纪律

每个母版都遵守：

1. 不手写代码；
2. 不人工 Debug；
3. 不接外部服务器；
4. 不接复杂数据库；
5. 不加登录/OAuth；
6. 优先本地存储；
7. 首版必须实际试玩；
8. AI 说“完成”不算完成；
9. 出故障只用自然语言要求 AI 自检、自修；
10. 每次只加一个主要复杂度，避免一次塞入过多功能。

### 时间记录

记录真实生成/修改耗时，但判断重点是课程预算：

- 小学 BASE 应有能力在 25–30 分钟内由学生完成；
- 初中 BASE 应有能力在 30–35 分钟内由学生完成；
- 单次 AI 生成/修改如果持续达到数分钟以上且频繁出现，需重新评估课堂容量。

## 3. 统一评分维度

每项 0–5 分：

1. 第一版速度；
2. 第一版完整度；
3. 第一眼 Wow；
4. 无代码程度；
5. 自然语言修改成功率；
6. 逻辑修改能力；
7. 个性化空间；
8. AI 自修能力；
9. 发布/扫码；
10. DISPLAY-SAFE BASE 稳定性；
11. Challenge 上探空间；
12. 普通教师负担。

总分 60。

### 判定

- 51–60：CORE MOTHER TEMPLATE STRONG PASS
- 43–50：PASS WITH GUARDRAILS
- 34–42：OPTIONAL / CHALLENGE ONLY
- <34：不进入正式主线

### 一票否决

出现任一情况不得作为小学/初中核心 BASE：

- 必须手写代码；
- 必须教师逐台技术处理；
- 复杂功能经常破坏基础版且难以恢复；
- 无法稳定试玩；
- 成果第一眼明显不像完整产品；
- 分享/展示很麻烦；
- 只有60分钟以上才可能形成完整基础成品。

# M3 — 互动故事 / 分支世界

## 4. 为什么验证 M3

对应正式课：

- 小学第3–4课；
- Demo/活动课候选；
- 初中互动体验类项目；
- 最终项目母版之一。

它的价值是：

> **比普通故事更“会工作”，比复杂游戏更容易让低能力学生完成。**

## 5. M3 Prompt 1 — 第一版

> 帮我做一个适合小学高年级玩的互动冒险故事微信小程序，主题是“恐龙岛逃生”。不要让我写代码，请直接生成可以运行和预览的完整小程序。
>
> 要有一个开场页，主角醒来后发现自己在恐龙岛。故事至少有3次玩家选择，每次选择会进入不同情节，最终至少有3种明显不同的结局：成功逃离、被困岛上、发现隐藏研究基地。
>
> 页面要有角色、场景图片或视觉元素、明显的选择按钮，并有简单动画或反馈。玩家可以重新开始探索其他结局。界面要有冒险感但适合小学生。

### 首版验收

- 开场；
- 至少3个选择节点；
- 至少3种真实分支结局；
- 可重玩；
- 页面不是纯文字；
- 可完整试玩；
- 视觉达到展示线。

## 6. M3 修改 1 — 状态机制

> 增加“勇气值”和“补给”两个状态。不同选择会增加或减少它们，部分选择只有达到一定勇气值或拥有补给时才能出现。请保持原来的故事和3种结局，并确保状态变化在页面上能看见。

验证：
- 状态真实变化；
- 条件真实影响分支；
- 原故事未损坏。

## 7. M3 修改 2 — 个性化

> 把主角改成由玩家自己输入名字，并让玩家从“探险家、科学家、摄影师”三个身份中选择一个。不同身份至少有一次不同的专属选择。

验证：
- 用户输入；
- 身份选择；
- 条件分支；
- 本地即可，无需登录。

## 8. M3 Challenge

> 增加一个隐藏结局，但不要直接告诉玩家怎么触发。需要玩家在前面的选择中收集到两个线索以后，最终才会出现隐藏入口。

意义：验证上探空间。

### M3 Strong Pass 特别要求

除了统一标准，还要求：

> **即使只完成首版，成品也已经足够拍15秒视频、扫码给家长试玩。**

# M4 — 兴趣馆 / 知识产品

## 9. 为什么验证 M4

对应正式课：

- 小学兴趣博物馆；
- 知识闯关；
- 学科/兴趣融合；
- 校园展示；
- 初中知识产品。

关键是避免变成：

> “AI生成了一堆文字和图片。”

必须是一个真正能逛、能点、能收藏、能闯关的产品。

## 10. M4 Prompt 1 — 第一版

> 帮我做一个适合小学高年级的“恐龙探索博物馆”微信小程序。不要让我写代码，请直接生成可以运行和预览的完整小程序。
>
> 首页要像一个真正的数字博物馆，有“肉食恐龙、植食恐龙、飞行爬行动物、化石发现”四个展区。每个展区至少有3个展品卡片，点进去可以看到名称、时代、特点和一条有趣事实。
>
> 增加“我喜欢的展品”收藏功能，并有一个“恐龙挑战”入口，里面有10道四选一题、积分和通关页。界面要有博物馆/探险感，视觉完整，不要只是文字列表。所有数据放本地，不需要登录或服务器。

### 首版验收

- 首页；
- 4展区；
- 详情；
- 收藏；
- 10题挑战；
- 积分/通关；
- 可实际试玩；
- 展示级视觉。

## 11. M4 修改 1 — 信息结构

> 增加一个“我的探索进度”，显示4个展区各自看过多少展品，以及总探索百分比。看过的展品要有明显标记。仍然只用本地数据。

验证：
- 状态记录；
- 跨页面更新；
- 进度显示。

## 12. M4 修改 2 — 学生所有权

> 增加一个“我的新展区”，让使用者可以自己输入展区名称，再新增3个展品，每个展品输入名称、简介和一个有趣事实。保存以后，新展区要和原来的展区一样可以浏览，也计入探索进度。只用本地存储。

验证：
- 自定义内容；
- 数据持久化；
- 不引入不必要后端。

## 13. M4 可信度测试

选择其中3条恐龙事实，单独人工核查。

目的不是验证平台百科质量，而是为正式课程验证：

> “AI生成内容 → 学生核查 → 产品纠错”

是否能自然进入作品流程。

## 14. M4 Challenge

任选：

- 隐藏展品；
- 搜索；
- 收藏成就；
- Boss题；
- 展品对比；
- 自定义主题馆（汽车/昆虫/足球/航天等）。

### M4 Strong Pass 特别要求

首版必须已经像一个完整数字产品，而不是“4个页面+一堆AI文字”。

# M5 — 工作台 / 记录 / 校园工具

## 15. 为什么验证 M5

对应正式课：

- 小学校园工具；
- 初中多页面产品；
- 数据记录；
- 学习驾驶舱；
- 运动/习惯记录；
- 校园应用；
- 最终真实问题项目。

这是“孩子做出了一个真正工具”的最强能力反差之一。

技术策略：

> **视觉复杂度可以高，但数据层必须简单。**

默认只用：

- 本地数据；
- 简单记录；
- 不接真实学校系统；
- 不接邮箱/日历/API；
- 不做真实多用户登录。

## 16. M5 Prompt 1 — 第一版

> 帮我做一个适合小学高年级和初中生使用的“我的学习驾驶舱”微信小程序。不要让我写代码，请直接生成可以运行和预览的完整小程序。
>
> 首页要像一个真正的个人学习控制台，显示：今天待办、今日专注时间、本周完成任务数、连续学习天数。
>
> 功能包括：
> 1. 待办任务：可以新增、完成、删除；
> 2. 番茄专注：可以开始25分钟专注并记录完成次数；
> 3. 阅读/学习记录：输入今天学了什么、花了多久；
> 4. 本周进度：用简单图表或进度条展示每天完成任务数量和专注次数。
>
> 界面要像现代 App 的仪表盘，有明显卡片、状态和进度，不要像普通表单。所有数据只保存在本地，不需要账号、服务器或真实日历接口。

### 首版验收

- 多页面/多模块；
- 新增/完成/删除；
- 本地保存；
- 专注记录；
- 学习记录；
- 周进度可视化；
- 第一眼像产品；
- 可试玩/分享。

## 17. M5 修改 1 — 游戏化

> 增加“学习能量”和“等级”。每完成一个任务获得10点能量，每完成一次专注获得20点。能量达到100自动升级，并出现明显但不过度的升级动画。首页显示当前等级和升级进度。

验证：
- 状态；
- 计分；
- 持久化；
- 动画。

## 18. M5 修改 2 — 用户自定义

> 增加“我的目标”，让使用者自己设置一个本周目标，例如“完成5次专注”或“读书120分钟”，首页显示目标进度。目标和进度都只保存在本地。

验证：
- 用户输入；
- 动态计算；
- 产品感。

## 19. M5 Challenge

任选：

- 今日一句鼓励；
- 成就徽章；
- 学习主题切换；
- 不同类型任务统计；
- 本周总结页；
- 自己定义一个真正想记录的东西。

### M5 Strong Pass 特别要求

> **基础版本必须看起来比它的真实技术复杂度“高级很多”。**

这是本母版成为学校 Wow 项目的关键。

# 20. 三类母版通过后的课程处理

## M3 Strong Pass

正式解锁：
- 小学互动故事/数字世界；
- 分支逻辑项目；
- 最终故事类项目。

## M4 Strong Pass

正式解锁：
- 兴趣博物馆；
- 知识闯关；
- 学科融合产品；
- 可信内容训练。

## M5 Strong Pass

正式解锁：
- 校园工具；
- 学习驾驶舱；
- 记录类产品；
- 初中真实问题产品。

如果某母版只是 PASS WITH GUARDRAILS：

- 可以进入正式课程；
- 但必须预制更强 BASE/FALLBACK；
- 不允许让学生从空白完成。

如果失败：

> **直接改课程，不强迫老师/学生提高技术能力来迁就母版。**

## 21. 当前停止条件

完成 M3/M4/M5 各一次真实账号测试后，停止继续广泛证明平台能力。

然后进入：

> **MOTHER TEMPLATE PRODUCTIZATION**

为通过的母版制作：

- 稳定 BASE；
- FALLBACK；
- Prompt/任务骨架；
- Theme Options；
- Rule/Feature Options；
- Wow Options；
- Recovery；
- Quick Win；
- Builder；
- Open Creator；
- 教师演示版；
- 展示样例。
