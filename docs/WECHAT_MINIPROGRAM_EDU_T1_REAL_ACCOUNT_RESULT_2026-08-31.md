# 微信小程序教育平台 T1 真实账号实测结果

更新时间：2026-08-31
状态：CORE STRONG PASS / PUBLISH CHECK PENDING

## 1. 测试目的

验证微信小程序教育平台是否能够让非程序员用户，在不手写代码、不进入传统编程教学的前提下，通过自然语言快速生成、修改并修复一个可玩的小游戏。

对应协议：`docs/WECHAT_MINIPROGRAM_EDU_HANDS_ON_TEST_V1.md`

## 2. 实测结论

核心创作闭环：**STRONG PASS**。

用户真实账号完成：

1. 从自然语言生成“记忆力翻牌”小游戏；
2. 将水果主题改为太空探险主题；
3. 增加 60 秒倒计时、失败机制、三连击和额外计分；
4. 增加通关后的火箭升空动画和新的成功文案；
5. 在一次预览持续“加载中”的实际故障中，仅通过自然语言要求 AI 检查并修复，AI 自动修改项目配置与样式实现并恢复可用；
6. 全部完成后实际试玩合格。

用户报告：**每次生成/修改任务均在 1 分钟以内完成。**

这显著优于此前协议设定的“10–15 分钟出现第一版”硬门槛，也优于公开报道中“约 5 分钟完成一个小程序”的参考基线。

## 3. 具体实测任务

### 3.1 第一版

Prompt：

> 帮我做一个适合小学高年级玩的“记忆力翻牌”小游戏。页面有12张卡片，共6对图案。开始时全部背面朝上，每次点击两张；相同则保持翻开并得10分，不同则1秒后翻回。全部配对成功后显示“挑战成功”和总分。界面明亮好看，有开始和重新开始按钮。请直接生成一个可以运行和预览的小程序，不要让我自己写代码。

实际结果：

- 生成 12 张卡片 / 6 对水果图案；
- 配对、翻回、计分、完成提示均实现；
- 有开始/重新开始；
- 有明显视觉设计和卡片动画；
- 生成耗时 < 1 分钟。

### 3.2 实际故障与 AI 自恢复

第一版之后出现“左边一直显示加载中”。

用户没有查看或修改代码，只用自然语言询问原因。

AI 自动完成：

- 修改 `project.config.json` 基础库版本并补充项目根目录；
- 修改 `project.private.config.json` URL 检查；
- 调整 `app.json` 兼容项；
- 修改 WXSS 中可能不兼容的 3D 变换属性；
- 完成文件验证并要求重新预览。

之后试玩恢复正常。

### 这条证据的重要性

本项目的核心风险之一是：普通教师若遇到学生作品报错，是否必须懂代码才能救场。

此次真实故障说明至少在这一类问题上可以形成：

> 学生/教师描述现象 → AI 自己检查 → AI 修改底层代码/配置 → 恢复运行

而不是：

> 教师打开 JS/WXSS 手工 Debug。

这对“普通教师可交付”是非常强的正向证据。

注意：单次成功不能推导所有故障都能自动修复，仍需后续故障样本库和课堂并发测试。

- 原游戏逻辑保持；

### 3.4 规则修改

## 5. 对产品设计的直接含义

### 5.1 微信小程序教育平台可以正式进入小学 Wow Demo 原型设计

此前最大疑问是：教育原生平台会不会虽然“学校合规”，但 AI-native 能力太弱，最后重新变成编程课。

本次实测已经显著降低这一风险。

目前真实体验符合项目硬约束：

> 想法 → 自然语言 → AI 一分钟内生成 → 试玩 → 自然语言改主题/规则/动画 → AI 自动修改 → 继续试玩。

整个学生可见流程不需要把 JavaScript / WXSS / 项目配置变成学习内容。

### 5.2 “AI自己修Bug”应进入正式课程设计

正式课程不要把报错当成灾难。

可把学生暗线能力设计成：

1. 描述现象；
2. 不自己乱改；
3. 让 AI 检查原因；
4. 验证修复是否真的有效；
5. 若无效再继续描述。

这比传统“老师帮你Debug”更符合课程定位。

### 5.3 Demo 课不应只复制一个标准小游戏

既然修改速度 <1 分钟，45–60 分钟 Demo 完全有空间要求每个学生完成至少 2–3 个自己的修改：

- 换主题；
- 改规则；
- 加一个“我还想让它……”的个人功能。

这样才能形成学生所有权，而不是所有人生成同一个翻牌游戏。
