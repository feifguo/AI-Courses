# AI-Courses 内部走课审核 V0.1

更新时间：2026-09-01
状态：ACTIVE INTERNAL WALKTHROUGH AUDIT
范围：当前小学高年级与初中已完成逐课 V0.1/V0.2 教案

## 1. 审核目的

本审核不再增加新课型，专门检查四件事：

1. **时间盒**：BASE 是否真的能在标准课时前明显完成，而不是理论上刚好做完；
2. **教师讲授量**：认知型课是否会滑成 AI 素养 PPT 课；
3. **跨课重复**：相邻课是否虽然换了标题，但学生体验仍然重复；
4. **展示强度**：教育动作完成后，家长/学校第一眼能否看到明显变化。

产品优先级不变：

> **先保证展示级成果与课堂成功率，再在稳定成果上叠加能力训练。**

---

## 2. 总体结论

当前 V0.3 课程结构方向正确，Pair 节奏、BASE/FALLBACK/Challenge、标准课时、最终展示链均可保留。

本轮最重要的新发现是：

> **AI 生成本身通常很快，但真实课堂的不确定时间主要消耗在试玩、触发条件、发现冲突、描述故障、AI修复、再次验证。**

因此不能因为一次 AI 修改只需要 1–2 分钟，就在 BASE 中连续要求学生完成 2–3 个复杂逻辑修改。

### 新增硬规则：BASE COMPLEXITY BUDGET

标准课时的 DISPLAY-SAFE BASE 原则上只承担：

> **1 个主要复杂修改 + 1 个低风险可见增强。**

其中“复杂修改”包括：
- 多条件规则；
- 多状态联动；
- 跨页面同步；
- 本地数据持久化；
- 多阶段反馈；
- 复杂计分/升级；
- 可能破坏原流程的结构改动。

“低风险可见增强”包括：
- 动画；
- 徽章；
- 颜色/状态提示；
- 文案；
- 视觉层级；
- 单一反馈效果。

第二个主要复杂修改默认进入：

- GUIDED CREATOR；
- Challenge；
- 延长课时。

### 例外

如果某节课本身的唯一教学目标就是“理解两个规则之间的关系”，例如初中 L3 Rule Lab，可以要求两个联动规则；但必须使用**预验证的规则组合菜单**，不能让全班同时自由设计两套未知复杂逻辑。

---

## 3. 认知型课的讲授上限

需求表达、AI评审、事实核查、AI反方、用户测试等课程的价值很高，但最容易变成讲道理。

正式规则：

> **教师原则讲解尽量控制在单次 3–5 分钟；连续 10 分钟没有学生操作真实作品，视为设计预警。**

优先采用：

> 看一个反例 → 立即在自己作品上做 → 结果出来后再总结。

不采用：

> 先讲完整概念 → 填表 → 再讨论 → 很久以后才改作品。

---

## 4. 认知课必须有可见 Before / After

事实核查、AI评审、用户测试、AI反方等课，不能只留下“我学会判断了”的隐形成果。

每节至少保留一种肉眼可见证据：

- 修改前/后截图；
- 首页结构变化；
- 来源/已核查卡；
- 删除/合并前后对比；
- 用户反馈卡 + 修复结果；
- V1/V2 对比；
- 规则触发前后画面。

目标：

> **教育价值发生在学生脑中，但学校和家长必须能看见它在作品上的痕迹。**

# 5. 小学逐课审核

## L1 第一款游戏 — PASS

当前结构合理：快速第一版 + 个性化 + 1 条规则/Wow。

不改。

## L2 游戏规则升级 — REVISE

### 当前风险

BASE 同时要求：
- 两条真实规则；
- 两次完整试玩；
- 再增加一个可见状态/反馈；
- 28 分钟前全部稳定。

对强学生不难，但对弱学生而言，真正风险在第二条规则引发冲突后的修复时间。

### 修正

BASE 改为：

> **1 条主要玩法规则 + 1 个低风险可见反馈。**

例如：
- 倒计时 + 最后10秒变红；
- 三连击 + 连击动画；
- 三次错误失败 + 生命提示。

第二条独立复杂规则进入 GUIDED / Challenge。

这样家长仍然能一眼看到“玩法真的变了”，但保底更稳。

## L6 知识闯关 — BACKUP ONLY

保持 V0.3 决策：M4 未通过前不作为正式默认 L6，避免与 L7 表面重复。

## L7 学习 App — PASS

首版完整产品 + 一条学习规则，节奏合理。

## L8 学习 App 会教人 — REVISE

### 当前风险

BASE 同时要求：
- 多阶段答错反馈；
- 不同计分；
- 连胜；
- 超级模式；
- 最高连胜；
- 多轮触发验证。

生成很快，但触发验证链过长。

### 修正

BASE 强制：

1. **一条“聪明反馈”复杂规则**，优先“第一次答错先提示、第二次再给答案”；
2. **一个低风险可见奖励**，例如徽章、进度动画、连胜文字。

“连续5题 → 20秒超级模式 → 双倍积分 → 最高连胜”等进入 GUIDED / Challenge。

## L11 用户测试 — PASS

真人测试与 L15 发布验收职责清楚，不改。

## L12 可信内容 — REVISE

### 当前风险

40 分钟 BASE 强制核查 3 条事实，对弱学生和阅读速度慢的学生不必要地消耗时间。

### 修正

BASE：
- 核查 **2 条关键事实**；
- 至少修正/澄清 1 条，或增加来源说明；
- 必须加入明显的“已核查/来源/纠错”可视模块。

第 3 条及多来源比较进入 Challenge。

教师必须提供预选来源，不让小学学生在开放网络无限搜索。

## L13/L14 Final V1/V2 — PASS WITH CLARIFICATION

最终项目课可以保留多个展示标准，但应明确：

> **这些是最终产品累计具备的能力，不代表本节要新增加多个复杂功能。**

每节 BASE 新增主要复杂度仍不超过 1 个。

## L15/L16 — PASS

发布验收与嘉年华职责清楚，继续保持“停止开发 → 锁稳定版本 → 展示”。

# 6. 初中逐课审核

## L1/L2 — PASS

L2 虽然认知成分较多，但学生在前 10 分钟后即进入自己作品，整体可接受。

内部走课时重点观察：四格需求卡是否需要 5 分钟以上；若普遍过慢，改成选择式卡片。

## L3/L4 Rule Lab — PASS WITH GUARDRAIL

V0.3 已把 L3/L4 换成新 Rule Lab，解决连续四周改同一作品的问题。

L3 是 BASE Complexity Budget 的例外：本课必须有两个规则才能教“联动”。

但正式产品化前必须提供 **3–5 套预验证规则组合**，例如：
- 连击 + 答错清零；
- 倒计时 + 最后10秒警告；
- 能量满100升级 + 升级后清零；
- 生命值归零 + 结束状态锁定。

弱学生不从空白设计两条未知规则。

## L7/L8 — PASS

区分继续保持：
- L7 = 作者自己做 UX 检查；
- L8 = 真人第一次使用。

L8 同伴测试组织要保证双方都有操作时间，建议每人 2–3 分钟核心流程，而不是完整探索所有功能。

## L9 AI评审 — REVISE

### 当前风险

前 25 分钟中较多时间用于：AI评审、分类、解释，再到 25 分钟才修改产品。

容易出现“方法正确，但课堂像研讨课”。

### 修正

标准版压缩为：
- 0–3 分钟：看一条错误/不合适建议；
- 3–8 分钟：AI只给最重要3条建议；
- 8–13 分钟：学生标记接受/拒绝并选1条；
- 13–28 分钟：立即修改并试玩；
- 28–35 分钟：BASE 锁定；
- 35–42 分钟：人类复核/第二建议（可选）；
- 42–45 分钟：Before/After + 一条“我没听AI”的说明。

BASE 只强制修改 **1 条** 最重要建议。

## L10 事实核查 — REVISE

BASE 改为：
- 核查 **2 条关键事实**；
- 使用教师预置可靠来源包；
- 至少处理 1 个错误/不严谨/来源问题；
- 加入可见可信模块；
- 第 3 条、多来源冲突进入 Challenge。

目的不是降低标准，而是保证学生有时间把核查结果真正改回产品并重新测试关联内容。

## L11 AI反方 — REVISE

### 当前风险

与 L9 相同，前 25 分钟讨论/判断偏长。

### 修正

标准版：
- 0–3 分钟：看“功能太多反而更差”的例子；
- 3–8 分钟：AI只提出最关键3条质疑；
- 8–13 分钟：学生选1条回应；
- 13–28 分钟：完成一次删除/合并/弱化/重排；
- 28–35 分钟：BASE 锁定并试玩；
- 35–42 分钟：比较前后版本；
- 42–45 分钟：解释最终决策。

BASE 强制产出一张明显的 Before/After。

## L12 Real Problem Sprint — PASS

V0.2 已明确为训练赛，与 L13 Final Launch 区分清楚。

## L13 — PASS

正式最终项目启动，不再与 Sprint 重复。

## L14 — PASS WITH CLARIFICATION

当前“核心流程 + 状态/数据 + Wow + 原创功能”应理解为 **V2最终累计状态**，不是要求本节从零新增四项。

本节标准 BASE：

> **只新增 1 个最重要复杂升级 + 必要低风险展示增强 + 1 次删减/弱化决策。**

如果 V1 已经有状态/数据，则无需再造一个新的。

## L15/L16 — PASS

继续保持发布前停止功能扩张。

# 7. 教师负担审核

当前最大教师风险不再是技术，而是：

1. 学生一次加太多功能；
2. 学生生成后不试玩；
3. 多个学生同时进入不同复杂 Debug；
4. 认知型课老师讲太多；
5. 快学生继续加功能，慢学生仍没锁 BASE。

因此教师统一看两个指标即可：

### BASE DEADLINE

到了时间，未达展示线的学生全部停止新增，进入 FALLBACK。

### COMPLEXITY COUNT

问一句：

> **“这个学生现在同时在改几个高风险逻辑？”**

基础路径答案原则上应为：

> **1 个。**

如果是 2–3 个，应先缩回一个。

# 9. 一句话结论

> **AI快，不代表课堂应该塞得满；AI省下来的时间，应该留给试玩、判断、修复和创造，而不是继续堆第二、第三个复杂功能。**
