## 一、结论先行

当前项目已经远远超过“只有课程说明”的阶段，但还没有达到“把整套资料交给一位刚培训完的新手老师，他就能稳定上完整学期课”的标准。

已经具备：

- 小学高年级 16 课完整学期结构；
- 初中 16 课完整学期结构；
- 25 / 32 节已有逐课脚本；
- M1 游戏、M2 学习平台两套真实账号验证过的稳定产品底座；
- 共用课堂卡；
- 教师授课方法；
- 教师培训与认证框架；
- 课前技术检查；
- 学校首发检查；
- 真实课堂记录表。

但仍有五类关键缺口：

1. 少数课程过早允许学生选择不同产品方向，教师现场负担会快速上升；
2. 还有 7 / 32 节没有逐课脚本；
3. 已有 25 份逐课脚本深度不一致，部分已经接近完整教案，部分仍只是执行提纲；
4. 教师材料仍大量使用研发语言，不适合新手老师直接阅读和行动；
5. 整套教师交付资料还没有完成“最后一公里物料化”：没有形成每课独立的上课包，也没有形成统一的人类入口。

因此当前最准确的阶段判断是：

> **课程设计已进入后半程；教师交付产品化尚未完成。**

# 二、课程自由度审计：哪里已经符合，哪里需要收紧

本轮新增的核心原则：

> **先同构，后分化；先完成，后创造。**

解释成人话：

> 每节课前半段，学生先从同一个稳定任务出发，保证绝大多数人都能做出来；完成以后，再逐步开放主题、内容、规则、功能和更自由的创造。

不是所有 32 节课都存在“学生做得太不一样”的风险。真正需要审查的是那些“重新创建一个新产品”的节点。

## 小学高年级

| 课次 | 当前设计 | 判断 | 优化方向 |
|---|---|---|---|
| L1 第一款游戏 | 全班做同一个记忆翻牌骨架 | 符合 | 保持 |
| L3 互动冒险 | 计划使用统一 M3 骨架 | 方向符合，但未验证 | M3 验证后固定统一起点 |
| L5 兴趣博物馆 | 计划使用统一 M4 骨架 | 方向符合，但未验证 | M4 验证后固定统一起点 |
| L7 学习 App | 全班使用同一 M2 学习平台结构 | 符合 | 保持 |
| L9 校园工具 | “校园/学习/记录工具”范围偏宽 | 需要收紧 | 不让学生任选工具，先固定一个标准工具任务 |
| L13 最终项目 | 从 M1/M2 等成熟方向选 | 可以更开放 | 保留多个成熟轨道，但禁止从完全未知架构起步 |

其余课程大多是在已有作品上继续修改、测试、核查、升级、发布，风险较低。

## 初中

| 课次 | 当前设计 | 判断 | 优化方向 |
|---|---|---|---|
| L1 第一数字产品 | 游戏 / 学习产品二选一 | 需要收紧 | 第一节统一一个产品骨架 |
| L3 Rule Lab | 统一 M1 + 已验证规则组合 | 符合 | 保持 |
| L5 真正工具 | 工具类别较宽，依赖 M5 | 需要收紧 | M5 验证后固定一个标准工具任务 |
| L12 真实问题极速赛 | 问题池可能导向不同架构 | 需要收紧 | 问题池与产品轨道绑定，不能任意跨架构 |
| L13 最终产品 | 最终项目可以更自由 | 可以更开放 | 只从成熟母版轨道中选，再做原创升级 |

### 审计结论

在真正“新建产品”的 11 个关键节点中：

- 3 个已经是“统一起点 + 已验证底座”；
- 2 个设计方向已经正确，但仍被 M3/M4 验证阻塞；
- 4 个需要明显收紧；
- 2 个属于最终项目，可以保留较高自由度，但应该改成“成熟轨道任选”，而不是无限开放。

换句话说：

> **现在的问题不是整套课程都太自由，而是少数关键起点还没有完全产品化。**

# 五、现在最明显的教师交付缺口

## 缺口 1：老师看到的语言还是研发语言

现在大量出现：

- BASE
- FALLBACK
- Recovery
- Challenge
- DISPLAY-SAFE
- Known-Good

这些词可以保留在研发文件里，但不应该作为教师版主要语言。

教师版建议统一翻译：

| 研发词 | 教师版说法 |
|---|---|
| BASE | 本节最低完成线 / 先做到这里 |
| BASE DEADLINE | 到这个时间，全班先停下来检查 |
| FALLBACK | 学生卡住时怎么救回来 |
| Recovery | 常见问题怎么处理 |
| Challenge | 做得快的学生接下来做什么 |
| DISPLAY-SAFE | 下课时至少要有的完整作品 |
| Known-Good | 已经实际验证过、可以放心使用 |
| Open Creator | 完成基础任务后自由发挥 |

原则：

> **研发层可以精确，教师层必须说人话。**

---

## 缺口 2：没有真正的“每课上课包”

最终每一课应该形成一个独立文件夹，例如：

```
Lesson-01/
  01_老师先看这里.md
  02_完整教案.md
  03_课堂投屏页.pptx 或 pdf
  04_学生任务单.pdf
  05_示例作品/
  06_学生卡住时怎么办.md
  07_做得快的学生做什么.md
  08_课后记录.md
```

现在这些内容很多散落在总教案、共用课堂卡和母版文档中，新手老师需要自己拼装。

这是当前最大的交付缺口之一。

---

## 缺口 3：没有正式课堂课件

当前仓库 90 个文件全部是 Markdown。

尚未看到正式的：

- 每节课投屏 PPT；
- 课堂演示页面；
- 学生可打印任务页；
- 教师打印速查页；
- Before / After 示例图；
- 作品展示页；
- 二维码作品墙成品模板。

所以：

> **内容层已有不少，课堂成品物料层基本还没有开始系统生产。**

---

## 缺口 4：没有逐课示例作品资产

学校开课清单要求“当前课演示作品”，但仓库里目前主要是文字描述，没有系统保存：

- 示例截图；
- 可扫码成品；
- 老师演示用稳定项目；
- 错误版 / 修复版示例；
- 优秀学生作品参考。

新手老师没有这些，很容易只能自己临时做。

---

## 缺口 5：事实核查课的“来源包”只是要求，还没有成品

小学 L12、初中 L10 都明确要求老师预置可靠来源。

但当前仓库没有每个主题对应的正式来源包。

正式开课前应该至少提供：

- 2–4 个预选主题；
- 每个主题 3–5 条课堂可核查事实；
- 已审核来源；
- 一条故意有问题的 AI 示例；
- 标准修改示例。

不能让新手老师临场自己找。

---

## 缺口 6：M3 / M4 / M5 尚未真实验证

这直接阻塞：

### 小学
- L3 / L4
- L5 / L6 正式版
- L9 / L10

### 初中
- L5 / L6

所以 7 节缺失逐课脚本并不是写作没完成，而是底层产品还没有完成真实验证。

---

## 缺口 7：全课程还没有完成教师真实走课

现有规则本身已经要求：

> 至少一位老师照正式脚本完整走过本课，并记录真实时间和问题。

但现在主要还是设计审计和 M1/M2 技术验证。

因此正式开课前必须有一个“教师自己完整走一遍”的阶段。

# 六、新手老师真正需要的标准上课包

以后判断一节课“完成”不能再看有没有 Markdown 文件，而要看以下东西是否齐全。

每节课至少要有：

1. **老师先看这一页**
   - 今天学生做什么；
   - 最后应该长什么样；
   - 最容易出什么问题；
   - 这节课绝对不要做什么。

2. **完整教案**
   - 40 / 45 分钟逐段安排；
   - 每个时间段老师做什么；
   - 学生做什么；
   - 老师关键话术。

3. **课前准备清单**
   - 账号；
   - 演示作品；
   - 学生任务页；
   - 预置素材；
   - 需要提前打开的网址 / 项目。

4. **课堂投屏材料**
   - 开场示例；
   - 学生步骤；
   - 时间提醒；
   - 收口检查。

5. **学生任务单**
   - 一页即可；
   - 不出现研发语言；
   - 学生可以直接照着做。

6. **示例成品**
   - 至少一个稳定演示版；
   - 最好再有一个“学生个性化版”。

7. **学生卡住时怎么办**
   - 没想法；
   - 做不出来；
   - 功能没生效；
   - 做得太复杂；
   - 改坏了；
   - 进度太慢。

8. **做得快的学生接下来做什么**
   - 2–5 个经过筛选的扩展方向；
   - 不让老师临场想题。

9. **本节展示与收口**
   - 最后检查什么；
   - 学生保存什么；
   - 老师收集什么。

10. **课后极简记录**
   - 完成人数；
   - 卡住人数；
   - 常见问题；
   - 下一版最需要改什么。

认知型课程还要额外有：

11. **课堂材料包**
   - 例子；
   - 反例；
   - 来源；
   - 修改前后样例。

# 七、整个项目必须增加一个“总交付入口”

目前 `HANDOFF.md` 是研发和跨工具交接入口，但它不是老师的交付入口。

建议新增根目录：

> `DELIVERY_INDEX.md`

它只回答：

- 这套课程交付给谁；
- 有哪些资料；
- 每份资料在哪里；
- 老师第一次拿到时先看什么；
- 培训时用什么；
- 每节课上课前看什么；
- 学生拿什么；
- 学校开课前检查什么；
- 课后记录什么；
- 哪些内容还是未完成状态。

这个入口不应该讲项目演化历史，也不应该要求老师理解研发架构。

建议同时把最终教师版资料整理成：

```
delivery/
  START_HERE.md
  teacher-training/
  primary-upper/
    L01/
    ...
    L16/
  middle-school/
    L01/
    ...
    L16/
  shared/
  school-setup/
  showcase/
```

研发文档继续留在 `docs/`、`mother-templates/` 等目录。

> **研发资料和教师交付资料必须正式分层。**

- 更丰富的教师进阶培训。

---

# 十、最终目标

我们最终交付的不是：

> “一份讲得很完整的课程设计文档。”

而应该是：

> **一套普通老师经过短期培训后，不需要编程能力、不需要读研发文档、不需要大量临场设计，就可以稳定带一个班完成一学期课程的完整教学产品。**

判断标准也从：

> “这节课我们设计清楚了吗？”

升级成：

> **“一个第一次拿到这套课的合格老师，明天能不能按这套材料上？”**

# 十一、并行开发策略：M3/M4/M5 与教师交付物可以同步推进

## 1. 结论

可以并行，而且应该并行。

原因是两类工作依赖关系不同：

### 轨道 A：已经稳定的课程继续产品化

可以立即推进：

- M1 / M2 对应课程；
- 用户测试、AI评审、事实核查、版本管理、发布等方法课；
- 教师培训；
- 教师手册；
- 学生任务册；
- 共用课堂课件模板；
- 展示模板；
- 学校开课清单；
- 已有课程的教师内部走课。

这些工作不需要等 M3/M4/M5。

### 轨道 B：M3 / M4 / M5 真实验证

同步执行：

- M3 互动故事；
- M4 兴趣馆；
- M5 工具 / 记录。

验证完成以后再补：

- 依赖这些底座的具体逐课流程；
- 对应示例作品；
- 对应常见问题处理；
- 对应课件中的操作页面。

## 2. 并行时唯一需要防的风险

不要在 M3/M4/M5 验证完成前，把依赖它们的具体课堂操作写死。

可以先写：

- 教学目标；
- 课堂节奏；
- 学生最后要完成什么；
- 教师怎么控制范围；
- 主题与内容选择；
- 展示方式。

先不要写死：

- 具体功能按钮；
- 具体操作路径；
- 必须能实现的高级功能；
- 精确故障处理；
- 示例截图。

这样验证结果回来以后，只补“底座相关部分”，不会推翻整节课。

## 3. 当前最合适的并行分工

### A1 — 课程结构收紧

先完成：

- 初中 L1；
- 小学 L9；
- 初中 L5；
- 初中 L12；
- 小学 / 初中 Final 项目自由度边界。

### A2 — 已稳定课程教师化

不等待 M3/M4/M5：

- 把已有 25 份逐课脚本升级成人类教师语言；
- 补齐老师真正需要的课前准备、课堂话术、常见问题、快学生安排和收口；
- 同步制作教师手册章节；
- 同步制作课堂课件与学生任务册。

### B — M3/M4/M5 验证

并行跑真实账号最小验证。

验证完成以后：

- 固定统一课堂起点；
- 固定允许个性化的范围；
- 固定常见问题；
- 补齐剩余 7 节；
- 插入教师手册、课件和学生任务册对应章节。

因此不需要“先等全部母版做好，再开始教师物料”。

# 十二、交付资料必须整合，不能把研发碎片直接交给老师

开发阶段可以有很多小 Markdown 文件，便于：

- 版本控制；
- 独立修改；
- 审计；
- 多工具协作。

但正式交付给老师时，应重新编译、整合。

推荐最终教师交付形态：

## 1. 一本《小学高年级教师手册》

一份完整文档，包含：

- 课程总览；
- 开课前准备；
- 通用带课方法；
- 16 节逐课教案；
- 每节课常见问题；
- 做得快学生的安排；
- 课堂收口；
- 课后记录；
- 常用教师速查表。

老师不需要逐课翻很多 Markdown。

## 2. 一本《初中教师手册》

结构同上。

## 3. 一本《小学学生任务册》

16 节学生任务页整合成一本。

## 4. 一本《初中学生任务册》

16 节学生任务页整合成一本。

## 5. 课堂课件

每节课一份 PPT 仍然合理，因为老师上课需要直接投屏。

但教师不应该同时打开多个说明文件。

建议一节课实际使用时，老师桌面上主要只有：

> **教师手册 + 本节 PPT**

学生主要只有：

> **学生任务册 / 本节页**

## 6. 少量独立附件

只有不能合理嵌入手册或课件的材料才独立存在，例如：

- 示例作品二维码；
- 事实核查来源包；
- 可复用图片素材；
- 学校作品墙模板。

原则：

> **研发资料可以碎；交付资料必须整。**
